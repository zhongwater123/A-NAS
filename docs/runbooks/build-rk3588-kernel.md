# 构建 RK3588 候选内核

公开记录中的 `REDACTED` 值是实例标识的占位符。任何磁盘操作前须从本地封存清单恢复真实值并重新核对目标，不直接执行带占位符的写入步骤。

状态：draft
更新时间：2026-11-18

## 目的

为 ATK-DLRK3588 的 Debian 13 / Linux 6.12 候选系统补齐产品需要的内核能力。编译只写专用构建文件；本手册不授权刷写开发板、改变真实磁盘分区或初始化 SSD。

## 目标识别与停止条件

- SDK 输入为 I 盘根目录的 `atk_dlrk3588_linux6.12_sdk_release_v1.2.0_20261104.tar.gz`；完成归档遍历、gzip 校验并记录 SHA-256 后，核对内核精确版本、板级配置和工具链。
- 2026-11-17 的 I 盘为 USB 机械盘上的 NTFS 卷，容量 500,106,784,768 字节，卷身份 `\\?\Volume{BOARD_UUID_REDACTED_05}\`。每次创建构建文件前重查身份、健康和空闲空间；不按磁盘序号执行写入。
- 构建目录固定为 `I:\A-NAS-RK3588`，仅允许新建专用 `build.ext4` 稀疏文件，最大逻辑容量 128 GiB。先确认目标文件不存在，标记 NTFS sparse 后才扩展长度；不得覆盖已有文件。物理占用按写入增长，持续监测 Windows I 盘空闲，至少预留 20 GiB；虚拟文件内的 `df` 不能代替宿主机余量。
- 格式化只允许针对本步骤独占创建、路径与长度均核对过的普通 `build.ext4` 文件，拒绝块设备路径。使用 `mkfs.ext4` 时关闭 discard，仅通过文件对应的 loop 设备挂载到 `/mnt/anas-rk3588-build`，挂载后核对来源及标签。禁止向 I 盘的真实分区或整盘执行 `mkfs`。
- 发现目标身份不同、目标文件已存在、归档路径越界、归档损坏、空间不足、挂载来源不符或 SDK 与板型不符，立即停止相关写入。

## 构建与验证

1. 保存镜像提取的原内核配置和 SDK 清单；归档仅提取必要内核仓库、板级构建脚本、工具链和打包工具，拒绝绝对路径、`..` 越界和逃出构建目录的链接。SDK 解包、检出和编译以 `anas-dev` 普通用户执行；root 只用于新构建文件的格式化、挂载和目录授权。
2. 以厂商匹配配置和设备树为基础，补齐 Landlock、Btrfs、资源限制和容器路径；通过 Kconfig 解析依赖，验证最终 `.config`，不以配置片段中的赋值当作已经启用。
3. 保存源码提交、配置差异、工具链版本、构建命令、日志及候选产物哈希。安装到独立暂存目录的模块须与内核 release 一致；保留驱动、DTB、资源和打包参数。构建后再检查内嵌配置及镜像结构。
4. 板端写入前必须另有已核对的目标介质、原系统备份、恢复入口、明确写入范围及用户授权。启动后先按[预检与候选包验收](prepare-rk3588-candidate.md)确认 Landlock ABI、存储、服务及实际功能，不能通过关闭隔离绕过失败。

## 回滚与恢复

编译失败时保留日志与原始 SDK，回退独立源码中的配置改动后重建。仅构建阶段不改变板端系统。清理构建文件前先停止全部使用者、卸载 `/mnt/anas-rk3588-build`、解绑准确的 loop 设备，确认没有残余挂载，再删除经路径检查的专用文件；不要格式化 I 盘来回收空间。

## 可逆的板端 4B 探针

- 只对 ADB 序列号 `BOARD_ADB_SERIAL_REDACTED`、设备树 `ATK-DLRK3588 Board`、eMMC CID `BOARD_EMMC_CID_REDACTED` 的目标执行。每次写入前重查身份；`/userdata` 必须挂载于 `/dev/mmcblk0p8`，空闲至少 8 GiB。
- 用户已要求开始调试；探针仅新建 `/userdata/anas-rk3588-probe-20261117`。目标目录必须不存在；不得覆盖、清空或格式化已有分区。Host 准备目录为 `I:\A-NAS-RK3588\board-probe`，拒绝覆盖已有目录。只复制固定候选中的 llama.cpp b11655、原 4B 分片与 mmproj；板端核对模型 SHA-256 后运行。
- 首先执行运行时版本检查。若系统库不兼容，仅向探针目录补充独立依赖，不替换系统库。服务使用 `nobody` 运行，只绑定板端回环地址；ADB 转发只绑定本机回环端口。探针记录版本、请求参数、耗时、结果、内存和温度，不能替代完整产品的内核隔离或质量验收。
- 失败或完成后仅停止通过 PID 及 `/proc/<pid>/cmdline` 确认为本探针目录程序的进程，移除本次端口转发；保留日志及哈希。需要删除测试文件时，再核对板卡 CID 和探针绝对路径，只删除本次创建的目录；不操作相邻数据、分区表或 NVMe。

## 候选系统文件准备

I 盘上的 `I:\A-NAS-RK3588\firmware` 只保存本次新建的镜像文件与校验清单。先确认目录不存在，再从已识别的官方镜像读取分区数据，校验范围、ext4 超级块和实际字节数；保留原镜像。`rootfs.img` 只可在核对普通文件、固定路径、输入大小及本次所有权记录后扩展，并通过该文件对应的独立 loop 挂载到 `/mnt/anas-rk3588-rootfs`；操作只针对镜像副本，不是开发板或 I 盘真实分区。修改后验证文件系统和文件哈希，板端激活另按目标、备份和恢复步骤执行。

当前增量候选按原分区表准备：boot 为 p3 的 64 MiB，根分区为 p6 的 14 GiB，PARTUUID `BOARD_UUID_REDACTED_06`。不直接套用官方更新容器的新 GPT。镜像副本仅加入匹配模块和临时 USB 调试、根文件系统扩容单元；屏蔽厂商会遍历分区的 `resize-all.service`。首次扩容必须再次核对 CID、根分区 UUID、分区号、长度及当前根挂载设备，只允许 `resize2fs` 扩大现有根文件系统，不改变分区表、不操作 OEM/userdata/NVMe。USB 调试只配置 ADB 功能，首次启动后检查实际监听；未提供 UMS 磁盘导出。部署后核对时间，原厂 1970 年时钟不能直接用于 TLS 与产品状态初始化。

## 原系统备份与激活门禁

1. 重查上述 ADB 序列号、设备树及 eMMC CID；eMMC 长度必须为 62,545,461,248 字节。确认 `/` 为 `/dev/root`、`/oem` 为 `mmcblk0p7`、`/userdata` 为 `mmcblk0p8` 的 ext4，原挂载均为读写；SSD 不参与操作。任何不符停止。
2. I 盘卷身份不变且空闲不少于 20 GiB。备份只在 `I:\A-NAS-RK3588\board-backup-20261118` 创建不存在的新文件；已有文件拒绝覆盖。boot 分区备份仅覆盖 boot，不应被称为完整系统备份。
3. 完整 eMMC 快照前停止本次探针，确认没有已知业务写入。备份辅助程序只放 `/tmp` 内新建的专用目录。按 userdata、oem、根目录顺序临时 remount 为只读，任一失败退出；trap 按相反顺序恢复原读写状态。不得通过杀死未知业务或强制卸载来绕过失败。只读状态下流式读取整块 eMMC，经 tee 同步计算源 SHA-256，再 gzip/base64 输出，主机流式解码到新文件；不在板卡数据分区暂存大镜像。
4. 旧 ADB 的 shell 会转换换行，直接重定向二进制不可信。备份必须经 base64，主机解压后核对原始字节数与源 SHA-256，同时保存压缩文件哈希、设备身份及原挂载恢复结果。传输失败、超时或空间低于预留即停止，保留不完整文件与错误记录，不标成可恢复备份。另保留分区表、原 boot/recovery 与必要的 eMMC boot 硬件区信息。
5. 完整备份校验成功也不等于恢复入口已验证。首次覆盖系统前还须验证厂商恢复/Loader 入口、可用传输工具，以及准确的恢复目标与镜像范围。恢复只在目标分区全部离线时执行，先重查 CID 和容量，从主机备份恢复并回读校验；不得从正在被覆盖的 eMMC 分区读取恢复源。
6. 验证通过后的项目部署授权不要求重复询问；具体激活流程须先固定并检查待写镜像、匹配模块、分区容量及恢复路径。未满足门禁时不覆盖系统；不得将 RKFW 更新容器当作整盘原始镜像写入，也不得将 MiniLoader 当作 raw idbloader。SSD 初始化另按存储手册完成目标、可丢弃数据与确认步骤。

## 在原分区表上试启动

仅用于上述已备份测试板。当前已实测 ADB 重启进入原 recovery，根目录为 RAM `rootfs`、p6 未挂载；也已通过 UART 中断 U-Boot，选择 `mmc dev 0 0`，从原 p4（LBA `0x28000`、长度 `0x40000`）只读加载到空闲 RAM `0x10000000`，用 `boot_fit 0x10000000` 重新进入同一 recovery 并恢复 ADB。此厂商 U-Boot 没有 `bootrkp`、`iminfo` 命令；不照搬其他 SDK 命令，不执行 `saveenv`、MMC erase 或硬件分区命令。失败时保留串口输出，不继续覆盖。

1. 在主机 `I:\A-NAS-RK3588\activation-20261118` 新建试启动输入与所有权记录，拒绝覆盖。新 FIT 填充到原 boot 分区的准确 64 MiB，保留原文件及两者摘要。由已校验完整快照按 p6 起点 `491520×512`、长度 `29360128×512` 提取原根分区 gzip，复验解压长度与 SHA-256；原 boot 也保留完整 64 MiB 的 gzip。不得从未校验或截断的备份提取。
2. recovery 内重查 DT 型号、CID、eMMC 容量、p3/p6 UUID、起点及长度，确认根为 RAM、p3/p6 均未挂载。确认 `/userdata` 仍是 p8、起点 `30113792`、可用至少 20 GiB；新建 `/userdata/anas-rk3588-activation-20261118`，拒绝覆盖已有目录。只复制候选 rootfs、填充后的 boot、原根与原 boot 回滚文件、清单及受限操作脚本，不改 GPT。p8 在本布局中不与 p3/p6 重叠；若改用官方新 GPT，此暂存方式不再成立，必须停止。
3. 核对全部文件长度及 SHA-256，主机和板端都要保留原根的解压长度与摘要。停止的仅可为确认 `/proc/<pid>/exe` 与命令行为 `/usr/bin/recovery` 的本次 recovery 更新进程，避免与手动写入并发；不得终止未知业务。先执行脚本的 verify 模式，验证失败不写设备。

   原厂 recovery 的 `wc -c` 对本次大于 4 GiB 的镜像发生计数回绕。关键长度、复制、解压及摘要操作必须使用已核对 SHA-256 的独立静态 AArch64 BusyBox 1.37.0，不能使用原厂 `wc` 推导写入范围；固定工具摘要与复现见[调查记录](../investigations/2026-11-18-rk3588-recovery-large-file-count.md)。工具只放本次暂存目录，不替换厂商工具。
4. apply 模式要求显式的候选摘要标识，写入前再次核对全部门禁。保存 eMMC 前 16 MiB（含 GPT、loader、uboot、misc）及原 recovery 的摘要。先把新根文件系统写到 p6，`conv=fsync` 并回读候选准确长度的 SHA-256；通过后才将填充的 64 MiB boot 写到 p3，同样 fsync 并回读整个分区。检查前 16 MiB 与 recovery 摘要不变。每阶段向暂存目录记录状态；任一失败保留 recovery，不自动重启，不尝试格式化、改分区表或修改 NVMe。
5. 两分区回读都通过后，主机先开始 UART 记录，再重启试启动。核对新内核 release、根分区、匹配模块、Landlock、cgroup、ADB、时钟、仅根文件系统扩容和 NVMe 枚举；完成系统预检后再安装项目包，不能以关隔离或扩大超时掩盖失败。
6. 若新系统不能启动，从 UART 在 U-Boot 阶段中断，再按上述只读 RAM recovery 流程进入原恢复环境。恢复脚本也须重查 CID、布局及 p3/p6 离线，并校验回滚文件；先解压原完整 14 GiB 根到 p6，fsync、回读整个 p6 比对原根摘要；再恢复原完整 64 MiB boot，回读校验。检查 GPT/uboot/recovery 未变，保存日志后才重启。回滚源始终放于不重叠的 p8 或主机，不从正在被覆盖的分区读取。

## 首次引导服务修复

仅针对上述候选及同一 CID。先保留串口通道并记录原脚本、单元和 SHA-256，备份到根分区内新建的专用目录，拒绝覆盖备份；不修改回滚镜像。修改前以跟踪模式复现失败，身份、分区、容量或根挂载不符时停止。

- 根扩容：`findmnt` 的默认列输出会填充空格，比较 `MAJ:MIN` 须使用 `--raw`；保留 CID、PARTUUID、容量和文件系统校验。先核对脚本语法和差异，再运行受限单元；验证根文件系统扩展至原 p6 容量，分区表和 NVMe 未变。失败保留日志并还原脚本，不绕过身份门禁。
- USB：启动 adbd 后重试绑定本板已实测的 OTG 控制器 `fc000000.usb`，不能先等 `ep1/ep2`，因为该版本 adbd 自身等待 `FUNCTIONFS_BIND`。本板另有 `fc400000.usb`，不能要求全机只有一个 UDC。仅复用身份和配置均核对过的本次 `anas-debug` gadget，遇到其他已绑定 gadget 或已有 adbd 时停止。修改前备份旧脚本；经 UART 停止本次临时 adbd、确认 UDC 已自动解绑后启动修复单元，检查 USB 枚举、进程和 TCP 监听，再完成一次重启回归。失败经串口恢复旧文件并使用已验证的临时绑定实验，不能改动其他 gadget 或 USB 磁盘功能。
- 时间：完成设备身份校验后，将板端时间与主机 UTC 对齐；确认时间和根扩容完成后才安装产品并初始化状态。

### 常开与调试连接恢复

本候选保留厂商 GNOME 桌面，不能假设无屏幕输入时仍持续服务。出现 UART/ADB 同时无响应时，先检查用户是否断电；短按电源键尝试唤醒并收集 `systemd-suspend`、logind 和内核 PM 日志，不直接判定内核崩溃。若日志确认休眠，核对桌面用户及其电源设置；本板 `rockchip` 的 `sleep-inactive-ac-type=suspend`、timeout=900。记录原值和 sleep target 状态到 root 专属的新备份目录后，关闭交流电/电池的自动休眠，并 mask sleep、suspend、hibernate、hybrid-sleep 与 suspend-then-hibernate target，使 NAS 保持常开。该操作保留关机、重启；回滚按记录恢复设置，仅解除本次新增的 mask。

唤醒后 gadget 可能已自动解绑，而 adbd 仍在等待 `FUNCTIONFS_BIND`。临时恢复只绑定已核对的本次 gadget 和 `fc000000.usb`；永久单元须监督 adbd 并在 UDC 为空时重新绑定，不能把仍 active 的 oneshot 当作 USB 可用证据。修改前备份当前脚本和单元；切换经独立 UART 完成。验证目标为实际 ADB shell 与本机 HTTP 200，另以仅解绑本次 gadget 的可逆实验检查自动恢复，并放置超过原 15 分钟阈值复测。失败经 UART 恢复上一版并保留日志，不改其他 gadget。

厂商实际运行的是 `usb-gadget.service`，不是已停用的 `usbdevice.service`。当前保留该服务；停用方案因可能影响非 ADB 功能被自动审批拒绝，未执行，须等用户另行明确授权。可选方案为：先核对 cgroup、脚本及当前功能，确认 `rockchip` gadget 未绑定并保存 enabled 状态。其 ExecStop 通过可执行文件名停止 adbd，可能误杀本次独立单元，因此停止前仅在 `/run/systemd/system/usb-gadget.service.d/` 临时清空 ExecStop；daemon-reload 后用 systemd 停止并禁用、mask 该服务，仅终止其自身 cgroup，不触碰其他 gadget 配置。调试单元增加对该实际服务的 Conflicts。回退时先停止本次调试单元，再解除本次 mask、移除临时 drop-in 并按记录恢复厂商服务。
