# AI 助手 V1 的模型、开启范围、密钥与告知

状态：decided（2026-11-17，用户）
更新时间：2026-11-17

## 问题

AI 助手在实验 NAS 上以试用包运行，用云端的 DeepSeek，规格与 [ADR 0024](../adr/0024-run-a-sandboxed-hermes-agent-per-member.md) 都写着云端模型“只用于开发测试”“本地模型接入前不在保存真实家庭数据的设备上开启”。实验 NAS 改用设备镜像（[ADR 0034](../adr/0034-release-as-signed-debian-packages-and-update-devices-with-sysupdate.md) 第 6 步）之前，助手要先成为正式功能，因为试用包往镜像管不到的 `/etc` 与 `/spike` 装文件。转正之前要定：

1. V1 用云端模型，还是等本地模型；
2. 谁有助手：全部成员默认开启，还是由管理员或成员逐个开启；
3. 云端服务商固定，还是可选或自填 OpenAI 兼容地址；
4. 模型的密钥由谁提供、怎样填写（试用中是 root 手写的 `/etc/anas-spike/model.key`）；
5. 除了整台设备，要不要按成员关闭；
6. 怎样告诉家人对话与读到的内容会发到云端（规格不许写“数据不出设备”）；
7. 看照片画面与看桌面画面在 V1 中怎样处理。2026-10-21 用户决定开放看桌面画面，当时的前提是试用：画面不遮挡“VNAS 不能查看”的区域，例如管理员只读查看的家人个人空间、快照里的文件。

## 选项

1. 模型：V1 用云端模型；或等本地多模态模型接入后再发布助手。
2. 开启范围：全部成员默认开启；管理员逐个开启；成员自己开启。
3. 服务商：固定为试用中的 DeepSeek；可在几家中选；管理员自填 OpenAI 兼容的地址。
4. 密钥：
   - 管理员在“设置”中填写，用自己的 DeepSeek 账号；
   - A-NAS 统一提供，设备经 A-NAS 自己的中转服务调用，要建服务器、按设备认证、限流并承担费用；
   - 像试用一样由 root 在命令行写入。
5. 关闭：只有删除密钥一种（整台设备）；管理员可逐个成员关闭；成员可自己关闭。
6. 告知：改侧栏“你的私人 Agent”中“隐私”一条；每位成员第一次打开时提示一次；管理员填写密钥时写明并确认。可多选。
7. 看图：保留，桌面画面遮挡“VNAS 不能查看”的区域；保留，维持不遮挡；V1 关掉看图，只读文字。

## 决定

用户 2026-11-17：

1. V1 用云端模型，本地模型在以后的版本中接入。
2. 全部成员默认开启，包括管理员与之后新建的成员。
3. 服务商固定为 DeepSeek，即试用中用的那一家。
4. 密钥由管理员在“设置”中填写：每户用自己的 DeepSeek 账号；粘贴一次，之后只能替换或删除，不再显示原文；设备加密保存，只有模型网关读得到。没有密钥时，桌面上的 VNAS 提示需要管理员设置。
5. 不另设关闭方式：有密钥时全家都有，管理员删除密钥即整台设备关闭；没有按成员的开关。
6. 告知放在管理员填写密钥的页面：页面写明对话与 VNAS 读到的内容会发到 DeepSeek 的服务器，管理员确认后才能保存。侧栏的“隐私”说明不改，也不加首次打开的提示。
7. 看图照现在的代码：照片画面照旧发给看图模型（证件、票据与文字没读完的照片仍不给，[决定](2026-11-10-assistant-view-of-documents.md)），桌面画面照旧不遮挡。用户的原话：“按我们目前的代码实现来规划就行。我理解为目前的需要的是文档来诚实锚定目前状态作为里程碑。”所以规格与 ADR 0024 去掉“试用期间”“只用于测试”“只做可行性验证”，照实写出发往云端的内容。

1–3 未记录理由。4、5 采纳了提问时的建议；6 没有选建议的改侧栏说明，只选了填写密钥时确认。

由此写定的：

- [AI 助手规格](../specs/ai-assistant.md)的非目标、看图与看桌面画面的场景，以及新增的“V1 转正（尚未实现）”一节；
- ADR 0024 的决定 6、7、8 与后果中的隐私随之改写，并链接到本记录：这些是试用时写进 ADR 的产品范围，改回来只是普通提交。
