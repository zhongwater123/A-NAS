# 剪辑中心的规划没有完成时，系统自动重来，到上限仍失败就让任务失败并通知

状态：decided（2026-11-25，用户）
更新时间：2026-11-25

## 问题

成员点“开始”以后，规划在后台由成员的 VNAS 做。到 2026-11-25 为止，只要这一轮里模型可能已被调用（调用过剪辑工具后对话中断、超时，或答案连续 3 次不合格），任务就停在“需要你处理”，等成员点“重新规划”（#514 的“模型可能已被调用就不自动重来”）；规划进程出错也只再试一次就停下。

结果是：大多数停下的原因是临时故障或模型出错，成员点了也不会改变什么，任务却一直挂着等人，成员不在桌面前就一直没有进展。要定的是：哪些情况交给成员，哪些由系统自己重来，重来几轮，到上限之后怎样结束、怎样告诉成员。

## 选项

- **维持原样**：模型可能已被调用就停下等成员。不会因为自动重来多花云端模型的费用，但临时故障也要成员处理。
- **只有成员的操作能改变结果时才停下**：素材被删、空间不足、要求在素材里找不到这类情况交给成员；临时故障和模型出错由系统自动重来，到上限仍失败就让任务以“失败”结束，立刻通知成员，写明原因，提供一键重来。每次重来都调用一次云端模型。

重来几轮的上限：同一个任务再试 2 轮（共 3 轮）、再试 1 轮（共 2 轮），或用到规划授权剩下的轮数为止。

## 决定

选“只有成员的操作能改变结果时才停下”，同一个任务对同样的输入最多规划 3 轮。

2026-11-25 用户对这条规则说“这点我非常认可”：

> 只有成员的操作能改变结果时，才停下交给成员，比如素材被删了、空间不足、他的要求在素材里找不到。临时故障和模型出错，系统先自动重试到上限。到了上限仍失败，就让任务以‘失败’结束，立刻通知成员，写明原因，并提供一键重来，而不是停在‘等你处理’。

同日用户在选项中定下：重试上限“再试 2 轮，共 3 轮”；失败的通知用“桌面提示加‘失败’，带一键重来”；改动合在 [#631](https://github.com/zhongwater123/A-NAS/pull/631) 里，不另开 PR。

具体做法：

- **算一轮**：一轮到了规划进程、却没有让任务拿到它在等的规划，就算试过一轮：对话开始前规划进程出错、模型调用剪辑工具前后对话中断或超时、答案连续 3 次不合格（第 3 次不合格就结束这一轮）、只交回一部分。VNAS 连不上的一轮没有调用模型，不算，照旧 2、4、8、15 分钟后再试。
- **重来**：试过的一轮结束 1 分钟后，任务自己再要一轮，已收下的大纲与方案保留，下一轮只规划还缺的部分。
- **上限**：同一个任务对同样的输入（同一个规划轮次、同一份目录与配乐）试满 3 轮仍没有完成，任务以“失败”结束，原因 `plan_failed`，错误写“规划试了 3 轮都没有完成：<最后一轮怎样结束>”。成员在项目页或桌面提示上点“重新规划”，任务从停下的地方接着规划，重新有 3 轮。
- **通知**：桌面提示增加“没有剪成”，24 小时内显示，带上原因；只有一个规划失败的任务时，提示上直接给“重新规划”。成员不在桌面前时，下次打开桌面看到。
- **不变**：规划授权仍是 7 天、5 轮，同一成员的几个任务共用，成员做会登记授权的操作就刷新。素材缺失、分析失败、视频过长、空间不足、歌曲不可用、没有可用画面仍停下交给成员。

**理由**：用户的原话即理由：只有成员能改变结果时才打扰成员；其余由系统处理到上限，失败时明确告知并能一键重来。

**代价**：成员不在场时，系统最多替同一个任务多调用 2 次云端模型；整体仍受 5 轮授权的约束。
