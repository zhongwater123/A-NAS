# 家庭待办是不是本体能力、按什么分范围、先做哪一步

状态：decided（2026-11-16，用户）
更新时间：2026-11-17

## 问题

家里要办的事（缴费、复查、续保、换证）原先在水墨屏原型里做：识别单据，在屏幕上提醒。把它带进 A-NAS 之前，要先定几件事（[#503](https://github.com/zhongwater123/A-NAS/issues/503)）：

- 待办做成 A-NAS 本体的能力，还是一个可以单独安装、移除的模块（[ADR 0037](../adr/0037-plug-removable-modules-in-as-separate-services.md)）。
- 一件待办谁能看：全家都能看，还是按它从哪里来分。
- 虚拟伙伴（桌宠）和待办是什么关系。
- 先做哪一步：等单据识别做好再一起上，还是先做待办本身。

## 选项

- **本体能力**，或**可移除模块**。
- 范围：**全家都能看**，**每件由人自己选**，或**按来源分**（共享空间里的事全家能看，个人邮箱、个人空间来的事只有本人能看）。
- 虚拟伙伴：**桌宠自己管待办**，或**待办是独立能力，桌宠只读汇总**。
- 第一步：**等识别**，或**先做待办、窗口和提醒，不等识别**。

## 决定

用户 2026-11-16 选定（#503）：

- 待办是 A-NAS 本体的能力，不做成可移除模块。
- 范围按来源分。
- 待办是独立能力，虚拟伙伴只读汇总。
- 第一步先做待办、窗口和提醒，不等识别。

未记录理由。

落实时由此得到的做法（不是另外的决定）：

- 第一步只有手工新建，没有来源；照原型规则 22，手工新建的一律算全家，界面上不提供“只我自己”。只给本人看的待办等邮件、个人空间来的待办时再出现。
- “全家”就是所有有效账号：这是 [ADR 0029](../adr/0029-keep-the-baby-as-a-profile-and-channel-photos-in-the-shared-library.md) 决定 3 已经记下的用户决定“NAS 的账号就是家人”，不是新决定。
- 待办由哪个服务持有、怎样授权、挂在哪个路径下，是难以逆转的技术选择，写在 ADR 0029 决定 6。
- 规格补充的其余默认值（类别、标题长度、推迟天数、提醒档位的细节等）等用户确认，见[家庭待办规格中补充的默认规则](2026-11-17-family-todos-default-rules.md)。
