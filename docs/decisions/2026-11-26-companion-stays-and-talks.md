# 虚拟伙伴停在成员放的地方、点它和 VNAS 说话、自己的开关菜单

状态：decided（2026-11-26，用户）
更新时间：2026-11-26

## 问题

V1 的伙伴会为当前窗口让开：它的点击区和最上层的窗口重叠时，自己挪到窗口外最近的空位（2026-11-11 起，起因是它挡住了 VNAS 的发送与停止按钮）。用起来它常为了不被挡而到处换位置，影响桌面上的布局。同时，点它只是“问她现在怎么样”，想和 VNAS 说话还要去开 VNAS 窗口；关掉或让她安静只能到设置 → 概览的最下方去选。V1 的规格把“聊天”列为非目标（[#414](2026-11-06-companion-v1.md)）。

## 选项

- **保持现状**：继续让开窗口；点击只问现状；开关只在设置里。
- **停在原处、点它说话、身上加菜单**：去掉让开，伙伴停在成员放的地方，在窗口之上（只有侧栏、通知与弹出层在它之上）；没别的事时点它打开 VNAS 说话；右键或长按它出一个小菜单，可以让她安静或隐藏。代价：她可能挡住窗口里要点的地方，要成员自己拖开；点击的含义多了一项。
  - 和 VNAS 说话的界面有两种做法：伙伴另开一个迷你对话框并自己连 VNAS；或就用 VNAS 窗口，开小一点放在伙伴旁边。前者要第二条连接，确认卡片与伙伴、桌面命令只发给发出这句话的窗口，这些命令的处理都在 VNAS 窗口里，VNAS 窗口没开时就没人接，VNAS 会等到超时；后者共用同一条连接，什么都照常。

## 决定

用户在 2026-11-26 选了第二项，原话：“我们可以让用户选择打开或者关闭，给用户自由度”“其实可以直接让它在最上层即可，不被覆盖，除非是系统端的通知”“点击以后会出现一个迷你对话框可以直接和 vnas 沟通”。

实现时选的默认做法（可以再调）：

- 说话就用 VNAS 窗口：开成 520×560（窗口最窄的宽度）放在伙伴左边，接着最近的一段对话；窄窗口的标题栏有“新对话”；VNAS 窗口已经开着时只调到最上；这样开的小窗口关掉后回到原来的大小。
- 点击仍是有事先说事（红点、等确认、新结果、回合进度、出错），都没有才开 VNAS；本地控制台上不开对话。
- 开关用现有的“正常 / 安静 / 隐藏”，入口加在伙伴自己的右键与长按菜单里；隐藏后在设置里打开。
