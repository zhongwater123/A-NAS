# 仓库保持公开，声明保留所有权利

状态：decided（2026-11-17，用户）
更新时间：2026-11-17

## 问题

仓库从 2026-11-06 起公开，但一直没有许可证。2026-11-17 出现了第一个 fork，用户问怎样防止别人拿这些代码商业化。要定的是：附哪种许可证，或者不附。

## 选项

- **什么都不写**：没有许可证时，默认保留所有权利。按 GitHub 服务条款，别人只能在 GitHub 上查看和 fork；复制、修改、分发与商用都要许可。缺点是读者容易把公开仓库当成开源。
- **写明保留所有权利**：保留的权利和不写一样，只是把规则写清楚，并说明第三方代码按各自的许可证。以后可以随时改发许可证。
- **PolyForm Noncommercial 1.0.0**：允许个人、学习、研究以及公益和教育机构使用、修改、分发，禁止商用。它会放出非商业使用的权利；按它发布的版本，拿到的人一般会一直保有这些权利。
- **BSL 1.1 或 FSL**：先限制生产使用或竞争性使用，到期后自动转为开源许可证（FSL 是 2 年，BSL 最长 4 年）。
- **AGPL-3.0 加商业授权**：允许商用，但修改后对外提供服务必须公开源码；想闭源使用，就向著作权人购买授权。双许可要求贡献者签贡献者协议。

## 决定

用户 2026-11-17 先选了 PolyForm Noncommercial，随后问“那我们现在什么都不写，是否权利反而是最大的？”。讨论后定为写明保留所有权利，不附开源许可证：“更新readme……然后申明一句保留所有权利声明”。

理由：保留的权利和不写相同，同时把规则写清楚。以后要放开非商业使用，可以再换成 PolyForm；反过来，已经按许可证发布的版本收不回。

声明写在 [README 的“版权”一节](../../README.md#版权)。以下部分不受这份声明约束：

- 自带许可证的第三方代码，按各自的许可证使用：
  - `internal/appstore/catalog/`，来自 CasaOS，Apache-2.0；
  - `web/src/assistant/hermes/` 与 `ai/assistant-spike/` 中复制的 Hermes 代码，MIT；
  - `web/src/companion/dsh-pet/`，MIT。
- 虚拟伙伴的形象，CC BY-NC-SA 4.0，不在仓库中。
- 模型权重，按各自的许可证（见[模型准入](2026-10-10-model-license-rule.md)）。

2026-11-17 在 main `c738affa` 上检查了随产品分发的依赖：

- Go 程序链接的 70 个模块都是宽松许可证，例外是 golang-lru（MPL-2.0，只约束它自己的文件，我们没有修改）。libcap/psx 是 BSD-3-Clause 或 GPL-2.0 二选一，取 BSD-3-Clause。
- Web 前端的生产依赖和 AI Worker 的 Python 依赖都是宽松许可证。
- 没有链接 GPL 或 AGPL 代码。
