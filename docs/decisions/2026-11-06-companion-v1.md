# 虚拟伙伴（大肥鱼）V1 的形象、实现方式与 VNAS 的控制

状态：decided（2026-11-06，用户）
更新时间：2026-11-06

## 问题

[#404](https://github.com/zhongwater123/A-NAS/issues/404) 提出在 Web 桌面上常驻一个虚拟伙伴，[PR #412](https://github.com/zhongwater123/A-NAS/pull/412) 是它的 V1 实现。动手前要定：

1. 用什么形象。
2. 渲染、动画与拖动自己写，还是接入开源项目。
3. V1 覆盖哪些客户端。
4. VNAS 只让伙伴跟随自己的状态，还是能主动控制伙伴。
5. 能控制时，命令送到哪些设备。
6. 开放哪些控制。
7. 命令经什么下达。

## 选项

1. 形象：社区二创的“大肥鱼”（CC BY-NC-SA 4.0，原作者声明不可以任何形式商业化）；或另做原创形象。
2. 实现：接入 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet)（代码 MIT，素材禁止商用）；或自己写精灵图渲染、拖动与气泡（#354 的做法）。
3. V1 范围：WebOS 与宿主机屏幕（本地控制台）共用一套 Web 代码；或同时做 Electron 电脑桌宠。
4. VNAS 的作用：伙伴只跟随 VNAS 的回合与待确认卡片（PR #412 的做法）；或 VNAS 能主动让伙伴做动作、说话。
5. 送达范围：
   - 成员所有打开的桌面：产品服务按成员保存伙伴状态，需要新的推送通道；定时任务运行时也能控制。
   - 只在发起这段对话的设备：经产品服务已有的 VNAS 窗口连接送达，不需要新的推送通道。
6. 开放的控制：播放动作、说话气泡、移动与抛出、睡觉与叫醒中的哪些。
7. 下达方式：
   - A-NAS 的 MCP 工具，参数沿用 dsh-pet 的接口契约（[`API.md`](https://github.com/PC2005-cloud/dsh-pet/blob/10f6c868b8110c897af33d6137a3d85e84b665ba/API.md)），由产品服务转给发起这段对话的 VNAS 窗口。
   - 让 VNAS 用浏览器工具点伙伴的菜单：说话没有可点的控件，做不到。
   - 修改 Hermes 的浏览器控制协议：要给上游打补丁。

## 决定

用户 2026-11-06 定下：

1. 形象用大肥鱼，A-NAS 商用前必须更换。未记录理由（[#404 审查意见](https://github.com/zhongwater123/A-NAS/issues/404#issuecomment-6674509488)）。
2. 接入 dsh-pet，不自己写，理由是 AGENTS.md 的“不重复造轮子”。审查 PR #412 后用户补充：“既然我们使用dsh-pet这个项目那么尽量复用已有代码，使用规范的接口设计”。dsh-pet 已有的模块（宠物卡片、工作状态汇总）直接复制，接口沿用 dsh-pet 的状态与命令契约，不另行设计。
3. V1 只做 WebOS 与宿主机屏幕，电脑桌宠属于 V2；理由是电脑端客户端近期不会上线。
4. “VNAS需要能主动控制”。
5. 只送到发起这段对话的设备。宿主机屏幕上的伙伴只由在宿主机上进行的 VNAS 对话控制，用户的说法是“宿主机的应当由宿主机会话的VNAS单独控制才合理吧”。由此：
   - 在宿主机上与 VNAS 对话的成员，可以让伙伴在这块屏幕上说出这段对话的内容；
   - 别处来的内容，例如定时任务的提示，在宿主机屏幕上仍只显示状态；
   - 定时任务运行时没有发起对话的设备，不能让伙伴做动作或说话，出结果时伙伴照旧挥手。
6. 四类控制全部开放：播放动作、说话气泡、移动与抛出、睡觉与叫醒。都不需要成员逐次确认，依据 2026-10-16 只拦破坏性操作的决定（[ADR 0024](../adr/0024-run-a-sandboxed-hermes-agent-per-member.md) 决定 8）。
7. 按建议用 A-NAS 的 MCP 工具（用户：“写并发布”）。ADR 0024 否决过为打开应用、播放等界面操作另写 MCP 工具，理由是浏览器工具已经能做到；伙伴的说话与动作没有可点的控件，浏览器工具做不到，所以这里另写。
