# Qwen 奶蛙助手接入检查

检查日期：2026-11-03

## 结论与范围

用户指定平台的认证模型目录返回 `qwen3.8-max` 与 `qwen3.8-flash`。两款模型各完成四次合成请求，均通过本次协议检查，可以继续进入 VNAS 联调。Base URL 为 `https://www.shokzai.com/v1`；这里使用的是用户指定代理的模型 ID，不由阿里云公开模型名推断。

本次客户端为 `openai==3.42.1`，直接访问该平台，连接超时 40 秒，自动重试为零。客户端采用本机 HTTP 代理；没有穿过项目的 Unix socket 模型网关、Hermes 或 NAS 任务执行器。没有创建真实提醒，也没有读取或修改 NAS 文件。网关的独立合成测试见[模型网关测试](../../ai/tests/test_model_gateway.py)。

## 合成用例与复现边界

工具 `preview_reminder(text, at)` 仅用于预览；预期参数为文字 `合成测试喝水` 与时间 `2026-11-04T10:00:00+08:00`。模拟返回明确包含 `simulated=true` 与 `real_reminder_created=false`。没有真实工具实现被执行。

普通请求上限 256 tokens，工具请求 768 tokens，结果回传 384 tokens；`temperature=0`，未增加供应商私有参数。非流式返回的 token 用量已保留；流式响应没有用量字段，不按零计费解释。

本机可复核产物位于被 Git 忽略的 `build/companion-review-20261102/`：`qwen-model-catalog.json`、`qwen_live_probe.py`、`qwen3.8-flash-live-result.json`、`qwen3.8-max-live-result.json` 与 `qwen-readiness.json`。脚本从私密文件在内存中加载凭据；产物只保留配置、判定、耗时与用量，不包含凭据、原始消息或提供商错误正文。重新运行脚本会产生新的云端请求，不属于离线检查。

## 下一阶段验收

继续使用既有 VNAS/Hermes，不为奶蛙另建任务系统。云端只是可切换的推理来源，本地模型上线后复用同一网关契约和验收用例。

1. **真实运行时**：先验证部署环境到平台的 TLS 连接，再让 Hermes 经沙箱外网关完成同一组合成请求。本轮 SDK 直连成功不替代这一步。
2. **自然语言提醒**：输入“明早十点提醒我交材料”，展示具体日期、时区，确认后持久化；重启仍能触发。当前固定时间参数测试没有验证相对时间理解。
3. **主动回报**：接入现有任务未读通知；奶蛙带回实际任务结果，支持打开原任务。重复推送、刷新和重连不重复执行或庆祝；通知已读不等于用户事项完成。
4. **文件任务与权限**：仅使用合成会议文本，经原确认卡保存；拒绝不写入，真实执行成功才显示已保存。
5. **本地模型同测**：替换 Base URL、模型 ID 与能力配置后重复上述检查；本地失败不自动转云端。定时调度、任务记录、权限和奶蛙状态独立于模型。

提醒与主动回报的产品行为见[虚拟伙伴规格](../specs/virtual-companion.md#personal-agent-的下一步设计尚未实现)，接入配置见[运行手册](../runbooks/try-ai-assistant-on-experimental-nas.md#qwen-云端联调与后续本地接入)。
