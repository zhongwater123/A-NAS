# 语音处理的声纹评估

状态：完成（2026-10-21）
更新时间：2026-10-21

本文是[语音处理技术设计](../architecture/voice.md)的模型与阈值依据：在开发机上用公开的会议录音评估三个可离线运行的说话人向量模型，选出随系统交付的声纹模型，并定下自动命名、建议与合并发言人的阈值。数据集与候选模型只在开发机使用，不进 release、不上 NAS。

## 问题

- 同一个人在不同的会议录音里，声纹能否稳定地比同一房间里的其他人更接近；一个人说话多少（2 分钟、30 秒、10 秒）对此有多大影响。
- 自动命名（不问成员）要求几乎不认错人：阈值取多少，能认出多少。
- 还没被命名的人（陌生人）在阈值下被认成别人的比例。
- 模型的速度与内存是否适合 i3-12100（4 核 8 线程）、8 GB 内存的 NAS。

## 数据

[AISHELL-4](https://www.openslr.org/111/) 测试集（Apache-2.0，经 Hugging Face 的 `AISHELL/AISHELL-4` 下载）：中文会议室里 8 麦克风阵列的远场录音，带逐句的说话人与时间标注（RTTM）。同一组人在同一房间录了多场会议，说话人编号（如 `004-M`）在同一组的各场之间指同一个人，所以同组不同场次的同一编号是同一个人的跨录音样本；同一房间里的其他人是最难分开的陌生人（同样的房间混响与麦克风）。只取阵列的第 0 路，相当于桌上的一部手机或录音笔。

| 组 | 场次 | 人数 |
|---|---|---|
| L_R003 | S01、S02 | 6 |
| L_R004 | S01、S02 | 7 |
| M_R003 | S01、S02 | 6 |
| S_R003 | S01、S02 | 5 |
| S_R004 | S01、S02 | 5 |

共 10 场、29 个编号，每场约 35 分钟；下载约 2.6 GB。

## 方法

代码在 [`ai/eval/voiceprints.py`](../../ai/eval/voiceprints.py)，在 Debian 13 开发镜像中以与声纹 Worker 相同的 Python 3.13、sherpa-onnx 1.13.8 运行，向量直接来自 Worker 的 `SpeakerProvider`。

- **发言人的声纹**与产品服务的规则相同（[`profileStretches`](../../internal/voice/speakers.go)）：取这个人不与他人重叠的发言，每段 1–15 秒，最长的优先，直到用完预算；每段一个向量，按时长加权平均后归一化。预算 120 秒对应一位正常参与讨论的人，30 秒与 10 秒对应只说了几句的人。
- **成对比较（全部）**：所有跨场次的两两组合，同组同编号为同一人，其余为不同人；报告等错误率（EER）与各阈值下的误接受率（FAR）、误拒绝率（FRR）。
- **按家庭（同组）**：有些人参加了不止一组的录制，编号不同而声纹在每一场都一致（见下文），所以跨组的“不同人”并不确定。按家庭的结果只数确定的部分，也正是一个成员的声纹库的样子：同一组里，另一场的同一编号是同一个人，其他编号是别人。
  - **命名**：模拟成员在一场里命名了所有人、再处理同组的另一场：每个声纹与另一场的全部声纹比较，最高分不低于阈值时命名为那个人，计命名的精确率与召回。
  - **陌生人**：把这个人自己在另一场的声纹拿掉，只剩同组的别人；最高分仍不低于阈值即被认成别人。这是家里还没被命名的人被错认的比例。
- **长录音的分段**（`--halves`）：超过一小时的录音分段转写，各段的发言人再按声纹合并（[`identify`](../../internal/voice/pipeline.go)）。把每场会议切成前后两半，各自为每个人建声纹，后一半的每个声音按产品服务的规则（找前一半中分数最高、不低于阈值且未被占用的声音）合并：合到别的编号上是错合，自己的编号在前一半却没合上是拆开。

## 结果

三个模型都来自 [3D-Speaker](https://github.com/modelscope/3D-Speaker)（Apache-2.0），用 sherpa-onnx 发布的 ONNX 文件（`speaker-recongition-models`，SHA-256 与发布的 `checksum.txt` 一致）：

| 模型 | 训练数据 | 文件 |
|---|---|---|
| CAM++ zh-cn common | 中文，约 20 万说话人 | 28 MB |
| CAM++ zh-en common advanced | 中文与英文的大规模说话人数据 | 28 MB |
| ERes2NetV2 zh-cn common | 中文，约 20 万说话人 | 71 MB |

### 同一个人的跨组录音

两个 CAM++ 模型都把下面几对不同组、不同编号的人打出与同一个人相当的分数，并且三者两两一致，最可能是同一个人参加了几组的录制（数据集没有给出跨组的身份）：

| 标签对（120 秒的声纹） | CAM++ zh-cn | CAM++ zh-en advanced |
|---|---|---|
| L_R004/001-M ~ M_R003/001-M | 0.833 | 0.836 |
| L_R003/006-M ~ L_R004/001-M | 0.825 | 0.851 |
| L_R003/006-M ~ M_R003/001-M | 0.794 | 0.834 |
| L_R003/004-M ~ S_R003/003-M | 0.759 | 0.772 |

因此“全部成对比较”的误接受率与 EER 把这些人算成了不同人，偏高且不可信（ERes2NetV2 在 120 秒时的 EER 0.027 主要来自它们）。下面按家庭（同组）比较。

### 按家庭（同组）

每个模型 29 对同一人、142 对同组的不同人（跨场次），142 对同一场里的不同人。“认错”为同组的不同人分数不低于阈值的对数，“召回”为另一场命名过之后认出的比例，“陌生人”为还没命名的人被认成别人的比例。

| 模型 | 声纹时长 | 同一人最低 | 不同人最高 | 无认错的最低阈值 | 该阈值的召回 |
|---|---|---|---|---|---|
| CAM++ zh-cn | 120 秒 | 0.815 | 0.704 | 0.72 | 1.000 |
| | 30 秒 | 0.701 | 0.778 | 0.80 | 0.897 |
| | 10 秒 | 0.331 | 0.702 | 0.72 | 0.793 |
| **CAM++ zh-en advanced** | 120 秒 | 0.787 | **0.605** | 0.66 | 1.000 |
| | 30 秒 | 0.697 | 0.731 | **0.74** | **0.966** |
| | 10 秒 | 0.240 | 0.719 | 0.72 | 0.759 |
| ERes2NetV2 | 120 秒 | 0.808 | 0.649 | 0.66 | 1.000 |
| | 30 秒 | 0.691 | 0.759 | 0.76 | 0.931 |
| | 10 秒 | 0.286 | 0.771 | 0.80 | 0.241 |

CAM++ zh-en advanced 在选定阈值附近（每格为认错对数 / 召回 / 陌生人被认成别人）：

| 声纹时长 | 0.60 | 0.70 | 0.72 | **0.74** | 0.76 | 0.80 |
|---|---|---|---|---|---|---|
| 120 秒 | 2 / 1.000 / 0.069 | 0 / 1.000 / 0 | 0 / 1.000 / 0 | 0 / 1.000 / 0 | 0 / 1.000 / 0 | 0 / 0.931 / 0 |
| 30 秒 | 1 / 0.983 / 0.034 | 1 / 0.966 / 0.034 | 1 / 0.966 / 0.034 | 0 / 0.966 / 0 | 0 / 0.931 / 0 | 0 / 0.897 / 0 |
| 10 秒 | 1 / 0.966 / 0.034 | 1 / 0.793 / 0.034 | 0 / 0.759 / 0 | 0 / 0.586 / 0 | 0 / 0.483 / 0 | 0 / 0.276 / 0 |

在 0.60，10 秒的声纹也有 0.966 被认出；唯一低于 0.60 的同一人是一个 10 秒声纹（0.240）。

### 同一场里的不同人

同一场录音里两个不同编号的最高分：CAM++ zh-en advanced 在 120 秒时 0.627、30 秒时 0.722、10 秒时 0.829。10 秒的 0.829 是 L_R003S02 的 006-M 与 007-M，声纹越长分数越低（30 秒 0.776、120 秒 0.640，CAM++ zh-cn），像是这两人最长的几段发言里有标注混在一起，而不是两人声音本来就像。

### 长录音的分段

CAM++ zh-en advanced，把每场会议切成前后两半、按产品服务的规则合并后一半的 53 个声音（每格为错合 / 拆开）：

| 声纹时长 | 0.60 | 0.64 | 0.66 | 0.70 | 0.74 | 0.80 |
|---|---|---|---|---|---|---|
| 120 秒 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 1 | 0 / 1 | 0 / 4 |
| 30 秒 | 0 / 0 | 0 / 0 | 0 / 1 | 0 / 3 | 0 / 4 | 0 / 6 |
| 10 秒 | 1 / 3 | 1 / 4 | 1 / 4 | 1 / 5 | 1 / 9 | 0 / 24 |

半场里每人的发言只有整场的一半，所以“120 秒”的声纹常常不足 120 秒，同一人前后两半的分数（120 秒时最低 0.686、5% 分位 0.770）反而低于跨场次。两半之间的不同人最高 0.713（120 秒）、0.730（30 秒）：合并取分数最高的那个声音，所以只要本人也在，这些分数不造成错合；只在后一段才开口的人，分数不低于阈值时会被合到别人身上。

### 速度与内存

10 场共 8338 秒的发言（三个预算合计），开发机 12 线程，同时有其他任务运行，所以时间只能比较量级：

| 模型 | 计算时间 | 峰值内存 |
|---|---|---|
| CAM++ zh-cn | 1091 秒 | 436 MiB |
| CAM++ zh-en advanced | 1330 秒 | 330 MiB |
| ERes2NetV2 | 3451 秒 | 860 MiB |

两个 CAM++ 结构相同，约为实时的 6 到 8 倍；一小时、6 个人的会议每人最多 120 秒，约 720 秒的发言，开发机上约 2 分钟。ERes2NetV2 慢 2.6 到 3.2 倍、内存翻倍以上。

## 结论

- **模型**：随系统交付 CAM++ zh-en advanced（[清单](../../deploy/models/campplus-zh-en-advanced.json)）。它在家庭场景中把同组的不同人分得最开（120 秒时不同人最高 0.605，30 秒时在 0.74 已无认错且召回 0.966），兼顾中文与英文，速度与 CAM++ zh-cn 相当、内存最小。ERes2NetV2 没有更好，却慢得多、内存翻倍。
- **自动命名 0.74**：三个时长都没有把同组的人认成别人；说了 2 分钟或 30 秒的人认出 97% 到 100%，只说了 10 秒的人认出 59%，其余落在建议里。
- **建议 0.60**：10 秒的声纹也有 97% 至少得到“可能是”；还没命名的人被建议成别人的比例 3% 到 7%，成员点“不是”后不再出现。
- **长录音合并 0.70**（[`SameVoiceThreshold`](../../internal/voice/speakers.go)）：两半合并时，有 30 秒以上发言的声音没有错合，拆开 2% 到 6%，成员用“合并发言人”一步合上。把两个人错合成一个要逐句改回，而只在后一段才开口的人没有本人可比，所以不取拆开最少的 0.64：同一场里不同人在 120 秒时的最高分为 0.627（家庭比较）与 0.713（半场），0.70 高于前者、接近后者。
- **聚类距离 0.5**（只在豆包语音没有分开说话人时使用）沿用 sherpa-onnx 说话人分离示例的默认值，未单独评估；分离质量待用真实录音核对。
- NAS 上的速度与内存在部署后用真实录音测量。

## 局限

- AISHELL-4 是远场、多人、在同一房间的会议，比家庭里手机贴近录的声音更难；近场录音的同人相似度通常更高，阈值偏保守。
- 同一组人的两场会议往往隔得不远，同一个人跨月、跨设备（手机与录音笔）的变化没有覆盖。
- 评估用的是标注好的说话人片段；产品里每位发言人的片段来自豆包语音的说话人分离，分离出错（两人合成一人、一人拆成两人）时声纹会变差。豆包语音的密钥到位后，用真实录音核对分离质量。
- 29 个编号（其中几位可能是同一人）、每人两场的样本量只够定阈值的量级，误接受率的估计在 1% 以下时分辨率不足（每个阈值的认错对数见上表）。
- 半场约 17 分钟，产品里的分段是一小时，每段的声纹通常更长；只在后一段开口的人在 AISHELL-4 中很少，错合的风险只能由同一场不同人的分数间接估计。

## 复现

```bash
# 开发机：下载候选模型（sherpa-onnx 的 speaker-recongition-models 发布）与 AISHELL-4 测试集的 10 场
# 到 D:\A-NAS-models\speaker 与 D:\A-NAS-datasets\aishell4-test（wav/ 与 TextGrid/）
docker build -t anas-voice-dev:trixie - <<'EOF'
FROM anas-ai-dev:trixie
RUN /opt/anas-ai/bin/pip install --no-cache-dir sherpa-onnx==1.13.8 sherpa-onnx-core==1.13.8 soundfile==0.13.1
EOF
docker run --rm -v "$PWD/ai:/ai:ro" -v /mnt/d/A-NAS-models/speaker:/models:ro \
  -v /mnt/d/A-NAS-datasets/aishell4-test:/data:ro -v /mnt/d/A-NAS-datasets/runs:/runs -v ~/voice-eval-cache:/cache \
  -w /ai anas-voice-dev:trixie /opt/anas-ai/bin/python -m eval.voiceprints \
  --model /models/3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx --data /data --cache /cache \
  --out /runs/voiceprints-campplus-zh-en.json
# 同一镜像与挂载，换最后的参数：
#   从保存的声纹重算报告（不再运行模型）：--profiles /runs/voiceprints-campplus-zh-en.npz --out /runs/household.json
#   长录音的分段：--halves --model ... --data /data --cache /cache --out /runs/halves.json
```

三个模型依次各跑完一个再跑下一个；第一次读取 FLAC 后每场的第 0 路缓存在 `/cache`。报告与声纹保存在 `D:\A-NAS-datasets\runs\voiceprints-*`。
