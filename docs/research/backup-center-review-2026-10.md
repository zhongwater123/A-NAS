# 备份中心 C 端功能评审（2026-10）

状态：完成；快照侧缺口已在[备份中心规格](../specs/backup-center.md)中补齐，外部备份仍待 [#27](https://github.com/zhongwater123/A-NAS/issues/27) 决定
更新时间：2026-10-14

## 问题

[#78](https://github.com/zhongwater123/A-NAS/pull/78) 把“文件快照”与“备份”合并为备份中心，[#92](https://github.com/zhongwater123/A-NAS/pull/92) 让每个空间默认每天拍一份快照。本评审以家用 NAS 用户对“备份中心”的通常期待为标准，逐项对照现有能力，决定哪些缺口先补、哪些需要先作决定。

## 方法

1. 参照对象：群晖 DSM（Snapshot Replication、Hyper Backup、Synology Drive）、威联通 QTS（快照、HBS 3）、绿联 UGOS Pro、极空间、飞牛 fnOS 公开的备份与版本功能，以及 macOS 时间机器的找回体验。只比较功能类别与交互方式，没有在这些产品上逐项实机核对。
2. 能力项按用户任务拆分：自动保护、找回、恢复、看清保护状态、防硬盘损坏、把设备备份进 NAS。
3. 每个缺口按三条标准排序：日常是否会用到；能否在现有权限边界内完成（不新增磁盘写操作、不改 Samba 与 ACL 模型）；是否有尚待用户决定的介质、加密或权限问题。
4. 新增的“最近删除”和快照对比要在大空间上读整份快照目录，先用合成目录测 SQLite 查询开销（见下文“性能”）。

## 结果

| 能力 | 主流 C 端 NAS 的做法 | #78、#92 之后 | 本轮之后 |
|---|---|---|---|
| 定时快照、默认开启 | 按计划拍摄，新卷常带默认计划 | 每个空间默认每天 03:00 | 不变，达标 |
| 保留策略 | 分级保留：近期密、远期疏（群晖的保留策略、威联通的智能版本管理、Hyper Backup 的 Smart Recycle） | 只保留最近 N 份；每小时快照只能回到一天前 | **智能保留**：每小时、每天、每周、每月各保留若干份，至多 100 份 |
| 按名称找回 | 搜索快照或备份版本 | 有，合并相同版本 | 另标出“与现在相同”的版本 |
| 不记得名字时找回 | 时间机器式按时间浏览；回收站 | 回收站 30 天；清空回收站或经 SMB 直接删除后只能按名称搜 | **最近删除或移走**：找回页默认列出快照里有、空间里已没有的项目 |
| 在文件管理里看历史版本 | Synology Drive、Qsync 等在文件上右键看版本 | 只能进备份中心按名称找 | **历史版本**：右键或详细信息栏打开，下载、另存一份、还原 |
| 还原到原位 | 用旧版本替换当前文件 | 只能另存，同名时要改名 | **还原此版本**：当前文件移到回收站，旧版本回到原处 |
| 看清快照之后改了什么 | 快照浏览器可比较差异 | 无 | **与现在不同**：快照中逐项标出已不在空间中、已修改、内有变化，可只看这些 |
| 整份快照恢复 | 还原整个快照（群晖为回滚）或复制出来 | 只能逐项恢复 | **全部恢复**到新文件夹，文件夹内“恢复此文件夹” |
| 恢复后保留修改时间 | 保留 | 恢复出的文件修改时间为当前时间 | 保留快照中的修改时间 |
| 快照占用空间 | 显示快照独占空间 | 只显示其中文件的总大小 | 未做：需要 Btrfs qgroup，或评估 `btrfs filesystem du` 在大空间上的开销 |
| Windows“以前的版本” | 群晖经 SMB 提供 | 无 | 未做：要让 SMB 看到快照目录，需设计快照的可见性与 ACL，属于权限边界变化 |
| 防勒索的锁定快照 | 群晖可设不可删除的快照 | SMB 看不到快照；只有所有者与管理员能经 Web 删除 | 未做：风险已较低，排在后面 |
| 失败通知 | 系统通知、邮件或手机推送 | 只在备份中心概览与侧栏显示 | 未做：桌面还没有通用的通知中心 |
| 备份到其他硬盘或远程 | Hyper Backup、HBS 3、USB 一键复制、云盘同步 | 规划中，界面如实说明 | 未做：依赖 [#25](https://github.com/zhongwater123/A-NAS/issues/25) 与 #27 的介质、传输方式、加密与密钥决定 |
| 把手机、电脑备份进 NAS | 手机相册备份、电脑备份、Time Machine | 相册可从手机上传；无 Time Machine 目标 | 未做：属于另一条功能线 |

### 性能

“最近删除”与快照对比用 SQLite 索引逐行比对快照目录与文件目录。合成目录（500 个文件夹 × 100 个文件，14 份快照，共 707,000 行快照条目，1% 已删除）在开发机上：

- 依次比对全部 14 份快照找出被删除的顶层项目：0.51 秒，约每行 0.7 微秒；
- 一层 500 个未改动文件夹逐个判断“内有变化”（最坏情况，需比对全部后代）：0.03 秒。

据此“最近删除”每次最多比对 100 万行、返回 200 项，超出时说明只列出了最近的一部分；查询计划全部走 `snapshot_entries(snapshot_id, backend_key)` 与 `entries(space_id, relative_path)` 唯一索引。实验 NAS 的 CPU 慢于开发机，部署后需实测。

## 结论与待验证

- 本轮补齐所有不需要新决定、也不改变权限边界的快照侧缺口。文件代理只多了一项操作：以用户身份设置用户自己文件的修改时间（`set_mod_time`），与 SMB 客户端本来就能做的事相同，因此不需要 ADR。
- 剩余缺口按价值排序：
  1. **外部备份**：家用单盘 NAS 防硬盘损坏的唯一手段，也是与主流产品差距最大的一项。需要先在 #27 决定首个介质（建议 USB 外接盘，依赖 #25）、传输方式（Btrfs `send/receive` 或文件级复制）、加密与密钥保管，再写运行手册。
  2. **Windows“以前的版本”**：Windows 用户不打开网页也能找回，需要先写 ADR 定下快照在 SMB 中的可见性与权限。
  3. **快照占用空间**与**失败通知**：分别依赖 qgroup 性能评估与桌面通知中心。
- 部署后在实验 NAS 上实测“最近删除”在真实空间上的耗时，并按[实验存储手册](../runbooks/provision-v1.0.1-experimental-storage.md#功能验收)第 4 步验证智能保留与还原此版本。
