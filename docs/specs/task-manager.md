# 任务管理器

状态：implemented
更新时间：2026-10-23

## 目标

在“设置 → 任务管理器”中查看设备实时资源用量，并定位占用资源的服务和进程。界面分为“设备运行状态”和“服务与进程”两大板块。

## 非目标

- 本版只读，不提供结束进程、重启服务、修改优先级或硬件配置。
- 不保存长期历史，不增加指标数据库、告警服务或新的后台守护进程。
- 不读取进程命令行、环境变量、打开的文件或用户文件内容。

## 设计方案

扩展现有 Host Agent 采集能力，经受限 Unix Socket 和产品 API 提供数据，沿用设置窗口的图标、卡片、错误提示和响应式布局。开发模式使用同一契约的 Fake Adapter。

仅搭建静态页面无法显示真实服务和进程；引入独立监控服务会增加安装、存储和权限配置。这两种方案不适合本次设置功能扩展。

### 设备运行状态

| 分页 | 内容 |
|---|---|
| 总览 | CPU、内存、网络收发、磁盘读写的即时指标与短时趋势，以及 GPU、NPU 的检测和采集状态 |
| CPU | 型号、逻辑核数、总体使用率和使用率趋势 |
| GPU | 按设备展示识别信息和驱动可提供的使用率、显存；缺失指标明确标记不可用 |
| NPU | 按设备展示识别信息和驱动可提供的使用率；缺失指标明确标记不可用 |
| 内存 | 总量、已用、可用、使用率与趋势；可回收缓存不算作不可用内存 |
| 网络 | 按网卡展示接收与发送速率、累计收发量和趋势；总览沿用现有物理接口优先的汇总口径 |
| 硬盘 | 按物理磁盘展示型号、容量、读取与写入速率、趋势；使用稳定资源 ID 关联设备 |

页面不显示数据来源或更新时间行；数据来源和采样时间仍保留在 API 中用于诊断与计算。页面打开且浏览器可见时每两秒刷新，短时趋势最多保留本次打开期间最近六十个采样点。首次显示真实短窗口采样结果，不把未采样值显示成零。速度按每秒字节数展示，容量遵循项目的二进制单位约定。

GPU、NPU 的识别和指标可用性分别表达：未发现设备显示“未检测到设备”；已发现但驱动没有指标显示“当前驱动不提供此指标”；读取失败显示“暂时无法读取”。使用率、已用显存和总显存分别保留可用状态，一个指标成功不能覆盖另一个指标不可用的原因。支持多设备。已有设备不能因为一个指标缺失而整个消失，不使用随机数据模拟实时值。

### 服务与进程

顶部显示运行中的系统服务数量，并提供“运行中的服务”和“进程”两个列表视图。服务行显示名称与运行状态；进程行显示名称与 PID。名称前优先显示程序或服务自带的本地图标，未匹配或加载失败时显示服务/进程的默认图标。两种视图均提供 CPU 占用、内存占用、硬盘读取速度、硬盘写入速度列，支持按这些数值升降序排序，默认按 CPU 降序。名称搜索在当前视图生效。

服务用量按其 cgroup 聚合，包括子进程；进程用量来自该 PID 的计数器。两种统计口径分开显示，不把服务与其进程相加。CPU 占用统一以整机逻辑 CPU 总容量为 100%；内存展示实际字节数；磁盘速度使用实际存储 I/O 字节计数，不以普通 read/write 调用量替代。

硬件状态、服务与进程对所有有效账号开放，管理员与成员具有相同的只读查看能力；产品 API 强制校验会话，未登录请求返回 401。

## 场景

### 打开任务管理器

- Given：账号已登录。
- When：在设置侧栏点击“任务管理器”，或点击桌面状态栏的 CPU 与内存仪表盘（[状态栏规格](host-metrics-status-bar.md#从仪表盘打开任务管理器)）。
- Then：默认显示“设备运行状态 → 总览”，可以切换全部七个设备分页；管理员和成员都可以进入“服务与进程”。窄窗口下导航可横向滚动，表格不会挤坏设置侧栏。

### 查找高占用进程

- Given：管理员或成员已进入“服务与进程”。
- When：搜索名称或 PID，点击 CPU、内存、硬盘读取速度或硬盘写入速度列。
- Then：按数值排序，而非按格式化文字排序；点击同一列切换升降序。缺失值排在已知值之后。没有匹配结果时显示明确空态。

### 采样中进程退出或设备变化

- Given：两次采样之间有进程退出、PID 被复用或设备计数器重置。
- When：计算速率。
- Then：已退出进程从列表移除；PID 与启动时间共同确认同一进程；新进程等待有效基线，重置计数器不产生负值或尖峰。服务停止后不再出现在运行列表。

### 读取失败与恢复

- Given：页面已成功读取一次数据。
- When：某次刷新失败。
- Then：保留最近数据并显示连接中断，趋势不补零；恢复后继续采样。首次失败提供重试入口。服务列表读取失败不伪装为“没有运行中的服务”，局部设备失败不阻止其他设备显示。

### 页面隐藏或关闭

- Given：任务管理器正在刷新。
- When：切换到其他设置分区、关闭窗口或隐藏浏览器页面。
- Then：停止对应页面的轮询并取消未完成请求；恢复可见时立即刷新，不累积并发请求或重复定时器。会话过期沿用现有返回登录页行为。

## 边界与失败

- 产品服务不直接读取宿主机进程信息，不获得额外 Linux 组权限；通过 Host Agent 的类型化只读接口读取。
- CPU、内存和网络遵循现有采样规则。新增磁盘、进程与服务采样分别使用 Linux 只读计数器和固定参数的 systemd 查询，不接受客户端任意命令、路径或 PID 操作。
- 服务、进程采集设定超时和输出上限；超限必须显示不完整状态，不能把截断的列表当作完整结果。
- 多浏览器共享 Host Agent 的采样缓存，不因请求密度改变百分比和速率口径。采样窗口及观测时间随响应返回，客户端不以本地请求间隔重新计算速率。
- GPU 通过 DRM class 发现设备，当前提供 AMD amdgpu sysfs 的使用率与显存指标，其他驱动明确显示不支持采集；NPU 通过 Linux accel class 发现设备，当前只展示识别信息，不宣称已有通用使用率接口。GPU/NPU 不为监控安装驱动或改变设备权限。
- 采集调用最多运行 4 秒；固定的 `lsblk` 与 `systemctl show` 命令各限 1 秒与 1 MiB 输出；每次最多列出 4096 个进程和 512 个服务，达到上限标记部分数据。进程内存为 RSS；服务内存为 cgroup 的当前用量（含其缓存），两者不保证相加相等。
- 产品 API 为 `GET /api/v1/task-manager/device` 和 `GET /api/v1/task-manager/tasks`，分别对应 Host Agent 的 `/v1/task-manager/device` 和 `/v1/task-manager/tasks`，响应禁止缓存。部署需同时更新 Host Agent 和产品服务；旧代理或不支持任务管理器的 Adapter 返回明确不可用。

### 图标来源

Host Agent 根据进程可执行文件的完整路径及服务 MainPID 匹配本机安装的 desktop entry，在 `/usr/share` 与 `/usr/local/share` 下找出可能是图标的文件，不执行 desktop entry 的命令、不读取用户目录、不通过远程网址获取图标。服务 MainPID 仅在采集端用于图标关联，不替代服务的 cgroup 统计。

Host Agent 不读取也不解码图标内容：它只给出每个图标的候选文件（至多 8 个，按优先顺序），由产品服务读取并解码，所以 root 进程中没有图片解码器（[#221](https://github.com/zhongwater123/A-NAS/issues/221)）。产品服务只读取这两个目录下的文件，并经 `os.Root` 打开，符号链接出不了目录。

支持 PNG、JPEG、WebP 和自包含的静态 SVG；位图限制尺寸后缩为 64px PNG，SVG 拒绝脚本、外部资源及活动内容。一个候选文件无法使用时换下一个。解码结果（包括失败）缓存 5 分钟，按内容哈希去重，快照最多携带 64 个图标、单项 24 KiB、总计 1 MiB。没有可安全使用的图标不影响指标采集，页面退回默认图标。

## 验收证据

自动化验收覆盖：

- Linux 采样测试：相邻窗口、首次采样、缓存、计数器重置、PID 复用、进程退出、设备缺失、部分失败与超时。
- IPC 与 API 契约测试：Fake 和真实适配契约一致、未登录拒绝、成员与管理员均可读取进程、无敏感命令参数、错误与可用性状态。
- 前端测试：两大板块与七个分页、数值排序和搜索、不可用提示、断线保留数据、页面隐藏停止刷新、会话失效处理。
- 完整本地验证命令为 `make check`；Fake 模式用于界面检查，真实硬件支持以已实现的采集接口为准。
