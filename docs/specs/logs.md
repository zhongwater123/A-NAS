# 日志

状态：implemented
更新时间：2026-10-12

## 目标

让家庭用户在一个地方回答两类问题：“谁在什么时候登录、做了什么”（活动记录），以及“设备上的服务出了什么问题”（系统日志）。桌面上原来规划中的“日志”应用并入“设置”，成为“设置 → 日志”分区；排查时不再需要 SSH 到 NAS 上以 root 执行 `journalctl`。

## 非目标

- 不做告警、通知推送或日志转发（syslog、远程 journald、云端）。
- 不做诊断包；“导出”只把当前筛选下的记录保存为文件。
- 不提供删除、清空或修改记录的入口，也不改变保留期限：活动记录永久保存在系统盘的各模块数据库中，系统日志的保留由 journald 配置决定。
- 不读取 A-NAS 服务清单之外的系统日志，不读取内核、SSH、sudo 或其他用户的日志，也不读取应用中心安装的容器日志（容器日志仍在 Docker 中查看，见[容器管理](container-management.md)）。
- 不改变 `/api/v1/audit`：它仍是管理员原样导出全部审计的接口，供运行手册收集证据。
- 不追溯补齐历史：登录记录从部署本功能后开始产生。

## 结构

“设置”侧栏在“用户与权限”之下新增“日志”，所有角色可见。分区顶部是两个分页：

| 分页 | 成员 | 管理员 | 内容 |
|---|---|---|---|
| 活动记录 | 只看与自己有关的记录（标题为“我的活动”） | 全部账号与系统任务 | 登录、账号、文件、存储与相册的操作，按天分组的时间线 |
| 系统日志 | 不显示 | 可用 | A-NAS 服务的运行日志，等宽字体的日志列表 |

成员只有“活动记录”一个分页，因此不显示分页切换。桌面不再有“日志”图标；在“全部应用”中搜索“日志”“审计”或“登录记录”会找到“设置”。“我的账号”的“本次登录”下方增加“登录记录”一行，点击跳到“日志 → 活动记录”并只看登录类记录。侧栏“规划中”的“安全与审计”改名为“安全”。

## 场景

### 管理员浏览活动记录

- Given：管理员打开“设置 → 日志”。
- When：页面载入。
- Then：显示“活动记录”分页，最新的记录在最上面，按“今天”“昨天”“10月10日 星期六”分组。每条记录是一句中文描述（如“alice 上传了 报告.pdf”“有人尝试以 bob 登录，失败”），配类别图标、类别与来源说明和时间。每次载入 50 条，滚动到底部或点击“加载更早的记录”继续读取，没有更多时显示“没有更早的记录了”。
- And：同一成员在 5 分钟内连续的同类文件或照片操作合并为一条（如“alice 上传了 12 个文件”，下方列出前几个文件名）；点开后逐条列出。

### 筛选与搜索

- Given：活动记录已显示。
- When：选择类别（全部、登录、账号、文件、存储、相册）、成员（仅管理员；所有成员、某个账号或“系统任务”）、时间范围（近 1 小时、近 24 小时、近 7 天、近 30 天、全部时间），或在搜索框输入文字。
- Then：列表从最新开始按条件重新读取，输入停止 0.3 秒后才发出搜索。搜索匹配文件名、照片名、操作代码、来源地址与成员账号名。没有结果时显示“没有符合条件的记录”和“清除筛选”按钮。

### 查看一条记录的详细信息

- Given：列表中有一条记录。
- When：点击它。
- Then：在原位置展开详细信息：完整时间（含秒和时区）、操作代码（如 `file.uploaded`）、对象类型与 ID、来源、原始详情和记录 ID，供对照运行手册与审计导出。再次点击收起；合并的记录展开后先显示其中每一条。

### 登录、登录失败与退出登录被记录

- Given：设备已部署本功能。
- When：有人在本机屏幕、局域网浏览器或 SSH 隧道中登录、输错密码或退出登录。
- Then：活动记录的“登录”类别出现对应记录。来源显示为“本机屏幕”“局域网 · 客户端地址”或“本机回环（SSH 隧道或设备上的浏览器）”；局域网地址取自 Caddy 设置的 `X-Forwarded-For`。登录失败注明原因：密码错误、账号已停用或账号不存在；账号不存在时显示尝试的账号名（截断到 64 个字符）。会话到期不产生记录。

### 成员只看到自己的活动

- Given：成员 `alice` 打开“设置 → 日志”。
- When：页面载入。
- Then：标题为“我的活动”，只有“活动记录”，没有成员筛选。列表包含 `alice` 的登录、登录失败、退出与改密，`alice` 在文件和相册中的操作，以及管理员对这个账号做的事：重置密码、开始和结束只读查看 `alice` 的个人空间或私有图库。看不到其他成员的记录、存储任务或系统日志；成员直接请求他人记录或系统日志时服务端分别忽略筛选或返回 `403`。

### 管理员看不到他人私有内容的名称

- Given：成员 `alice` 在个人空间上传了 `体检报告.pdf`，并在相册中导入了照片。
- When：管理员浏览或搜索活动记录。
- Then：文件记录显示为“alice 在个人空间上传了 1 个文件”，不显示文件名和文件 ID，详细信息中也没有；搜索“体检”不会命中这条记录。相册记录只对操作者本人可见，管理员看不到 `alice` 的照片操作。共享空间中的操作和管理员自己的操作显示完整名称。这与[统一身份与文件授权](unified-identity-and-file-acl.md)中“管理员默认看不到成员的个人空间和私有图库”一致；需要找回内容时仍使用可审计的只读查看。

### 导出活动记录

- Given：活动记录已按某些条件筛选。
- When：点击页头的“导出”。
- Then：按当前筛选从最新开始读取至多 5,000 条，下载为 UTF-8（带 BOM，Excel 可直接打开）的 CSV，列为时间、类别、成员、描述、来源、操作代码、对象类型、对象 ID 和记录 ID，文件名形如 `a-nas-activity-20261012-1432.csv`。导出期间按钮显示进度，不能重复点击；超过上限时提示只导出了最新的 5,000 条。

### 管理员查看系统日志

- Given：管理员打开“日志 → 系统日志”。
- When：页面载入。
- Then：列出全部 A-NAS 服务的最新 200 行日志，新的在上：时间（精确到毫秒）、级别标记（错误、警告、信息、调试）、服务名与消息；错误行带浅红底色，警告行带浅橙底色。点击一行展开结构化字段（如 `error`、`socket`）、进程号、systemd 单元与日志游标。底部可以加载更早的日志。
- And：数据来自模拟环境时页头显示“模拟数据”。

### 按服务、级别、时间和关键词筛选系统日志

- Given：系统日志已显示。
- When：选择服务（全部服务、产品服务、Host Agent、相册服务、容器代理、本地 AI、媒体 Worker、本机屏幕、文件共享 Samba、局域网入口 Caddy）、级别（全部、警告及以上、仅错误）、时间范围，或输入关键词。
- Then：从最新重新读取。产品服务等 A-NAS 进程以 JSON 写日志，级别、消息和字段取自日志本身；systemd 自身与其他程序的行使用 journald 优先级。一次读取最多检查 20,000 行；在此之前没有凑满一页时，页尾说明“已检查到某时间”，可以继续加载更早的日志。

### 实时跟随

- Given：系统日志已显示。
- When：打开“实时”开关。
- Then：每 5 秒读取一次比列表最新一行更新的日志，新行以淡入高亮插在顶部，列表滚动位置不跳动；一次超过 200 行新日志时整页重新载入。切换分页、关闭设置窗口或关闭开关后停止读取。

### 导出系统日志

- Given：系统日志已按条件筛选。
- When：点击“导出”。
- Then：按当前筛选读取至多 5,000 行，下载为纯文本 `a-nas-system-log-20261012-1432.log`，每行包含 ISO 时间、级别、服务、消息和字段，便于附在问题反馈或交给开发者。

## 边界与失败

- 活动记录由产品服务读取各模块的审计表并合并：账号与登录（`control.db`）、文件与快照（`files.db`）、存储计划（`storage.db`），以及相册服务数据卷上的 Catalog。各来源按同一游标（毫秒时间与记录 ID）分页，合并结果严格按时间倒序且不重复、不遗漏。
- 相册服务不可用或数据卷离线时，其余来源照常返回，列表上方提示“相册的活动暂时无法读取”；某个来源失败不影响其他来源。
- 系统日志只经 Host Agent 读取（[ADR 0019](../adr/0019-read-service-logs-through-the-host-agent.md)）：产品服务只能按服务键名请求，Host Agent 以固定参数运行 `journalctl`，只匹配白名单中的单元；关键词在 Host Agent 中按纯文本匹配，不传给 `journalctl` 当作表达式。每行消息超过 16 KiB 时截断并标记。单次读取在 10 秒内结束，超时返回已读到的部分。
- Host Agent 不可用时，系统日志显示“无法读取系统日志”和“重试”，活动记录不受影响。
- 新文件审计记录写入所在空间；部署前已有的记录在启动时按文件目录、回收站和快照补写空间。仍无法确定空间的旧记录对管理员一律按他人私有内容处理（不显示名称），除非操作者就是管理员本人。
- 登录失败的记录没有频率限制；局域网中持续猜测密码会让 `control.db` 随之增长。
- 筛选条件在设置窗口关闭后保留到页面刷新，与其他分区一致。
