# 剪辑中心

状态：implemented（首版 M0–M10 于 2026-11-19 合入；2026-11-20 规划改为成员规划进程里的一次对话，[决定](../decisions/2026-11-20-montage-planning-as-a-vnas-session.md)，[#608](https://github.com/zhongwater123/A-NAS/pull/608)；出片后的二次编辑按 [ADR 0039](../adr/0039-edit-montage-films-as-server-side-drafts-saved-as-new-versions.md) 实施中，[#596](https://github.com/zhongwater123/A-NAS/issues/596)）
更新时间：2026-11-20

## 目标

成员把一次旅行或活动拍的一批视频交给剪辑中心，选一首歌、写一句要求，就能得到一条跟着音乐剪好的成片。成片存进本人的个人图库，像其他视频一样播放、下载。

剪辑中心是桌面上与家庭中心、影视中心并列的应用（[#514](https://github.com/zhongwater123/A-NAS/issues/514)）。实现方式见[技术设计](../architecture/montage-center.md)。

## 已确认（2026-11-17）

经过见[决定记录](../decisions/2026-11-17-montage-center-first-version.md)。

- **剪法与配乐**：
  - 剪法用原型第八版；
  - 配乐从本人的音乐库选，或上传一首存进本人个人空间的“音乐”文件夹；NAS 用 allin1 分析节拍、重拍与段落，和原型第八版相同（2026-11-18 用户决定）；allin1 的商业版权待议，见[决定记录](../decisions/2026-11-17-montage-center-first-version.md#allin1-的商业版权)。
- **素材**：可以从相册选入本人能看到的视频，包括共享图库里别人上传的（2026-11-18）。
- **数据归属**：
  - 原片和成片都在相册里，相册是事实源：上传的原片与成片存进本人的个人图库，从相册选入的视频留在原来的图库；
  - 视频的基础分析（窗口向量、卡片、画质、卡片描述）由相册计算并保存，按内容复用；
  - 剪辑中心只保存项目、规划、时间线与任务，以及选歌时复制的配乐副本。
- **规划**：
  - 由成员自己的 VNAS 完成，只发文字描述、不发画面；
  - 描述不抄号码，交给 VNAS 前再替换可能出现的号码；画面里的其他文字可以写进描述，这是功能本身的设计（2026-11-18）；
  - 任务走到规划时，NAS 在后台自动发起，成员不用开着桌面或剪辑中心（2026-11-18 改定）；成员点“开始”时，同时允许 VNAS 在后台为自己的剪辑规划。
- **做不到的要求**：简单提示一下。
- **出片后的二次编辑**（2026-11-19）：确认一版、修改镜头、说一句话重剪，见[出片后的二次编辑](#出片后的二次编辑)；实现见 [ADR 0039](../adr/0039-edit-montage-films-as-server-side-drafts-saved-as-new-versions.md)，两项默认做法见[决定记录](../decisions/2026-11-19-montage-edit-defaults.md)。

## 本稿补充的默认规则

以下是让实现和验收可以执行的规则，2026-11-18 用户确认全部保留，见[决定记录](../decisions/2026-11-17-montage-center-default-rules.md)。

- **推荐方案**：#514 要求“展示推荐方案，用户确认开始后生成”。配乐页显示素材数与总时长，默认选中本人上次用的歌；第一次用时不预选，提示从音乐库选或上传一首。选中的段落按找到的副歌给出，可以试听、拖动起点。用户确认后才开始。
- **项目与版本的名称**：新项目默认以素材的拍摄日期命名，例如“2026-08-02 至 08-04”，可以改名。每个成片是一个版本，版本号在项目内从 1 递增。
- **两个方案**：每次生成规划两次，剪出方案一、方案二两条成片，并排给成员挑，和原型挑方案的做法相同，只是原型出三条（2026-11-18 用户决定）。两条都存进相册，各占一个版本号；成员下载喜欢的一条，另一条可以在相册里删掉。两条由 VNAS 在同一轮里规划；这一轮在方案二之前结束时，方案一照常存进相册，方案二按“规划没有交回”处理。升级前已经开始的任务照开始时的样子只出一条。
- **按拍摄时间排列**：默认打开，和第八版相同。
- **成片在相册里的样子**：存进本人个人图库的根目录，文件名“<项目名> v<版本号>.mp4”，拍摄时间取素材里最晚的拍摄时间，所以成片在时间线上排在这批素材后面。
- **分析结果保留多久**：一个视频没有任何未撤销的授权引用满 7 天后，相册删掉它的剪辑分析。
- **桌面提示**：成员开着桌面时提示四件事：等待规划（VNAS 没开启或还没接手时写明原因）、正在规划、成片已存进相册、需要处理。
- **规划等多久**：VNAS 开始规划后，距最后一次调用剪辑工具 20 分钟没有新的调用，或开始后 65 分钟仍没交齐，就当作没有交回（[#607](https://github.com/zhongwater123/A-NAS/pull/607) 起；原为开始后 30 分钟，模型交大纲之前读 brief 就可能超过）。等 VNAS 接手超过 10 分钟，项目页写“VNAS 还没有接手”。
- **后台规划的授权**：点“开始”“重新规划”，或在任务停下时点“去掉这些继续”“重试分析”（这几项之后都可能要规划），都留下授权；7 天内有效，最多 5 轮，同一成员的几个任务共用，再做一次这些操作就刷新。
- **规划过程的记录**：规划是成员 VNAS 里的一次对话，标题“剪辑规划 · <项目名>”，留在 VNAS 的对话历史里，成员可以打开它接着说；不出现在“定时任务”里（2026-11-20 用户[决定](../decisions/2026-11-20-montage-planning-as-a-vnas-session.md)，原为定时任务里的一条、跑完删掉）。项目页显示规划状态和 VNAS 指出的找不到的内容。
- **上传部分失败**：上传队列跑完后列出成功与失败的文件，失败的可以重试或跳过；只用上传成功的视频建项目。
- **一次能交多少**：一次最多 500 个视频；一句话要求最多 200 字；配乐文件不超过 100 MiB，时长 30 秒到 8 分钟。
- **活动记录**：首版不写。

## 非目标

- 一次出三版、快捷微调。挑一版与精修见[出片后的二次编辑](#出片后的二次编辑)，在首版闭环之后实施（[#596](https://github.com/zhongwater123/A-NAS/issues/596)）。
- 竖屏、指定时长、多首歌、字幕、保留原声。成片固定为 1920×1080、30 帧，时长跟着音乐段落走。
- 日常或定时剪辑、VNAS 自主剪辑、扫描整个图库：#514 划在本 issue 之外。
- 把接连拍的几段原片拼成一条再剪（第八版的拼接工具）：首版每段视频单独处理。
- 断点续传：沿用相册的上传，单个视频最大 4 GiB。
- RK3588。

其余各项延后的理由见技术设计的“首版范围”；断点续传的取舍见技术设计的“考虑过的替代方案”。

## 场景

### 上传一批视频新建项目

- Given：成员 A 打开剪辑中心。
- When：A 拖入一批视频（或一个文件夹），上传完成后确认“新建项目”（默认选项；也可以选“加入已有项目”）。
- Then：
  - 视频经相册的上传队列存进 A 的个人图库，进度也显示在传输中心；
  - 上传失败的按默认规则处理；
  - 单独上传的 MOV 如果补进了图库里在等它的实况照片，它不会成为新视频，页面说明它没有加入项目；
  - 新项目只包含这一批视频，A 的其他视频不会混进来；
  - 相册开始在后台分析这些视频，项目页显示分析进度。

### 从相册选视频

- Given：A 的相册里已有视频。
- When：A 在剪辑中心用相册的选择器选几段 A 能看到的视频，建项目或加入已有项目。
- Then：只有选中的视频进入项目，视频留在原来的图库（可以是共享图库）。A 看不到的、在回收站里的、不是视频的，都不能选入。

### 追加素材

- Given：A 的项目已有成片。
- When：A 再上传一批视频，上传完选“加入已有项目”。
- Then：素材追加进项目，已有成片不变，也不会自动重新生成；由 A 决定是否再生成一版。任务进行中追加素材或改歌、改要求，只影响下一次生成，进行中的任务照原样做完。

### 确认素材与配乐

- Given：A 的项目素材已定。
- When：A 进入配乐页。
- Then：
  - 列出 A 在音乐库里能看到的歌，也可以上传一首；
  - A 选定一首后，NAS 复制一份并分析，页面显示进度；
  - 选中的段落可以试听，不对就拖动起点，吸附到最近的重拍；没找到副歌时提示“请试听确认”；
  - 素材数、总时长与默认选中的歌按默认规则的“推荐方案”显示。

### 写一句要求并开始

- When：A 写一句要求，选择是否按拍摄时间排列，点“开始”。
- Then：
  - 生成一个任务，页面显示当前步骤、进度、排队位置；
  - A 可以关掉窗口去做别的，回来时进度从服务端恢复；
  - 要求里出现竖屏、指定时长、两首歌、字幕、原声时，输入框下方提示首版的限制，不拦着继续。

### 规划

- Given：A 点了“开始”，然后关掉了浏览器；任务分析完成，进入“等待规划”。
- When：NAS 上没有别的规划在跑。
- Then：
  - NAS 在后台、在 A 自己的 VNAS 里开一次规划对话，不需要 A 在线；
  - 项目页显示“VNAS 正在规划”，A 开着桌面时桌面也提示；
  - 云端模型只看到文字（卡片描述、音乐段落、A 的要求），看不到画面；
  - 规划中需要确认的操作一律拒绝，因为没有人能确认；
  - VNAS 交回的规划经校验后收下，任务继续往下走；
  - 规划对话留在 A 的 VNAS 历史里；对话结束后 VNAS 照常复盘，下次规划用得上这次学到的做法。

### 成片存进相册

- When：渲染完成。
- Then：
  - 成片作为一个视频存进 A 的个人图库（位置、名称与拍摄时间按默认规则）；
  - 两个方案都存完后，项目页把方案一、方案二并排显示，各自可以播放、下载，桌面提示“成片已存进相册”；
  - 方案一存完、方案二还在规划或渲染时，项目页已经能播放方案一；
  - 两条成片都等 A 点播放，打开页面时不自动播放；
  - 在剪辑中心或相册里都能播放、下载这条成片；
  - 规划时 VNAS 指出素材里找不到的内容（例如要求里提到、素材里没有的地点），成片页原样列出；
  - 同一个版本重试也只存一次。

### 再生成一版

- When：A 在已有成片的项目里再点“开始”（可以先改歌或要求）。
- Then：
  - 生成新的一版，旧版不覆盖；
  - 相册的分析直接复用；VNAS 重新规划，所以即使什么都没改，也可能得到不同的剪法；
  - 新版失败时，旧版照常可播。

### 取消

- When：任务进行中，A 点“取消”。
- Then：
  - 任务立即不再往下走，正在进行的渲染停止，规划中的 VNAS 回合被中断；
  - 不会存进相册；
  - 之后 VNAS 交来的答案被拒绝。

### 素材进回收站或被删除

- When：任务执行中，A 把一段素材移进回收站。
- Then：任务暂停，项目页写“有 N 个视频在回收站，恢复后继续”；恢复后自动继续。
- When：A 永久删除了一段素材。
- Then：任务停下，列出缺失的视频，由 A 选“去掉这些继续”或“取消”。去掉后素材变了，没存的方案重新规划。已存进相册的方案是定局：版本和成片都不动，也不重做。

### 任务停下等 A 处理

任务停下时，项目页写明原因和 A 能做什么：

| 原因 | A 能做的 |
|---|---|
| 素材缺失 | 去掉这些继续，或取消 |
| 某段素材分析失败 | 重试分析、去掉这段素材继续，或取消 |
| 没有可用的画面 | 取消，追加素材后再生成 |
| 歌曲不可用 | 取消，换一首歌后再生成 |
| VNAS 没有交回规划，或规划连续 3 次不合格 | 重新规划，或取消 |
| 空间不足 | 腾出空间后重试，或取消 |

### VNAS 不可用

- Given：A 没有开启 VNAS、设备上 VNAS 没有密钥，或者 A 的 VNAS 起不来。
- When：A 的任务走到规划。
- Then：
  - 任务停在“等待规划”，项目页与桌面提示写明原因；超过 10 分钟没有接手时写“VNAS 还没有接手”，并给出“重新规划”；
  - 上传、浏览项目、播放已有成片都照常。

### 规划没有交回

- When：VNAS 的这一轮结束了，规划却没有交齐；或者超过默认规则的时限没有交回。
- Then：
  - 项目页显示“VNAS 没有交回规划，重新规划？”；
  - 只有 A 点了才开下一轮，不会自动再次调用模型；
  - 这一轮交回了方案一、没交回方案二时，方案一照常存进相册并显示，A 点“重新规划”后只规划方案二。

### 删除项目

- When：A 删除一个项目。
- Then：
  - 项目、版本记录和规划都删除，相册对剪辑中心的授权撤销；
  - 相册里的原片和成片都保留。
  - 确认对话框写明这一点。

### 两名成员互不可见

- Given：成员 A 与 B 各有项目。
- When：B 请求 A 的项目或任务，或者 B 的 VNAS 调用 A 的任务。
- Then：回答“不存在”，不暴露 A 的项目是否存在。

## 出片后的二次编辑

两条成片出来以后，成员可以确认一版、在成片上改镜头，或者说一句话让 VNAS 重剪（[#596](https://github.com/zhongwater123/A-NAS/issues/596)）。交互照第八版原型的“挑一版与精修”；怎样实现、为什么这样选见 [ADR 0039](../adr/0039-edit-montage-films-as-server-side-drafts-saved-as-new-versions.md)。本节在首版闭环之后实施，分票见 ADR 的“交付”。

### 选版页

- 每一条成片下面有“确认这一版”“修改镜头”，以及一句话的输入框和“重剪”。任何版本，包括更早的和改过的，都可以修改或重剪。
- 每一版显示：
  - 成片播放器，同一时刻只播一条；
  - 镜头缩略图条，每格宽度按槽的长短；
  - 剪辑思路：第一步规划的设计说明，段落名串成一行；“看完整规划”展开设计说明、开头、结尾和各段的名称与概要；
  - 统计：几个镜头、用了几段原片、几个竖拍，有竖拍时标黄；
  - 规划时 VNAS 指出素材里找不到的内容。
- 改过的版本标“改自第 N 版”，重剪的标“按‘<这句话>’重剪自第 N 版”；剪辑思路取它们所来自的规划。
- **确认这一版**：项目列表与主页以这一版为项目的成片，另一条收进“其他版本”。不删除任何成片，另一条由成员在相册里删；可以改选（[决定记录](../decisions/2026-11-19-montage-edit-defaults.md)）。

### 修改页

- **顶栏**：“换一版”（回到两版并排处）、版本名与“精修镜头”、镜头数、“重洗没锁的”“全部还原”“粗预览”“导出镜头清单”“存为新版本”。
- **配乐条**：按音乐段落排开，按段落强度着色（安静、中等、铺垫、高潮），标出每段的起点。
- **镜头区**：按段落分组，每组写段落名与概要，两镜以上时提示“拖动换顺序”。每个镜头一张卡片，宽度按长短：缩略图、镜号、在成片里的时间与长度、景别、段落强度色条，角标“已换”“延长”（删除后被拉长的）“竖”，右下角的锁。
- **点开一镜**：在所在段落下面展开，写“第 N 镜”、强度、起止与长度和“规划要：<画面描述>”；按钮有锁定这一镜、还原这一镜（改过时）、删除这一镜、收起；下面列出同卡片与备用的节拍。没有可换的节拍时，提示去右边搜，并把搜索框填上画面描述。
- **右栏**：上面是搜索框与筛选（景别、场景、只看横拍），下面是试看区。单击一个候选，在试看区播放它会用到的那一段，写“候选”和它的内容，给出“取消”与“替换第 N 镜”；双击候选直接替换。没有候选在看时，试看区播当前这一镜。
- **搜索结果**：写了字时列最像的 3 个，往下滚动看更多；没写字时按拍摄先后列出筛选下的全部节拍。场景按卡片数从多到少列出，后面写个数，最多 8 个，其余并进“其他”。
- **每一步之后**：底部提示做了什么（例如“第 3 镜已替换”“已删除，由前一镜延长补上”“换了 12 个镜头，锁住的 4 个没动”），带“撤销”。

### 修改的规则

- 修改的单位是音乐槽，槽的长度与切点不动。
- 一个节拍在一条成片里只用一次。已经用在别的槽里的节拍照样列出，标“已用在第 N 镜”，不能选。
- 候选只列填得满这个槽的节拍（按放慢的上限算）。手动换镜头可以选竖拍，卡片上标“竖”。
- **换镜头**：候选依次是同一张卡片里还没用到的节拍、规划时为这个画面备选的节拍，再往后是文字搜索全部素材；搜索框默认填这个画面的描述。
- **拖动**：只在同一个段落里；锁定的镜头不动，其他镜头按新顺序依次占没锁的槽。节拍不够新槽的长度时这次拖动不成立，页面说明原因。
- **删除**：不留空，由前一镜或后一镜延长补上；两边都够时选画面更像的一边，两边都不够时拒绝，提示换一个镜头代替。至少留一个镜头。
- **重洗没锁的**：每个没锁的槽按所在画面的描述搜索，从最像的 4 个里随机挑一个；不和前一镜同卡片，横拍的槽不换成竖拍。一个都没锁时先问“还没有锁定镜头，重洗会换掉全部 N 个镜头”，选“先去锁定”或“全部重洗”。
- **还原与撤销**：“还原这一镜”恢复这个版本原来的节拍，“全部还原”恢复整个修改稿；撤销回到上一步。三者本身都是可撤销的一步，最多撤销最近 100 步。
- **修改稿在 NAS 上**：每位成员每个版本一份，刷新页面、换一台电脑都接着改。两个窗口同时改时，后到的那一步不生效，页面重新读取。

### 粗预览

- When：A 在修改页点“粗预览”，或从某一镜开始播。
- Then：
  - 配乐按这一版的选段播放，画面按槽轮流播每个槽用到的原片片段，静音，在槽的切点换下一段；
  - 没改过的槽从成片里那一镜的起点播；改过的槽从所选节拍的起点播一个槽长，与存为新版本后的截取可能稍有出入；
  - 页面写“粗预览，不含放慢、竖拍垫底与淡出”；
  - 改一步就能马上再看，不占后台的渲染；
  - 浏览器不能直接播的原片走相册的转码播放，切点处可能短暂黑屏。

### 存为新版本

- When：A 点“存为新版本”。
- Then：
  - 回到项目页，进度照生成任务的样子显示；
  - 渲染后作为新的版本存进相册，排在最前面，标“改自第 N 版”；原版本与原成片不动；
  - 修改稿保留：不满意就在相册里删掉新成片，接着改；
  - 项目已有任务在跑时，页面写“等这个任务做完”；改修改稿、看粗预览不受影响；
  - 用到的素材缺失或进了回收站时，任务照“素材进回收站或被删除”停下或暂停，页面标出用到它们的槽，A 换掉后再存；没有“去掉这些继续”。

### 说一句话重剪

- When：A 在某一版下面写“结尾留长一点”，点“重剪”。
- Then：
  - VNAS 从这一版的规划出发，只改这句话要求的地方，出一条新成片，标“按‘结尾留长一点’重剪自第 N 版”；素材、歌与起点都和这一版相同；
  - 只出一个方案；占后台规划的一轮，授权照“开始”刷新；
  - 手动改过的镜头不带进重剪，页面写明；
  - 字数上限与“一句话要求”相同，首版不支持的要求照样提示；
  - 换镜头、搜索、重洗、删除、粗预览、存为新版本都不调用模型，不占轮数。

### 导出镜头清单

- 版本与修改稿都能导出，CSV（UTF-8 带 BOM，表格软件直接打开）。每个镜头一行：镜号、音乐槽、成片里的起止、段落、资产 ID、拍摄时间、原片里的起止、放慢倍数、是否改过；删掉的槽写明由哪一镜补上（[决定记录](../decisions/2026-11-19-montage-edit-defaults.md)）。

## 边界与失败

- **成员离线后的访问**：剪辑中心不保存会话。成员离线后，它凭相册持有的项目授权读素材、存成片；相册每次按成员当前的权限重新判断。成员账号停用或看不到某段素材时，任务按“缺失”处理。
- **画面不出设备**：画面只交给本机的 FFmpeg 和本地模型。发给云端的只有文字：用户的要求、卡片描述、拍摄时间等元数据（[#295](https://github.com/zhongwater123/A-NAS/issues/295)）。描述的提示词要求不抄号码；相册再按照片文字的号码规则替换身份证号、银行卡号、手机号与 15 位以上的数字串。车牌、短票号一类不在规则内，只靠提示词约束。
- **助手能看到什么**：助手经相册接口仍看不到视频。剪辑中心的工具只在成员的规划进程里出现，成员平时的 VNAS 和定时任务里都没有；规划进程也没有看图、看视频、文件、终端与相册的工具。只有带着进行中那一轮 token 的调用有效，影响只限本人的任务，读到的也只是本人项目里视频的文字描述。
- **成员的记忆会随规划发出，规划也会写进记忆**：规划对话和成员平时的对话一样，带着成员的记忆与技能；VNAS 用云端模型时，它们连同卡片描述一起发给服务商（[AI 助手规格](ai-assistant.md)）。对话结束后的复盘可能把卡片描述里的文字写进记忆或技能，成员在“记忆”页查看与删除（用户 2026-11-20 接受）。
- **资源**：剪辑分析在相册的 AI 准入里运行，有人在用相册时让路；渲染以低优先级运行，不和正在播放的视频抢 CPU。一组素材的描述在 NAS 上可能要几个小时。
- **存储**：数据卷离线或只读时，剪辑中心整体不可用，不在系统盘建替代目录。渲染或存回相册时空间不足，任务停在“空间不足”，腾出空间后可重试；已有项目与成片照常可看。
- **后台规划的授权**：剪辑中心自己不能让成员的 VNAS 开始规划。成员做默认规则里列出的那几项操作时留下授权，NAS 只在授权有效、还有轮数时发起；账号停用后不再发起。
- **重启**：服务重启后任务从没完成的步骤接着做，已经完成的分析与规划不再重做。
- **二次编辑**：除了重剪，换镜头、搜索、重洗、删除、粗预览与存为新版本都不调用模型，不需要后台规划的授权。搜索在相册里进行，只在本项目的素材里找；分析模型更新后、窗口还没重算时搜不了，页面写“分析模型已更新，重新分析后才能搜索”。删除项目、删除账号时一并删除修改稿。
- **配乐**：选歌时 NAS 复制一份。之后 A 改动或删除音乐库里的原文件，不影响已经选好的项目和进行中的任务；没有项目或版本再用时副本删除（二次编辑要用版本当时的歌）。分析出错时配乐页写明原因，不可用的条件见技术设计的“配乐”。

## 验收证据

证据分五层：
- **单测**：Go 或 Python 单元测试，用替身；
- **契约**：OpenAPI 契约测试；Go 与 Python 之间（领取、简报、答案、填槽请求、选段）还没有共用的样例，见[测试](../development/testing.md#跨进程契约)；
- **系统测试**：`scripts/system-test.sh`，真实安装和 systemd，用替身模型与替身计算 Worker；带真实 Hermes 运行环境时，脚本化模型在规划进程里走一遍规划；
- **开发机**：真实媒体和真实模型；
- **实验 NAS**：真机。

替身只能证明控制流和校验，不能证明模型质量、性能和内存。

### 首版闭环（实验 NAS）

1. 成员 A 在剪辑中心上传品杰一组里的 11 段视频（约 6 分钟，清单与摘要记在 M10 的 PR 里），从音乐库选《Symphony》（10 首测试歌之一，事先放进 A 的“音乐”文件夹），点开始。验收：
   - 视频出现在 A 的个人图库；
   - 点开始后关掉浏览器，任务照样依次经过各步骤，规划在后台自动发起；
   - 生成一条 1920×1080、30 帧、带音乐的成片，时长等于音乐选段，误差不超过 0.1 秒；
   - 成片出现在 A 的个人图库，可以播放和下载。
2. 生成途中刷新页面、关闭再打开窗口，进度从服务端恢复。
3. 生成途中执行 `systemctl restart anas-montage`：任务立即从没完成的步骤接着做，已经完成的分析与规划不再重做。核对方法：相册描述步骤的 AI Worker 调用次数与规划的回合数都不增加。
4. 记录各步骤的耗时与峰值内存，包括相册的分析。#514 不设门槛，这些数字作为以后性能评估的基线。实验 NAS 是 16 GB，峰值要按目标机型 8 GB 的预算比，不能当作够用的证据。

### 媒体与 AI 操作

| 触发 | 预期 | 证据 |
|---|---|---|
| `frames` 的帧数或灰度帧总量超出技术设计里的上限 | 预检回答 `invalid_request`，不启动 FFmpeg | 单测 |
| `frames` 运行中输出超限 | 报错 `too_large`，不截断，不是 `unreadable` | 单测（真实 FFmpeg） |

### 规划（VNAS）

| 触发 | 预期 | 证据 |
|---|---|---|
| 点开始后关掉浏览器，任务走到规划 | 规划发起方在 A 的规划进程里开一次对话，两个方案收下，成片存进相册 | 系统测试（真实运行环境、脚本化模型），实验 NAS（2026-11-20） |
| A 没开启 VNAS 或设备上没有密钥 | 任务停在 `waiting(vnas)`，页面与桌面提示说明原因；上传、浏览、播放可用 | 单测，系统测试 |
| 剪辑中心留了记号，但 A 没有规划授权，或授权过期、轮数用完 | 规划发起方不领取；10 分钟后页面写“VNAS 还没有接手” | 单测 |
| 授权文件不是 root 自己目录里、root 所有且他人不可写的文件 | 不认，不领取 | 单测，系统测试 |
| A 点“重新规划”，或去掉素材、重试分析后要重新规划 | 授权刷新，等待清掉，一分钟内再要一轮 | 单测 |
| 规划进程起不来、登录时连不上、模型网关不应答 | 这一轮作废（`unreachable`），没有调用模型，不计轮数；2、4、8 分钟后再试，之后每 15 分钟；页面写明几分钟后再试 | 单测 |
| 领取后 5 分钟没开始 | 这一轮作废，按连不上处理 | 单测 |
| 规划进程或发起方出错，模型还没调用剪辑工具 | 不计轮数；1 分钟后再试一次，仍出错就 `needs_input(plan_error)`，页面写“规划出错”与错误原文 | 单测 |
| A、B 同时等规划 | 全机同一时间只规划一个，先规划等得最久的；没有授权的成员不挡别人 | 单测 |
| 这一轮已作废或任务已取消，规划发起方才报 `started` | 拒绝；不提交提示词，模型不会被调用 | 单测 |
| 模型调用过剪辑工具后，对话中断、超时或出错 | 计轮数；`needs_input(vnas_unknown)`，不自动再开一轮 | 单测 |
| 距最后一次调用工具 20 分钟，或开始后 65 分钟仍没结束 | 规划发起方中断对话，这一轮结束 | 单测 |
| 同一个 `attemptToken` 交两次，或两份答案同时到 | 只留一份，第二次回答“已收下” | 单测 |
| 不合 Schema 的答案 | 回答 `rejected`（不是 `isError`）；连续 3 次后 `needs_input(plan_invalid)` | 单测 |
| 场景数多于段落的槽位、文字超过上限 | 交之前 Schema 已写明上限；交了也回答 `rejected` 并说明 | 单测 |
| 这一轮交回方案一后结束 | 方案一存进相册；方案二 `needs_input(vnas_unknown)`，不自动发起新的一轮 | 单测 |
| 只交了大纲这一轮就结束 | `needs_input(vnas_unknown)` | 单测 |
| 等规划时重启剪辑服务 | 进行中的一轮不重开 | 单测 |
| 规划中取消 | 之后交来的答案回答“任务已取消” | 单测 |
| B 的 VNAS 调用 A 的任务 | 拒绝（对端 UID 不匹配） | 单测 |
| root 的对端不指明账号，或指明停用的账号 | 拒绝（403、401） | 单测，系统测试 |
| 规划对话 | 标题“剪辑规划 · <项目名>”，留在 A 的 VNAS 历史里；结束后复盘写出技能 | 系统测试（真实运行环境） |
| 规划进程里的工具 | 只有剪辑、记忆与技能，没有看图、看视频、文件与终端 | 系统测试，开发机（决定记录里的实测） |
| A 平时的 VNAS、定时任务、整理单元，沙箱外的进程连剪辑的助手套接字 | 没有绑定，连不上 | 系统测试 |
| 规划中 Hermes 发来审批请求 | 一律拒绝，对话不挂起 | 单测，开发机 |
| 剪辑服务改了提示词模板的版本号或在领取回答里塞文字 | 规划发起方只认已安装的模板、只填检查过的编号与数字，否则这一轮按出错作废 | 单测 |
| 剪辑中心生成的轮次编号与 token | 规划发起方认得（两边各自的测试曾用不同的格式，[调查](../investigations/2026-11-19-montage-job-stalls-on-the-experimental-nas.md)） | 单测（读规划发起方的格式） |

### 任务与校验

| 触发 | 预期 | 证据 |
|---|---|---|
| 计算 Worker 或 FFmpeg 实例被 kill | 这一步重试，最多 3 次；用完后 `failed`，没有永远卡在 `running` 的任务 | 单测（替身），系统测试 |
| 时间线有空槽、越界、引用外部资产 | `failed`，不渲染 | 单测（回归） |
| 渲染中取消 | FFmpeg 实例结束；不存进相册；任务 `cancelled` | 单测，开发机 |
| 已有版本 1，再生成版本 2 失败 | 版本 1 仍可播放 | 单测 |
| 数据卷只读 | 整体回答 `montage_unavailable`；系统盘上不出现剪辑数据 | 系统测试 |
| 渲染或存回相册时空间不足 | `needs_input(storage_full)`；腾出空间后重试，只存一次 | 单测 |
| 成片存进相册后、剪辑中心记下版本前服务崩溃 | 重启后重试存回，相册里不会多出一条成片 | 单测（相册与剪辑中心） |
| 从没有剪辑中心的版本升级，再按系统更新回滚 | 账号、子卷、单元、套接字装好且权限正确；回滚时停掉剪辑服务并恢复 `montage.db` | 系统测试 |
| 同一任务重启或重试 | 输入摘要不变的步骤不重做 | 单测 |
| 规划收下后去掉缺失的素材 | 已收下的规划作废，重新规划；新目录里没有去掉的素材 | 单测 |
| 方案一存进相册后去掉缺失的素材 | 方案一的版本与成片不动、不重存；只重做方案二 | 单测 |
| 升级前开始的任务在升级后继续 | 仍只出一个方案 | 单测 |
| 任务进行中追加素材或改歌 | 进行中的任务照原样做完；下一次生成才用新设置 | 单测 |
| 要求超过默认规则的字数上限 | 400 | 单测 |
