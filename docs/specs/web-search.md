# 网页搜索

状态：draft
更新时间：2026-11-02

## 目标

成员在 A-NAS 桌面上直接搜索互联网，不需要自己安装或配置搜索引擎。NAS 用内置的 SearXNG 把一次查询同时发给多个公网搜索引擎，合并去重后在 A-NAS 自己的窗口中显示。网页搜索随系统安装、默认开启，管理员可以在设置中关闭（[ADR 0030](../adr/0030-ship-web-search-as-a-built-in-searxng-service.md)）。

## 非目标

- 不自建网页索引，不爬取网站；结果只来自随 release 打开的公网搜索引擎。
- 不保存搜索词或搜索历史：服务端不写日志、审计或数据库，浏览器也不保存；关闭窗口后不留下记录。
- 除管理员可以整体打开或关闭“种子”分类外，成员和管理员都不能选择、增减或配置引擎，也不填写任何引擎的 API 密钥；引擎与默认参数随 release 固定。
- 不下载：种子与磁力链接只显示、打开和复制，不交给 NAS 上的下载应用，NAS 也不参与 BT 传输。
- 不按网站过滤结果：不拦截某个网站，也不为某个网站单独接入引擎。
- 不做站内浏览：点击结果在新的浏览器标签页中打开原网页，与应用中心的外部链接相同。本机屏幕能否打开外部网址由本地控制台的浏览器策略决定，不在本规格中处理。
- 不让 VNAS 使用网页搜索；VNAS 是否联网另行决定（[AI 助手规格](ai-assistant.md#非目标)）。
- 不做按成员的内容过滤或家长控制；安全搜索按引擎各自的支持统一取中等。
- 不修改 SearXNG 的代码，也不提供它自带的网页界面；SearXNG 不对局域网或互联网开放。

## 引擎

随 release 加载 SearXNG 自带的全部引擎，只去掉没有它就不能用的（用户 2026-11-02：“能接入的都接上，搜不到是另外的事情”）：

- 需要 API 密钥或令牌的 16 个，例如 Brave API、YouTube API、DeepL、GitHub 代码搜索；
- 只能经 Tor 访问的 2 个（ahmia、torch）；
- 要搜索自建服务的 2 个（Elasticsearch、Torznab）。

清单在 [SearXNG 的设置](../../deploy/search/settings.yml)中。SearXNG 默认不加载（inactive）的引擎也打开。固定的提交 `1cd13d98d` 共有 352 个引擎，加载 332 个。从 NAS 的网络访问不到的引擎照样加载，搜不到时计入“未响应”。各引擎的实测见[引擎实测](../research/web-search-engines.md)。

产品服务从 SearXNG 读取它加载的引擎及其分类，按下表放进窗口的分类。一个引擎可以在几个分类中，例如 YouTube 在“视频”和“音乐”；不属于任何分类的（如菜谱、游戏网站）归入“网页”。

| 分类 | SearXNG 的分类 | 例子 |
|---|---|---|
| 网页 | general、dictionaries、translate、currency、weather、shopping | 百度、搜狗、必应、Google、DuckDuckGo、维基百科 |
| 图片 | images、stock images、icons | 百度图片、必应图片、Unsplash |
| 视频 | videos、movies | 哔哩哔哩、爱奇艺、YouTube、IMDb |
| 资讯 | news | 搜狗微信、新浪、必应资讯 |
| 音乐 | music、lyrics、radio | SoundCloud、Bandcamp、Genius |
| 地图 | map | OpenStreetMap |
| 学术 | science、scientific publications | arXiv、Google Scholar、PubMed |
| IT | it、packages、repos、q&a、software wikis、apps | GitHub、Stack Overflow、PyPI |
| 社交 | social media | Mastodon、Lemmy |
| 种子（默认关闭） | files | 海盗湾、1337x、nyaa、Library Genesis、Z-Library |

每个分类中，中文引擎排在前面，其次是大型通用引擎，其余按名称排列；这也是结果轮流显示的顺序。视频结果标明所在平台（如“哔哩哔哩”“爱奇艺”），点击在该平台打开。种子分类由管理员单独打开（用户 2026-10-30 要求支持，用于测试能力边界）。

## 场景

### 打开并搜索

- Given：网页搜索已开启，成员或管理员已登录。
- When：从桌面、程序坞或“全部应用”打开“网页搜索”，在搜索框中输入关键词并回车。
- Then：窗口顶部是搜索框，打开时光标在框内；下面是“网页”“图片”“视频”“资讯”“音乐”“地图”“学术”“IT”“社交”九个分类（管理员打开种子搜索后多一个“种子”），默认“网页”；窗口放不下时分类可以左右滑动，方向键在分类间移动，回车或点击才搜索。每条网页结果显示标题、网址的域名、摘要、发布日期（引擎给出时）、缩略图（引擎给出且能加载时）和提供结果的引擎；点击标题在新标签页打开原网页（`rel="noopener noreferrer"`），打开过的标题换成另一种颜色。换搜索词或分类后，结果从顶部开始显示。
- And：结果随引擎回答陆续出现（用户 2026-11-02 要求）：搜索开始约一秒后，先显示已经回答的引擎的结果；其余引擎回答后，它们的结果接在已有结果之后，已显示的结果不移动。在第一条结果出现之前，结果的位置显示与该分类布局相同的灰色占位。结果上方一行写已有的结果数和“还有 N 个引擎在搜索”，例如“36 条结果 · 还有 12 个引擎在搜索”；引擎都回答或超时后只写结果数，这时才出现“更多结果”。
- And：同一批回答的引擎按分类中的顺序轮流排列：依次各给出一条自己的下一条结果（A→B→C→A），每个引擎的结果保持它自己的顺序，结果少的引擎用完后，其余引擎继续轮流。一条结果由几个引擎找到时只显示一次，来源列出所有找到它的引擎；后回答的引擎找到已显示的结果时，只把它加进来源。
- And：引擎给出的答案（如计算结果）显示在结果上方。信息框（如百科简介）在窗口足够宽时显示在结果右侧，否则显示在结果上方；它写出来源网站，点击在新标签页打开。相关搜索在结果末尾分两列排列，点击即用它重新搜索。结果末尾的“更多结果”把下一页接在后面，最多 20 页；每页之前写“第 N 页”。
- And：2026-11-03 用户要求对网页搜索做 UI、UE、UX 的设计优化，“可以自主设计优雅的设计方案”；本节和下面各分类的布局是那次优化的结果。

### 其他分类

- Given：已有一次搜索。
- When：切换到其他分类。
- Then：用搜索框中当前的关键词（未按回车也算）在该分类中搜索。
  - “图片”按图片原有的宽高比排成等高的行，每行铺满窗口宽度；悬停显示尺寸和来源域名，点击在新标签页打开来源页面。
  - “视频”每条显示封面、标题、时长与来源。
  - “资讯”可以限定“一天内”“一周内”“一月内”“一年内”，不支持时间范围的引擎此时不参与。
  - “音乐”每首显示封面、歌名、歌手或上传者、平台与时长。
  - 学术论文显示作者（多于三人时写前三人和总人数）、期刊或出版者、日期，有 PDF 或 DOI 时给出链接。
  - 软件包与代码仓库显示版本、维护者、许可证、热度（站点给出的星数、下载数等）和更新日期，有主页或源代码地址时给出链接。
  - 地点显示地址和经纬度。
  - 其余结果与“网页”的列表相同。这些细节取自 SearXNG 给结果选定的布局（论文、软件包、地图），不按分类区分。
- And：缩略图与封面经 NAS 代取，浏览器只向 A-NAS 自己请求图片。图片分类中加载失败的图片直接去掉，不留空位；列表中的缩略图加载失败时让出位置给文字；视频与音乐的封面加载失败时显示带播放或音符标记的占位。

### 种子

- Given：管理员已打开种子搜索，已有一次搜索。
- When：切换到“种子”。
- Then：每条结果显示名称、大小、做种数与下载数、发布日期和来源站点；“复制磁力链接”把磁力链接复制到剪贴板，点击名称用本机关联的下载程序打开磁力链接，来源站点在新标签页打开详情页。文件站（如电子书站）的结果没有磁力链接，只显示名称与来源站点。
- And：管理员关闭种子搜索后，“种子”分类从所有窗口消失，正在显示的种子结果被清空。

### 部分引擎未响应

- Given：一次搜索中，有的引擎超时、出错或要求验证码。
- When：其他引擎返回了结果。
- Then：结果照常显示。结果上方那一行的右侧写“N 个引擎没有回答”，点开按原因列出引擎：“未响应”“被网站拦截，暂停中”（每个写出恢复时间）、“搜索太频繁，本次跳过”。
- And：引擎要求验证码时，A-NAS 不尝试绕过，而是暂停这个引擎（见“像人一样搜索”）。

### 像人一样搜索

全家共用一个公网地址。搜索网站发现这个地址搜得比人快，或者被拦下后还在搜，就会封它，家里手机、电脑直接上这些网站时也会遇到验证码。用户 2026-11-02 要求“不希望 IP 被封，策略要更像人搜的”。所以产品服务按一个人在键盘前搜索的样子询问每个引擎：

- Given：家里有人在搜索。
- When：同一个引擎在短时间内被问到（不论是哪个账号、搜什么）。
- Then：每个引擎可以连续被问 3 次，像人修改搜索词那样；之后每 10 秒一次，等过的请求再随机晚 0～3 秒发出。轮不到的引擎排队，结果晚几秒出现；要等 20 秒以上的，这次不问它，计入“没有回答”，点开列在“搜索太频繁，本次跳过”下。
- And：窗口里改了搜索词或关闭窗口，还在排队的请求不再发出，把轮次让给后面的搜索。
- When：引擎的网站要求验证码、拒绝访问、说请求过多，或者返回引擎无法识别的页面（常是它不认识的验证页）。
- Then：产品服务暂停这个引擎 1 小时，此后连续被拦每次加倍，最长 1 天；它再次正常回答后，记录清零。暂停期间所有搜索都不问它，计入“没有回答”，点开列在“被网站拦截，暂停中”下，并写出恢复时间。暂停记在产品服务的状态中，重启后仍然有效。
- When：点“更多结果”。
- Then：只问上一页有结果、而且能翻页的引擎；人只会在有结果的地方翻页。
- When：同一个账号 10 分钟内再次搜索同一页（重试、返回）。
- Then：已经回答过的引擎直接用它的回答，只问没有回答的引擎。这些回答不在账号之间共用：结果出现的快慢会让一个人知道另一个人搜过什么。
- And：搜索词里的“!百度”“:en”“<3”等写法按普通文字搜索，不当作 SearXNG 的指令；否则“!bd 天气”会让每个引擎的请求都变成问百度，百度一次收到约 100 个相同的请求。

### 搜索中断

- Given：结果正在陆续出现。
- When：与 NAS 的连接中断。
- Then：已经显示的结果保留，下面写“搜索中断，请重试”和“重试”；重试重新搜索这一页，替换它已有的结果。

### 没有结果

- When：所有引擎都已响应但没有结果。
- Then：显示“没有找到与“<关键词>”相关的结果”。部分引擎没有回答时，下面写“N 个引擎没有回答”（可点开）和“重试”。
- When：所有引擎都未响应（例如 NAS 无法访问外网）。
- Then：显示“搜索引擎都没有响应，请稍后再试”和“重试”，不显示为“没有结果”。
- When：没有回答的引擎中有暂停或本次跳过的。
- Then：显示“搜索引擎暂时不可用，请稍后再试”和“重试”。

### 搜索太频繁

- Given：一个账号刚连续搜索了 10 次。
- When：再次搜索。
- Then：显示“搜索太频繁，请稍后再试”，不向引擎发出请求。这个上限按账号计算，保护产品服务与搜索服务；对每个引擎的节奏另见“像人一样搜索”。

### 设置中的网页搜索

- Given：管理员已登录。
- When：打开“设置 → 网页搜索”。
- Then：显示开关“网页搜索”及其状态（运行中、已停止、启动中），一行说明“搜索请求从这台 NAS 发往下列搜索引擎”和各分类的引擎数量，点开列出名单（只读；搜索服务运行后才能读到），以及“开源许可”：SearXNG 的名称、版本、AGPL-3.0 许可证全文与这一版本的源码下载，源码由 NAS 自己提供。
- And：下面是第二个开关“种子搜索”，默认关闭，网页搜索关闭时不可操作；旁边一行写明“种子与文件站的结果多为未经授权的内容”。
- And：网页搜索开启时，“暂停的引擎”列出被网站拦截而暂停的引擎、拦截方式与恢复时间，例如“百度 / 要求验证码，今天 15:30 恢复”；没有时写“没有被网站拦截的引擎”。管理员由此能看出出口地址是否已被搜索网站标记。
- And：成员的设置中没有这一分区。

### 管理员关闭网页搜索

- Given：管理员在“设置 → 网页搜索”中。
- When：关闭开关。
- Then：NAS 停止搜索服务，此后不再访问任何搜索引擎；所有账号的桌面、程序坞与“全部应用”中不再出现“网页搜索”；已打开的窗口显示“管理员已关闭网页搜索”。重新打开开关后，图标与搜索恢复。
- And：开关在升级与重启后保持。

### 搜索服务暂时不可用

- Given：网页搜索已开启，但搜索服务正在启动、已崩溃或正在重启。
- When：成员搜索。
- Then：显示“网页搜索暂时不可用，请稍后再试”和“重试”；systemd 会自动重启服务。

## 边界与失败

- 只有已登录的账号能搜索，未登录返回 401；成员与管理员的能力相同。搜索服务只经产品服务访问：它只监听一个只有产品服务能连接的 Unix 套接字，没有 TCP 端口。
- 搜索词放在请求体中，从浏览器到产品服务、再到搜索服务都不进入 URL，因此不会出现在 Caddy、产品服务或浏览器的访问记录中。产品服务不记录搜索词，不写审计；搜索服务关闭查询日志与访问日志。
- 没人搜索时搜索服务不访问外网。引擎中只有 Radio Browser 在启动时用 DNS 查一次它的服务器；插件只加载计算器、单位换算、时区与哈希，不加载启动时下载规则的跟踪参数清除插件。
- 每个账号最多连续搜索 10 次，之后每 2 秒一次，超过返回 429 和 `Retry-After`；被拒绝的搜索（无效、关闭、种子未开）不占次数。单个引擎 5 秒超时，最长 10 秒（SearXNG 的设置），产品服务等一个引擎最多 12 秒，超时的引擎计入“未响应”。SearXNG 要等它被问到的全部引擎回答后才返回，所以产品服务把分类中的每个引擎各作为一个请求同时发给 SearXNG（网页约 100 个），哪个先回答就先显示哪个；超时或连不上的引擎之后 5 分钟不再询问（SearXNG 自己的暂停，只在内存中）。
- 每个搜索网站只看到发给它自己的请求，所以接入全部引擎不会让任何一个网站看到异常的流量；要管的是每个网站各自收到的节奏，见“像人一样搜索”。SearXNG 发出的请求在加密握手和请求头上模仿 Chrome（curl_cffi），不保留 cookie；它对发出的请求不限速，所以节奏由产品服务控制。产品服务按 SearXNG 用英文给出的未响应原因判断拦截（`settings.yml` 固定 SearXNG 的界面语言为英文）。
- 引擎的暂停记录在 `web-search.db`；搜索结果只在产品服务内存中按账号保留 10 分钟、最多 32 次搜索，不写磁盘。
- 搜索服务只能连接公网地址：本机、局域网、链路本地与其他保留地址都被拒绝，只放行设备当前使用的 DNS 服务器。这样它不能被结果中的地址利用来访问家里或公司内网的设备；系统测试证明这一点。
- 缩略图代取只接受带 SearXNG 签名的地址，只返回图片类型，单张大小有上限；桌面的内容安全策略不为外部图片放开。签名是用安装时生成的密钥对图片地址做的 HMAC，不随搜索变化也不过期：签名只防止把代取当作任意地址的转发，不限制成员再次取一张见过的图片。远端拒绝或找不到的图片返回 404，前端按上文去掉该图或显示占位。
- 结果中的标题、摘要与网址一律按纯文本显示；只有 `http`、`https` 地址显示为链接，“种子”分类另外允许 `magnet:` 链接。信息框的内容在 SearXNG 中是 HTML（如 Jisho 词典的释义列表），产品服务只取其中的文字，每段或每个列表项一行。
- 种子搜索的开关由产品服务执行并保存在产品服务的状态中：关闭时产品服务不向搜索服务请求这一分类，种子请求返回 403 和 `torrent_search_disabled`。
- 管理员关闭后，搜索与缩略图接口都返回 403 和 `web_search_disabled`，搜索服务处于停止状态；打开开关时由 Host Agent 启动服务。
- 网页搜索与 SearXNG 的设置都由安装器生成且只读，升级时重写；只有两个开关的状态跨版本保留。

## 验收证据

- 产品服务：对 Fake SearXNG 的接口测试，覆盖结果映射（含种子的大小、做种数与磁力链接）、部分引擎未响应、全部未响应、超时、限流、两个开关的关闭状态与未登录。
- Web：搜索、分类切换（含方向键）、翻页与分页标记、没有回答的引擎按原因列出、空结果与重试、论文/软件包/地点/音乐的细节、加载失败的图片不留空位、种子分类的显示与消失、关闭状态与图标隐藏的组件测试。
- 系统测试：搜索服务只有产品服务能连接；它无法连接回环、局域网与保留地址；DNS 服务器变化后允许列表随之更新；关闭开关后服务停止，升级后仍关闭；搜索服务无法启动时升级照常完成并给出提示。部署前用 `ANAS_SYSTEM_TEST_SEARCH=real` 跑一次，让真正的 SearXNG 在单元的沙箱中启动，核对加载的引擎与插件、启动后空闲时没有 IP 流量、日志中没有错误。
- 产品服务：分类与 SearXNG 分类的对应、引擎读取与失败后的保留、结果的轮流排列，论文、软件包、地点与音乐的细节，见领域测试。
- 产品服务：搜索词中的 SearXNG 指令按文字搜索；每个引擎的节奏（不论账号）、等不到轮次的跳过、离开的搜索让出轮次；同一页再搜只问没回答的引擎、不跨账号；翻页只问上一页有结果的引擎；被拦截的暂停、加倍、重启后保留与回答后清零，见[节奏测试](../../internal/websearch/pace_test.go)。
- 实验 NAS：搜索服务能连接公网（门禁不访问外网，只在这里验证）；在 NAS 的实际网络下逐个测量候选引擎的成功率与耗时，结果写入研究记录，作为默认引擎列表的依据。
