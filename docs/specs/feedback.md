# 问题反馈

状态：implemented
更新时间：2026-10-12

## 目标

家庭成员在桌面上随时记下遇到的问题或建议，附上文字、图片或当前界面的截图；所有人看到同一份清单，谁都可以补充、修改，处理完的条目划线保留。

## 非目标

- 不做工单系统：没有指派、优先级、分类、评论串、通知或邮件。
- 不向开发者或任何外部服务发送反馈，只保存在本机。
- 不按账号区分权限：成员与管理员对每条反馈的读写能力相同，也不记录修改历史，只保留最近一次编辑者。
- 不调用浏览器的屏幕录制接口；“截取界面”只截取 A-NAS 桌面本身。
- 不进入审计、备份或数据卷；反馈与其图片随产品服务状态存放在系统盘。

## 结构

桌面右侧边缘有一个与快捷栏、程序坞同为深色玻璃的竖向标签，橙色图标下写“反馈”，有待处理条目时在角上显示数量。标签可以上下拖动避开窗口内容，位置保存在当前浏览器（`localStorage` 键 `a-nas.feedback.button-top`），并始终保持在状态栏下方、离屏幕底边一段距离。

点击标签后，桌面右侧浮出“问题反馈”面板，桌面和窗口仍可操作。面板自上而下是撰写框、“待处理 / 已处理 / 全部”三个带数量的筛选，以及可滚动的反馈清单。面板浮在窗口和程序坞之上；Esc（焦点在面板内时）或右上角关闭按钮收起面板，焦点回到标签。

## 场景

### 写一条带截图的反馈

- Given：用户在某个窗口里遇到问题，并打开了反馈面板。
- When：写下描述，点“截取界面”，再按 Ctrl+Enter 或点“提交”。
- Then：屏幕闪一下，撰写框出现一张整个桌面的截图缩略图，截图中没有反馈标签、面板和图片查看器。提交后新条目出现在“待处理”最上方，撰写框清空；作者和时间显示在条目下方。

### 粘贴、拖入或选择图片

- Given：用户用系统截图工具截好图，或电脑里已有图片。
- When：在撰写框中粘贴、把图片拖到撰写框上，或点“添加图片”选择。
- Then：图片加入撰写框，可单击放大，悬停后可移除。剪贴板同时带文字时文字照常粘贴。只接受 PNG、JPEG、GIF 和 WebP，每张不超过 10 MB，每条最多 6 张；超出时撰写框说明原因，不加入。只写文字或只放图片都可以提交，两者都没有时“提交”不可用。

### 草稿在收起面板后保留

- Given：撰写框里有文字或图片尚未提交。
- When：收起面板去操作窗口，再重新打开。
- Then：草稿原样保留；退出登录后丢弃。

### 标记已处理

- Given：清单中有一条待处理反馈。
- When：任意账号点条目左侧的圆形勾选框。
- Then：勾选框变绿，正文从左到右划线并变淡，图片变灰，条目下方显示“某人 已处理”。条目留在当前视图直到切换筛选或收起面板，之后归入“已处理”。再次点击恢复为待处理并清除处理人。

### 编辑他人的反馈

- Given：清单中有别人写的反馈。
- When：悬停条目，点编辑（铅笔），修改文字、移除或添加图片后保存。
- Then：条目更新，下方显示“已编辑”，悬停可见编辑人和时间。编辑时 Esc 或“取消”放弃修改。

### 两人同时编辑

- Given：A 和 B 同时打开了同一条反馈的编辑框，B 先保存。
- When：A 保存。
- Then：A 的保存被拒绝，编辑框上方提示“B 刚刚修改了这条反馈”并引用 B 的文字；A 的草稿保留，B 新加的图片出现在编辑框中。A 再次保存时以 A 的版本为准。

### 删除

- Given：清单中有一条反馈。
- When：悬停后点删除（垃圾桶）。
- Then：条目内出现确认条“删除后所有人都看不到这条反馈”，确认后条目及其图片被删除；取消则不变。

### 查看图片

- When：点清单或撰写框中的缩略图。
- Then：图片在全屏查看器中按比例显示，多张时可用左右方向键或两侧按钮切换；Esc、关闭按钮或点背景关闭查看器，反馈面板保持打开。

## 边界与失败

- 读写都要求有效会话，写操作要求 CSRF 令牌；所有有效账号读写同一份清单。被管理员重置密码的成员在自行改密前无法访问。
- 文字去掉首尾空白后最多 5000 字。图片类型由服务端按文件内容判定，扩展名和声明的类型不算数；SVG、HTML 等可能带脚本的格式一律拒绝。图片以判定的类型返回，并带 `X-Content-Type-Options: nosniff` 与 `sandbox` 内容安全策略。
- 编辑以读取时的版本号提交，版本不一致时返回 `409 feedback_changed`；标记已处理不改变版本，不会让别人正在进行的编辑失效。重复标记已处理时保留第一次的处理人。
- 条目或图片已被删除时返回 `404`，面板把它从清单中移除。
- 面板打开时每 15 秒刷新清单，收起时每 60 秒刷新待处理数量。刷新失败时保留已显示的清单；首次读取失败时显示“无法读取反馈”和重试按钮。
- “截取界面”在浏览器中把桌面页面绘制成 WebP，分辨率按屏幕像素比（最多 2 倍）；局域网入口是明文 HTTP，浏览器不允许那里使用屏幕录制接口。截图失败时提示改用系统截图后粘贴。截图库在第一次截图时才加载。
- 打开面板时光标落在撰写框，但不滚动桌面：窗口超出屏幕时桌面本身可以被滚动，滚动后整个桌面会错位。
- 系统偏好减少动态效果时取消面板、条目与查看器的动画和截图闪光，划线直接出现。
- 反馈保存在产品服务状态目录的 `feedback.db`（SQLite），图片随条目存放在同一数据库；删除条目同时删除图片并回收空间。

## 验收证据

- Go 测试：[反馈存储测试](../../internal/feedback/feedback_test.go) 覆盖多账号编辑、版本冲突、已处理与重开、删除连带图片、内容校验与按时间排序；[产品 API 测试](../../internal/httpapi/feedback_test.go) 覆盖未登录拒绝、缺少 CSRF 拒绝、成员与管理员读写同一条目、图片响应头、过期编辑与 SVG 拒绝；[OpenAPI 契约测试](../../internal/httpapi/openapi_test.go) 覆盖全部路由的请求与响应。
- React 行为测试：[反馈面板测试](../../web/src/feedback/FeedbackChannel.test.tsx) 覆盖待处理数量、筛选、粘贴与截图后提交、草稿保留、勾选划线并停留、编辑冲突后重新保存、确认删除、图片查看器与时间描述。
- 浏览器检查：Fake 模式预览中检查右侧标签、拖动定位、面板、勾选划线、编辑、删除确认、图片查看器，以及打开文件管理窗口后“截取界面”得到的截图不含反馈面板。
