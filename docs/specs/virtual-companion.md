# 虚拟伙伴

状态：prototype（奶蛙、主动捉迷藏送花、任务情绪反馈、网页小窝/电脑桌宠与成员状态接续；触屏 deferred）

更新时间：2026-11-03

## 目标

成员可以在伙伴小窝或桌面与同一个实验角色互动；奶蛙会主动藏起来露出脑袋，成员找到它后收到小花，也可以轻点打招呼、拖动放下、选择安静、隐藏与叫回。形象层固定使用社区奶蛙精灵图验证功能；旧实验形象配置保持可读，界面暂不提供切换。素材来源、摘要与使用边界见[素材说明](../../web/src/companion/assets/NOTICE.md)。

## 当前范围

- Web 桌面增加“伙伴小窝”，复用已有账号登录、启动器和窗口；小窝可将角色叫到当前网页角落，或叫回。
- 角色基础动画在本地运行，点击与物理反馈不调用模型；互动收敛为主动捉迷藏与送花，不再提供抛接球、动作跟拍和呼吸游戏菜单；支持键盘与减少动效。
- NAS 在 `companion.db` 中按登录成员保存形象、安静偏好、累计玩球次数、当前互动端和一个 VNAS 存储对话 ID。接口没有可选成员参数，不复制对话内容，也不执行文件或模型操作。
- 电脑桌宠通过 Electron 透明窗口运行，提供托盘、隐藏、显示、屏幕归位与窗口拖动；离线实验室复用网页的交互代码。
- 配置 NAS 地址后加载已部署本功能的 Web 页面。桌面端自行通过原有登录页认证，沿用自身会话；不复制系统浏览器 Cookie。打开“小窝”由同一 Electron 会话中的网页申请接续。
- 出现位置仍按客户端保存；角色形象、安静偏好和玩球次数跟随成员。网页小窝与同一页面的悬浮角色共享一个客户端身份，不互相争抢。

## 主动互动与明确情绪

页面只保留“陪我一下”，不要求成员挑一个小游戏。奶蛙在当前可见、可互动、空闲的页面中待十二秒后主动躲到纸箱后、露出脑袋：“我躲起来啦，找找我？”点小脑袋后它跳出来开心地送花；点花收下，给出回应后自然恢复陪伴。也可以随时说“我先忙啦”。一次停留只主动邀请一次，二十秒没有回应就回去安静待着；不因拒绝、离开或没有回应而难过。任务处理中和安静模式不主动邀请。当前十二秒是内部快速试玩参数。

| 触发原因 | 表现与当场说明 | 下一步 |
| --- | --- | --- |
| 找到奶蛙、收下花、回应击掌或挠痒痒 | 开心，并直接说出原因 | 短暂庆祝后恢复陪伴 |
| VNAS 协议报告本轮回答结束 | “开心 · 这轮回答完成啦” | 看结果；不等同于文件保存 |
| VNAS 报告任务出错 | “有点失落 · 这次任务没完成” | 成员摸摸它时回应安慰，6.5 秒后恢复平静 |
| VNAS 等待确认 | 期待地等成员决定 | 打开原 VNAS 确认卡，不自动决定 |
| 忙、无回应、安静、隐藏 | 平静地退回陪伴 | 不扣分、不催促、不制造内疚 |

情绪不是随机切换。真实联动仅消费当前成员已绑定对话的 VNAS 状态、网关事件和确认卡。流式文字、未结束回复、过程发言和被新用户消息取代的旧回答不能触发成功；刷新历史不重播庆祝。未来本地 AI 遵循同一任务协议即可复用；理解对话语境后选择安慰或庆祝的结构化反馈仍待接入。

隐藏、后台、安静或失去互动租约会结束当前小游戏并清理定时器。游戏与花只在本次本地互动中呈现，不写入旧版玩球计数，也不跨端复制逐帧动作；现有 SQLite 活动记录保持兼容。原生桌宠、网页小窝与网页角落使用同一逻辑。触屏和形象重做继续延后。

## Personal agent：任务输入与主动回报

奶蛙是成员自己的助手入口。小窝以“有事交给我”为主入口，接现有 VNAS 对话、定时任务与未读结果，小游戏保留为非任务时的补充。当前新增的是产品入口与通知展示；真实模型经 Hermes 安排、唤醒并带回结果仍需运行时联调，不能由模型直连测试或前端协议测试替代。

1. **交代事情**：输入“明早十点提醒我交材料”等请求，先保存对话引用，再交给现有 VNAS；不可互动、断线、运行中或有待确认卡时不能另发。示例只填入交代框，成员点“交给奶蛙”才发送。提示要求定时任务使用现有 `cronjob`，核对 NAS 日期、时间与时区；“我的提醒与后台任务”直接读取服务端实际任务，支持原有的暂停、继续、立即运行与删除。下一次运行显示完整日期、时间和当前设备时区，模型口述“安排好了”不新增任务卡。
2. **交代工作并回来报结果**：例如“今晚整理这份会议记录，明早给我摘要”。复用原 VNAS 实例和确认卡，通知区分完成、失败、等待决定；结果必须有可打开的运行记录或文件。电脑关掉时由在线 NAS 处理，桌宠下次在线补看未读结果，不承诺电脑关闭时仍能在电脑上弹出提醒。
3. **有边界的主动发现**：指定文件夹上传完成等事件在成员授权范围内触发；不以模型反复轮询作为定时器。这部分需新增事件 Adapter，现有代码不等于已经支持。

后台结果复用成员的 `assistant_task` 通知。小窝列出最近三项，悬浮与原生桌宠显示最近一项；每分钟读取一次，页面恢复可见时补读。新通知的 `ok` 状态触发“有新结果”的开心反馈，失败触发明确原因的失落反馈，持续约 6.5 秒；首次载入的历史未读结果保留卡片但不重播庆祝。忙、安静或伙伴在别端时不主动播报。刷新与重复读取不执行任务，未读结果仍保存在 NAS。

“查看结果”打开原 VNAS 运行记录，由原窗口记录已读；“知道了”只在服务端接受回执后清除通知，失败则保留卡片供重试，不代表用户已交材料等事项完成。小窝的“十分钟后再提醒”先填入新交代并明确要求发送，原结果保持未读；经 VNAS 实际保存后才算新提醒，不重跑原任务或改其重复计划。桌宠紧凑视图只提供查看和已读，重新安排从小窝发起。

通知缓存按成员隔离，换账号清空；旧账号的迟到读取和已读回执不改变新账号的显示。定时任务、NAS 唤醒和每成员运行记录沿用现有助手，不另起一套 Agent。外部网页、邮箱、日历等连接器需另行设计，现有助手规格限制不能默认为已放开。

说话气泡已和角色共享移动容器，拖动、滑行及主动移动时一起走；文字变化和场景边缘会重新计算位置，上方不足时放到下方。原生透明窗口高度扩为 400 像素，为气泡与任务状态留出空间；完整对话和任务记录仍在 NAS 页面展开。

### 云端试验与本地目标

云端阶段使用用户已有的 Qwen 兼容 API，通过既有沙箱外模型网关接入；后续本地服务沿用同一 `/v1` 契约，调度、成员任务、确认卡、通知及奶蛙交互独立于模型。接入配置包含完整 Base URL、模型 ID、独立凭据与已验证能力参数，不能把“兼容 API”当成工具执行可靠性的证明。

当前网关已支持路径前缀和回环本地无密钥模式，合成服务测试覆盖两条路线；Qwen 两款模型的 SDK 合成协议检查与运行时验收边界见[接入检查](../research/qwen-companion-capability-check.md)。4B 和后续较大模型均用同一组合成任务验证，默认本地失败不自动回退到云端。具体配置与检查见[云端联调与本地接入](../runbooks/try-ai-assistant-on-experimental-nas.md#qwen-云端联调与后续本地接入)。

## 接续规则

### 小窝 → 桌宠 → 小窝

打开 Web 小窝只观察，不抢占其他端。成员点“叫到这里”后才申请互动；电脑桌宠启动并登录后申请一次，后续通过按钮叫回。“到网页桌面陪我”只切换当前网页内的位置。

其他端在线时，新端显示“正在过来”，保持不可互动；旧端读到申请后先停止本地互动，再向 NAS 确认交接。NAS 原子地递增活动代次并授予新端；旧代次的玩球、续期和交接都被拒绝。桌宠“回小窝”打开或刷新小窝窗口，由小窝申请接续，旧端按同一规则交接。

旧端离线或页面隐藏、来不及确认时，新端等待其 15 秒租约到期后重新申请。不是点击后立即在两端同时激活。客户端按请求发出时刻计算保守截止时间，不使用跨设备的墙上时钟，也不因慢响应额外延长互动；即使读取挂起，到期后也会停下。

### 进度与冲突

申请携带状态版本，过期版本返回冲突；写操作携带当前代次和唯一事件 ID。最近 256 个事件内的同内容重试不会重复累计，复用事件 ID 改内容会被拒绝。客户端不自动重放离线玩球。

断线时显示暂停，可主动选“先在本地玩”，该模式的次数与偏好不写入共享状态。连接恢复后需点“叫到这里”退出本地模式。旧版 NAS 或未启用状态存储的测试实例显示接续不可用，不能把本地偏好当作 NAS 同步。

### 退出与恢复

退出账号卸载小窝与悬浮角色，取消请求和排队中的写操作；再次登录按成员读取 NAS 状态。页面隐藏时停止轮询和互动，重新可见时恢复读取。服务端不靠浏览器关闭通知维持正确性，失去响应的旧端最终通过租约失效。

## 第一条任务流程：NAS 文本会议纪要

- 小窝列出本人个人空间与共享空间，排除管理员查看的其他成员空间；选择 32 KiB 以内的 `.txt` / `.md`。路径按 NAS 挂载名称构造并作为 JSON 引用，交给既有 VNAS `read_file` 读取，浏览器不另传文件内容。
- 通过既有 `useAssistantGateway` / `useAssistantThread` 创建或恢复对话，先用当前互动代次把存储 ID 记入 `companion.db`，成功后才 `prompt.submit`。保存失败或窗口退出不继续排队提交。只复用现有成员的 Hermes 实例、会话与工具规则，不另起一个 Agent。
- 首轮整理摘要与待办，不提交个人文件更改。点“保存到个人空间”继续同一对话，请 VNAS 走 `submit_changes`；这只是提交确认请求，用户仍须在原 VNAS 确认卡决定。桌宠不调用确认接口。
- 任务表现从真实连接、线程和确认卡记录推导：连接中、思考、处理、等待决定、回答结束、失败、停止。回答结束只代表本轮回答结束；“已确认保存”只采纳 `approval.status=applied` 且 `change.status=applied` 的写入、复制与移动记录，不采纳模型口述的文件路径。
- 已确认的个人空间文本文件可通过已有文件列表定位真实文件 ID，再使用认证的文本预览接口读取（预览上限 256 KiB）；其他位置与大文件回原 VNAS 或文件管理查看。此处不把模型输出转成下载 URL。
- 原生桌宠和网页悬浮入口显示任务状态并可停止已运行回答。原生桌宠“交代事情”打开小窝，确认与完整交互进入同一个 VNAS 对话。原生 IPC 仅接受正常存储对话 ID，导航保持同一 NAS origin。
- 接续只共享对话引用；每端恢复同一对话及确认记录。互动租约到期不会取消后台任务；任务生命周期遵循现有 VNAS 成员实例规则，不承诺成员退出后无限后台运行。断线时停止新提交，重连恢复结果，不自动重放 prompt。
- 本次 SQLite 迁移为版本 1，旧活动次数、偏好、代次和事件去重记录保留。新字段不赋予任何对话读取权限；实际访问继续由既有助手成员鉴权校验。

## 非目标与待办

- **触屏待办**：现有硬件暂不支持；触控手势、公共与个人模式、共享屏幕身份确认及触屏实机验收均不在当前交付范围。
- 当前接续的是小型活动状态，不保存游戏的逐帧坐标、桌面布局、聊天记忆或物件库存。
- 当前有通用文字交代与文本纪要模板；语音按住说话、统一 TTS、长时专注陪伴、关系记忆、照片纪念卡和共同小作品后续接入。
- 系统其他应用的全屏自动避让、混合 DPI、多显示器连续甩抛与 Windows 原生验收待做。当前可从托盘主动隐藏；显示器变化时归位。
- 不后台读取其他应用、连续截屏、常开麦克风或自动访问用户资料；没有登录自启或自动部署操作。

## 验证与交付边界

- 新一轮专项覆盖主动邀请、发现与收花、无回应不失落、不重复催促、安静/任务抢占、明确任务情绪、历史不重播与键盘互动。玩法改为主动捉迷藏后，旧版游戏菜单与规则已经删除。
- 当前检查结果见[当前状态](../status/CURRENT.md)。前端专项覆盖自然语言交代、示例不自动发送、模型口述不伪造已保存任务、结果已读失败保留、历史不重复庆祝和跨成员迟到请求隔离。typecheck、lint、生产与离线桌宠构建及 docs-check 的记录在本地构建目录。前一轮浏览器实际走通了主动躲藏、找到后送花、收下花；新增提醒入口与真实模型、跨端原生、真实 NAS 仍需按运行手册验收。
- 接续控制器覆盖旧端停下再交接、候选端等待与到期、慢响应、旧版本、退出期间的请求和断线不重放。领域存储通过 race 测试验证并发申请、成员隔离、事件去重与重启持久化；五个 HTTP 操作均做契约校验。
- `smoke:handoff` 用真实临时 SQLite 与领域 API、两个独立 Chromium 上下文验证双向接续、共享偏好与进度、断网后本地玩不回写。它使用固定的合成测试成员，不验证产品登录或 CSRF；完整产品路由的鉴权测试单独放在 `internal/httpapi/companion_test.go`，需要 Linux 开发环境运行。
- `smoke` 检查本机离线 Electron 桌宠与小窝、透明窗口尺寸、隔离配置和基本交互；不能替代已登录 NAS 的 Electron 实机验收。
- `smoke:tasks` 使用真实伙伴 SQLite/API、React 组件、Hermes JS 客户端及原 VNAS 确认卡 UI，验证选文件→草稿→等待→桌宠接续→手动确认→预览→刷新不重复提交。模型运行时、文件 API、确认执行器与成员鉴权为模拟；它不是真实 NAS 文件落盘或模型效果验收。
- 本机前端 typecheck/lint/build、相关 74 项前端测试、伙伴 Go race 与离线原生烟测通过；原型快照完整 Web 602 项通过，音乐菜单测试现等待真实表格行。macOS 无法运行 Linux-only 产品门禁；PR 使用 Ubuntu x86_64 的完整检查、race、Debian systemd 系统测试和专门的伙伴协议验证，结果以对应提交的 CI 为准。
- 完整 Linux 门禁、真实 NAS 登录/退出/会话失效、真实模型与保存执行器、Windows 与多屏验收仍待做；部署事实以[当前状态](../status/CURRENT.md)为准。
