# 虚拟伙伴

状态：prototype（奶蛙、多回合陪伴玩法、任务情绪反馈、网页小窝/电脑桌宠与成员状态接续；触屏 deferred）

更新时间：2026-11-02

## 目标

成员可以在伙伴小窝或桌面逗玩同一个实验角色，轻点打招呼、按住拖动、放下、抛接小球，并选择安静陪伴、隐藏与叫回。形象层固定使用社区奶蛙精灵图验证功能；旧实验形象配置保持可读，界面暂不提供切换。素材来源、摘要与使用边界见[素材说明](../../web/src/companion/assets/NOTICE.md)。

## 当前范围

- Web 桌面增加“伙伴小窝”，复用已有账号登录、启动器和窗口；小窝可将角色叫到当前网页角落，或叫回。
- 角色基础动画在本地运行，点击与物理反馈不调用模型；互动包含三回合抛接、三轮动作跟拍和五轮呼吸放松，支持键盘与减少动效。
- NAS 在 `companion.db` 中按登录成员保存形象、安静偏好、累计玩球次数、当前互动端和一个 VNAS 存储对话 ID。接口没有可选成员参数，不复制对话内容，也不执行文件或模型操作。
- 电脑桌宠通过 Electron 透明窗口运行，提供托盘、隐藏、显示、屏幕归位与窗口拖动；离线实验室复用网页的交互代码。
- 配置 NAS 地址后加载已部署本功能的 Web 页面。桌面端自行通过原有登录页认证，沿用自身会话；不复制系统浏览器 Cookie。打开“小窝”由同一 Electron 会话中的网页申请接续。
- 出现位置仍按客户端保存；角色形象、安静偏好和玩球次数跟随成员。网页小窝与同一页面的悬浮角色共享一个客户端身份，不互相争抢。

## 陪伴过程与任务情绪

这轮的体验目标是“邀请 → 伙伴动作 → 成员回应 → 伙伴反馈 → 自然结束”，每个玩法都有自己的轮次和结束反馈。动作使用现有奶蛙帧，不重新生成形象；招手、左右移动、思考、执行、等待、开心和受阻之间用已有 Motion 库做短交叉淡化与弹簧衔接。

| 场景 | 伙伴表现 | 成员可以做什么 |
| --- | --- | --- |
| 收到任务、执行工具 | 专心思考、认真工作 | 看进度，也可以陪它玩一会儿 |
| 等待确认卡 | 停下当前小游戏，期待地等候 | 打开原 VNAS 确认卡决定 |
| 本轮回答完成 | 短暂开心，6.5 秒后恢复平稳陪伴 | 看结果、击掌；不宣称文件已保存 |
| 任务报错 | 短暂沮丧后缓和 | 摸摸它、看原因；不责怪成员 |
| 停止任务 | 放松下来 | 随时休息，不受惩罚 |
| 空闲 45 秒 | 当前停留中邀请玩一小会儿 | 选择玩法或“下次再玩”；拒绝后本次停留不再邀请 |

真实联动继续使用当前成员已绑定的 VNAS 对话、网关事件和确认卡。流式文字、未结束回复、过程发言和旧回答后面的新用户消息都不能触发“回答完成”；刷新看到历史结果时不重播庆祝。当前不是监听全部对话或系统任务。未来本地 AI 只要遵循同一 VNAS 任务协议即可复用；其他执行器仍需实现任务状态 Adapter，不让语言模型直接操控 DOM、执行动画脚本或越过确认规则。

### 三个可完整玩一轮的小玩法

- **你来我往抛接球**：成员抛出 → 奶蛙接住 → 奶蛙回传 → 小球亮起等成员接住 → 鼓励或温和失手反馈；共三回合。只有实际接回才累计玩球次数，快速重复点击不多计。减少动效时保留文字流程并移除接球时限。
- **默契跟拍**：奶蛙示范“左边 / 招手 / 右边”的两步动作 → 成员按顺序回应 → 下一轮多一步，共三轮。出错后给出轻松反馈，可以再玩，不扣成长值。
- **一起放松**：五轮吸气三秒、呼气三秒，共三十秒；身体随节奏舒展，文字同步提示。随时可以结束，不调用模型，也不作健康效果承诺。

安静、隐藏、页面切到后台或失去互动租约会结束当前游戏并清理定时器。减弱动效保留流程与键盘操作；原生桌宠沿用同一套逻辑，互动按钮位于鼠标可点击区域。当前只共享既有玩球累计和偏好，不同步游戏逐回合状态；切换端后从新的小游戏开始。

### 下一轮体验验证

先让同事试玩上述完整回合与真实任务事件，观察是否愿意主动再玩、动作是否清楚、提示是否打扰。随后再迭代本地 AI 驱动的情境短对话、可编辑的共同小记忆和更多双人小游戏。模型决定语气或提出玩法时仍需受到安静偏好、邀请频率和任务状态约束；日常动作、游戏判定和任务完成事实继续由本地逻辑负责。触屏与重新设计形象继续延后。

## 接续规则

### 小窝 → 桌宠 → 小窝

打开 Web 小窝只观察，不抢占其他端。成员点“叫到这里”后才申请互动；电脑桌宠启动并登录后申请一次，后续通过按钮叫回。“到网页桌面陪我”只切换当前网页内的位置。

其他端在线时，新端显示“正在过来”，保持不可互动；旧端读到申请后先停止本地互动，再向 NAS 确认交接。NAS 原子地递增活动代次并授予新端；旧代次的玩球、续期和交接都被拒绝。桌宠“回小窝”打开或刷新小窝窗口，由小窝申请接续，旧端按同一规则交接。

旧端离线或页面隐藏、来不及确认时，新端等待其 15 秒租约到期后重新申请。不是点击后立即在两端同时激活。客户端按请求发出时刻计算保守截止时间，不使用跨设备的墙上时钟，也不因慢响应额外延长互动；即使读取挂起，到期后也会停下。

### 进度与冲突

申请携带状态版本，过期版本返回冲突；写操作携带当前代次和唯一事件 ID。最近 256 个事件内的同内容重试不会重复累计，复用事件 ID 改内容会被拒绝。客户端不自动重放离线玩球。

断线时显示暂停，可主动选“先在本地玩”，该模式的次数与偏好不写入共享状态。连接恢复后需点“叫到这里”退出本地模式。旧版 NAS 或未启用状态存储的测试实例显示接续不可用，不能把本地偏好当作 NAS 同步。

### 退出与恢复

退出账号卸载小窝与悬浮角色，取消请求和排队中的写操作；再次登录按成员读取 NAS 状态。页面隐藏时停止轮询和互动，重新可见时恢复读取。服务端不靠浏览器关闭通知维持正确性，失去响应的旧端最终通过租约失效。

## 第一条任务流程：NAS 文本会议纪要

- 小窝列出本人个人空间与共享空间，排除管理员查看的其他成员空间；选择 32 KiB 以内的 `.txt` / `.md`。路径按 NAS 挂载名称构造并作为 JSON 引用，交给既有 VNAS `read_file` 读取，浏览器不另传文件内容。
- 通过既有 `useAssistantGateway` / `useAssistantThread` 创建或恢复对话，先用当前互动代次把存储 ID 记入 `companion.db`，成功后才 `prompt.submit`。保存失败或窗口退出不继续排队提交。只复用现有成员的 Hermes 实例、会话与工具规则，不另起一个 Agent。
- 首轮整理摘要与待办，不提交个人文件更改。点“保存到个人空间”继续同一对话，请 VNAS 走 `submit_changes`；这只是提交确认请求，用户仍须在原 VNAS 确认卡决定。桌宠不调用确认接口。
- 任务表现从真实连接、线程和确认卡记录推导：连接中、思考、处理、等待决定、回答结束、失败、停止。回答结束只代表本轮回答结束；“已确认保存”只采纳 `approval.status=applied` 且 `change.status=applied` 的写入、复制与移动记录，不采纳模型口述的文件路径。
- 已确认的个人空间文本文件可通过已有文件列表定位真实文件 ID，再使用认证的文本预览接口读取（预览上限 256 KiB）；其他位置与大文件回原 VNAS 或文件管理查看。此处不把模型输出转成下载 URL。
- 原生桌宠和网页悬浮入口显示任务状态并可停止已运行回答。原生桌宠“交代事情”打开小窝，确认与完整交互进入同一个 VNAS 对话。原生 IPC 仅接受正常存储对话 ID，导航保持同一 NAS origin。
- 接续只共享对话引用；每端恢复同一对话及确认记录。互动租约到期不会取消后台任务；任务生命周期遵循现有 VNAS 成员实例规则，不承诺成员退出后无限后台运行。断线时停止新提交，重连恢复结果，不自动重放 prompt。
- 本次 SQLite 迁移为版本 1，旧活动次数、偏好、代次和事件去重记录保留。新字段不赋予任何对话读取权限；实际访问继续由既有助手成员鉴权校验。

## 非目标与待办

- **触屏待办**：现有硬件暂不支持；触控手势、公共与个人模式、共享屏幕身份确认及触屏实机验收均不在当前交付范围。
- 当前接续的是小型活动状态，不保存球的逐帧坐标、桌面布局、聊天记忆或物件库存。
- 当前任务模板仅为文本纪要；语音按住说话、统一 TTS、长时专注陪伴、关系记忆、照片纪念卡和共同小作品后续接入。
- 系统其他应用的全屏自动避让、混合 DPI、多显示器连续甩抛与 Windows 原生验收待做。当前可从托盘主动隐藏；显示器变化时归位。
- 不后台读取其他应用、连续截屏、常开麦克风或自动访问用户资料；没有登录自启或自动部署操作。

## 验证与交付边界

- 本地体验二版：完整 Web **610/610**、typecheck、lint、生产与离线桌宠构建通过；专项用例覆盖三回合计数、重复点击、跟拍、呼吸、安静停止、邀请拒绝、情绪恢复与网关完成事件。当前 Mac 浏览器已实际完成三回合抛接，原生窗口已观察到跟拍示范及回应按钮；情绪演示使用明确标注的模拟任务入口。尚未接入真实模型，也未重跑二版的跨端浏览器脚本；真实任务、原生跨端与多屏验收仍待做。
- 玩法单测覆盖键盘招呼、玩球、安静模式、拖动取消、隐藏后叫回、账号偏好与不可用的本地存储；物理测试覆盖反弹、停稳、后台时间跳跃与过小容器。
- 接续控制器覆盖旧端停下再交接、候选端等待与到期、慢响应、旧版本、退出期间的请求和断线不重放。领域存储通过 race 测试验证并发申请、成员隔离、事件去重与重启持久化；五个 HTTP 操作均做契约校验。
- `smoke:handoff` 用真实临时 SQLite 与领域 API、两个独立 Chromium 上下文验证双向接续、共享偏好与进度、断网后本地玩不回写。它使用固定的合成测试成员，不验证产品登录或 CSRF；完整产品路由的鉴权测试单独放在 `internal/httpapi/companion_test.go`，需要 Linux 开发环境运行。
- `smoke` 检查本机离线 Electron 桌宠与小窝、透明窗口尺寸、隔离配置和基本交互；不能替代已登录 NAS 的 Electron 实机验收。
- `smoke:tasks` 使用真实伙伴 SQLite/API、React 组件、Hermes JS 客户端及原 VNAS 确认卡 UI，验证选文件→草稿→等待→桌宠接续→手动确认→预览→刷新不重复提交。模型运行时、文件 API、确认执行器与成员鉴权为模拟；它不是真实 NAS 文件落盘或模型效果验收。
- 本机前端 typecheck/lint/build、相关 74 项前端测试、伙伴 Go race 与离线原生烟测通过；原型快照完整 Web 602 项通过，音乐菜单测试现等待真实表格行。macOS 无法运行 Linux-only 产品门禁；PR 使用 Ubuntu x86_64 的完整检查、race、Debian systemd 系统测试和专门的伙伴协议验证，结果以对应提交的 CI 为准。
- 完整 Linux 门禁、真实 NAS 登录/退出/会话失效、真实模型与保存执行器、Windows 与多屏验收仍待做；部署事实以[当前状态](../status/CURRENT.md)为准。
