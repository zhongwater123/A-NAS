# 系统更新

状态：draft
更新时间：2026-11-12

## 目标

管理员在“设置 → 系统更新”中查看、下载、安装 A-NAS 的新版本，不需要 SSH，也不需要手写命令。设备定时检查新版本并在后台下载；安装后检查不通过时自动回到原来的版本。这是 [ADR 0034](../adr/0034-release-as-signed-debian-packages-and-update-devices-with-sysupdate.md) 实施计划的第 4 步：Host Agent 的更新服务与“设置”中的更新页。

同一个页面、同一套状态，两种设备：

- **软件包设备**：由人装好 Debian、从 A-NAS 的签名软件源用 apt 安装的机器，例如 Experimental NAS（[部署 A-NAS 软件包](../runbooks/deploy-a-nas-packages.md)）。更新服务替管理员执行部署手册第 6 步的 apt 命令与 `a-nas-check`，失败时执行手册中的回滚。
- **镜像设备**：家里的设备，以两个系统分区更新（ADR 0034 决定 2，第 5 步）。更新服务调用 `systemd-sysupdate --json=short`；系统更新要重启，产品层的更新不重启；新版本启动失败由 systemd-boot 退回。

先实现软件包设备；镜像设备随第 5 步接入，本规格写明两者的差别。自动下载、自动安装、谁能看到、回到上一版本与提示位置的默认做法由用户 2026-11-12 确认（[决定记录](../decisions/2026-11-12-system-update-defaults.md)）。

## 非目标

- 不在页面上切换更新渠道（`release` 与 `dev`）或软件源地址：它们来自设备上的软件源配置。软件源放在哪里另行决定（[决定记录](../decisions/2026-11-11-update-hosting.md)）。
- 不提供增量下载：软件包设备按包下载，内容没变的包不下载；镜像设备每次系统更新下载约 750 MiB（ADR 0034 第 3 步结论）。
- 不更新应用中心的应用与它们的镜像；应用由应用中心管理。
- 不负责软件包设备上 Debian 自己的更新（`apt upgrade`）；那仍由管理员按 Debian 的做法处理。镜像设备的 Debian 随基础镜像更新。
- 不管理多台设备，不做远程推送；每台设备自己检查。
- 不装指定的任意版本：只有“装最新版本”与“回到上一版本”。

## 页面

“系统更新”在设置侧栏的“存储”之后，只对管理员显示。成员看不到这个分区，概览中的“产品版本”照常显示。

页面从上到下：

- **当前版本**：版本号与安装时间；软件包设备另写“渠道：release”或“release 与 dev”。
- **状态与操作**：一行状态和它对应的一个主要按钮（见下表），下载与安装时显示进度。
- **新版本**：有新版本时显示版本号、发布日期、需要下载的大小与更新内容。更新内容取自新版本附带的发布说明；开发构建没有发布说明时只显示版本号中的提交号。
- **设置**：“自动下载新版本”开关；“自动安装”开关与时段（见“自动下载与自动安装”）。
- **记录**：最近 10 次检查失败、安装、回退与回到上一版本，每条有时间、版本、结果与原因；完整记录在“日志 → 活动记录”。

| 状态 | 显示 | 主要按钮 |
|---|---|---|
| 已是最新 | 已是最新版本，上次检查于 …（时间） | 检查更新 |
| 有新版本 | 有新版本 X | 下载（自动下载打开时不出现，直接进入下载） |
| 下载中 | 正在下载 X：已下载 / 总大小 | 无；可以离开页面 |
| 可以安装 | X 已下载，可以安装 | 安装 |
| 安装中 | 正在安装 X | 无 |
| 等待重启（镜像设备） | X 已装好，重启后生效 | 立即重启 |
| 已回退 | X 安装后检查没有通过，已回到 Y | 查看原因 |
| 检查失败 | 无法检查更新：原因 | 重试 |

“回到上一版本”在页面底部，只在上一版本仍可回到时显示，点击后在对话框中确认。

## 场景

### 定时检查

- Given：设备开机运行，软件源可以访问。
- When：每天一次，在随机的时刻检查；管理员打开页面时，上次检查超过一小时也检查一次；点“检查更新”立即检查。
- Then：只读取 A-NAS 软件源的签名索引，不下载软件包；镜像设备只取约 300 字节的清单与签名。有比当前版本新的版本时，状态变为“有新版本”，概览的“需要处理什么”出现一项“有新版本 X”，设置侧栏的“系统更新”带一个标记。检查只用管理员配置的软件源，不访问其他地址。

### 下载

- Given：有新版本 X。
- When：自动下载打开，或管理员点“下载”。
- Then：下载 X 需要而设备上还没有的文件：软件包设备只下载变了的软件包，模型与运行环境没变就不下载。下载前核对系统盘的可用空间：需要下载的大小加上安装后的大小，再留 2 GiB；不够时不下载，状态写明还差多少。下载在后台进行，离开页面或关闭浏览器不影响；断网后下次检查时从断点继续。每个文件按签名索引中的 SHA-256 核对，不符时丢弃并显示“下载的文件与签名不符，已丢弃”。

### 安装

- Given：X 已下载，没有进行中的存储转换、应用安装或卸载、快照恢复，也没有另一个更新在进行。
- When：管理员点“安装”，确认对话框写明“安装期间 A-NAS 的服务会重启，正在进行的上传、终端与相册整理会中断后重连”；或到了自动安装的时段。
- Then：
  - 软件包设备：执行部署手册第 6 步的安装命令，`preinst` 先复制数据库，`postinst` 按顺序重启服务。页面在服务重启时显示“正在安装，页面会在服务恢复后自动刷新”，恢复后显示结果。
  - 镜像设备：系统组件写进空闲的分区，状态变为“等待重启”；只有产品层变了时不重启，换上新的产品层并重启服务。
  - 有上面列出的任务在进行时，按钮不可用并写明在等什么；自动安装推迟到下一个时段。

### 安装后的检查与自动回退

- Given：X 刚装好（软件包设备）或刚从 X 启动（镜像设备）。
- When：更新服务运行健康检查：软件包设备是 `a-nas-check`，镜像设备是开机的健康检查（`boot-complete.target`）。
- Then：通过时状态变为“已是最新”，记录“已更新到 X”。不通过时：
  - 软件包设备：回到安装前的版本 Y（部署手册的回滚命令），数据库由 Y 启动时按 X 留下的反向步骤退回；Y 的检查也不通过时，从安装前的数据库副本恢复（部署手册“回滚或恢复”）。状态变为“已回退”，记录 `a-nas-check` 失败的项。
  - 镜像设备：失败的版本试启动 3 次后，systemd-boot 回到 Y；更新服务在 Y 上发现启动过的 X 没有被标为成功，状态变为“已回退”，并且不再自动安装 X。
  - 已回退的版本不再自动下载或安装；检查到更新的版本时照常提示。

### 回到上一版本

- Given：X 已装好并通过检查，安装前的版本 Y 仍在软件源中（软件包设备）或仍在另一个分区上（镜像设备）。
- When：管理员点“回到上一版本”并确认。
- Then：与自动回退相同的步骤回到 Y，记录“由 admin 回到 Y”。之后自动安装不再装 X，直到出现比 X 更新的版本。

### 安装中断电或重启

- Given：软件包设备在安装 X 的过程中断电。
- When：重新开机。
- Then：更新服务在开机时发现上次的安装没有完成，先让 dpkg 把中断的安装做完（`dpkg --configure -a`），再运行检查，按“安装后的检查与自动回退”处理。镜像设备写分区时断电，下次启动仍是 Y，空闲分区里写了一半的内容被丢弃，下次下载重新写（ADR 0034 第 3 步已验证）。

### 软件源不可达或签名不对

- Given：软件源暂时访问不到，或它的签名与设备信任的 A-NAS 存档密钥不符。
- When：检查更新。
- Then：前者显示“无法检查更新：连不上软件源”，保留上次检查的结果；后者显示“软件源的签名不对，没有使用它”，不下载也不安装，记入活动记录。两种情况都不影响设备的其他功能。

### 自动下载与自动安装

- Given：管理员在页面的“设置”中操作。
- When：打开或关闭“自动下载新版本”（默认打开）；打开“自动安装”（默认关闭）并选时段（默认 03:00–05:00）。
- Then：自动下载打开时，发现新版本就下载。自动安装打开时，在时段内安装已下载的版本，安装与检查的结果照常记录；镜像设备需要重启的更新在同一时段内重启。时段内有进行中的任务时推迟到第二天。

## 边界与失败

- 权限：只有管理员能检查、下载、安装与回到上一版本；成员的请求返回 `403`。服务端执行权限，页面只是不显示入口。
- 同一时间只有一个更新操作；第二个请求返回 `409 update_busy`，写明正在做什么。
- 执行位置：安装会重启产品服务与 Host Agent，所以下载、安装、检查与回退在独立的 systemd 单元中由 root 运行，不是任何一个要被重启的服务的子进程。产品服务经 Host Agent 的类型化接口发起操作、读取状态，与网页搜索的开关一样；更新服务把状态写在自己的状态目录中，服务重启后照常读到。
- 版本只能前进：自动操作只装比当前版本新的版本；“回到上一版本”只回到安装前的那一个。软件包设备的版本由 [`release-version.sh`](../../scripts/release-version.sh) 的规则排序。
- 内容包的保留：上一版本用到的模型与运行环境保留到下一次更新通过检查，更早的才删除，所以“回到上一版本”不需要重新下载它们。
- 系统盘空间：下载与安装前都核对；安装中空间耗尽时按安装失败处理并回退。
- 活动记录：检查失败、开始下载、安装、通过或回退、回到上一版本、签名不对，各记一条，带操作者（管理员或“自动”）、版本与原因（[日志](logs.md)）。
- 时间与版本号按[网页错误与时间](web-errors-and-time.md)的格式显示；大小用[大小单位](size-units.md)。

## 验收证据

- 单元测试：状态机（每个状态的合法操作与 `409`）、apt 与 `systemd-sysupdate --json=short` 输出的解析、空间核对、只装更新的版本。
- 系统测试（软件包设备）：在签名软件源中放上一 release、本 release 与“下一 release”：
  - 经产品接口检查、下载、安装到下一 release，`a-nas-check` 通过；
  - 安装一个 `a-nas-check` 故意失败的版本，自动回到原版本，数据库按反向步骤退回；
  - 回到上一版本；
  - 安装中杀掉更新单元，重启后完成或回退；
  - 成员调用返回 `403`。
- 镜像设备：在第 3 步的虚拟机验证（[研究记录](../research/sysupdate-image-verification.md)）上加一轮：经更新服务的检查、下载、重启、坏版本被退回后状态为“已回退”。
- 前端测试：每个状态的显示与按钮、安装中服务重启后自动刷新、成员看不到分区。
