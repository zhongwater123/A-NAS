# 系统更新

状态：软件包设备 implemented（2026-11-13，尚未在 Experimental NAS 上运行）；镜像设备 draft（ADR 0034 第 5 步）
更新时间：2026-11-13

## 目标

管理员在“设置 → 系统更新”中查看、下载、安装 A-NAS 的新版本，不需要 SSH，也不需要手写命令。设备定时检查新版本并在后台下载；安装后检查不通过时自动回到原来的版本。这是 [ADR 0034](../adr/0034-release-as-signed-debian-packages-and-update-devices-with-sysupdate.md) 实施计划的第 4 步：Host Agent 的更新服务与“设置”中的更新页。

同一个页面、同一套状态，两种设备：

- **软件包设备**：由人装好 Debian、从 A-NAS 的签名软件源用 apt 安装的机器，例如 Experimental NAS（[部署 A-NAS 软件包](../runbooks/deploy-a-nas-packages.md)）。更新服务替管理员执行部署手册第 6 步的 apt 命令与 `a-nas-check`，失败时执行手册中的回滚。
- **镜像设备**：家里的设备，以两个系统分区更新（ADR 0034 决定 2，第 5 步）。更新服务调用 `systemd-sysupdate --json=short`；系统更新要重启，产品层的更新不重启；新版本启动失败由 systemd-boot 退回。

先实现软件包设备；镜像设备随第 5 步接入，本规格写明两者的差别。自动下载、自动安装、谁能看到、回到上一版本与提示位置的默认做法由用户 2026-11-12 确认（[决定记录](../decisions/2026-11-12-system-update-defaults.md)）。

软件源从哪里来：近期以局域网推送为主（[决定记录](../decisions/2026-11-13-release-by-lan-push.md)）。开发机构建并签名后，把软件源目录推送到设备上暂存账号的目录（部署手册第 2 步）；更新服务把它同步到 apt 的本机软件源 `/var/local/a-nas-repository`，再按下面的流程检查与安装，代替部署手册中 root 手工执行的第 3 步与第 6 步。暂存目录由 `/etc/a-nas/site.conf` 的 `ANAS_UPDATE_STAGING` 指定，没有设置时不同步。设备的 apt 源指向 GitHub 等网络地址时（备选），没有同步这一步，新版本要先下载。

## 非目标

- 不在页面上切换更新渠道（`release` 与 `dev`）、软件源地址或暂存目录：它们来自设备上的软件源配置与 `site.conf`。
- 不提供增量下载：软件包设备按包下载，内容没变的包不下载；镜像设备每次系统更新下载约 750 MiB（ADR 0034 第 3 步结论）。
- 不更新应用中心的应用与它们的镜像；应用由应用中心管理。
- 不负责软件包设备上 Debian 自己的更新（`apt upgrade`）；那仍由管理员按 Debian 的做法处理。镜像设备的 Debian 随基础镜像更新。
- 不管理多台设备：开发机的推送只把软件源放进设备的暂存目录，装不装由各台设备的管理员决定。
- 不装指定的任意版本：只有“装最新版本”与“回到上一版本”。

## 页面

“系统更新”在设置侧栏的“存储”之后，只对管理员显示。成员看不到这个分区，概览中的“产品版本”照常显示。

页面从上到下：

- **状态与操作**：一行状态和它对应的一个主要按钮（见下表），下载与安装时显示进度；出错时写明原因，`apt` 或 `a-nas-check` 的原话收在“详细信息”中。
- **版本**：当前版本与安装时间；有新版本时显示新版本，从网络软件源安装时另显示需要下载的大小；软件包设备另写更新渠道，“正式版”（`release`）或“正式版与开发版”（`release` 与 `dev`）。开发版的版本号显示为它通往的 release、“开发版”与提交号，如“1.0.1-rc.6 开发版 4e842653”。打了标签的 release 的发布说明以后加入。
- **自动更新**：“自动下载新版本”开关；“自动安装”开关，打开后显示安装时段（见“自动下载与自动安装”）。
- **记录**：最近 10 次检查失败、下载、安装、回退与回到上一版本，每条有时间、版本、结果、发起者与原因；同一个原因的检查失败接连发生时只记第一次。“在日志中查看”打开“日志 → 活动记录”的“系统”类别。

| 状态 | 显示 | 主要按钮 |
|---|---|---|
| 已是最新 | 已是最新版本，上次检查于 …（时间） | 检查更新 |
| 有新版本 | 有新版本 X，需要下载的大小 | 下载（自动下载打开时，检查后直接进入下载）；推送来的本机软件源没有这一步，直接是“可以安装” |
| 下载中 | 正在下载 X：已下载 / 总大小，进度条 | 无；可以离开页面 |
| 可以安装 | X 可以安装；自动安装打开时写明时段；在等存储或应用时写明在等什么 | 安装（在等时不可用） |
| 安装中 | 正在安装 X，服务重启、恢复后自动刷新 | 无 |
| 等待重启（镜像设备） | X 已装好，重启后生效 | 立即重启 |
| 已回退 | X 安装后检查没有通过，已回到 Y，下面是原因 | 检查更新 |
| 检查失败 | 无法检查更新，下面是原因 | 重试（设备不是用软件包安装的时没有） |

“已回退”一直显示到出现比 X 更新的版本，或管理员回到上一版本；之后的检查不改变它，检查失败只进记录。“回到原版本时出错”（自动回退或回到上一版本之后）另在之后的检查中 `a-nas-check` 再次通过时消失，例如管理员按部署手册修好之后。

安装与回到上一版本都先在对话框中确认，对话框写明服务会重启、正在进行的上传、终端与相册整理会中断后重连。安装后页面的代码仍是旧版本的：页面比较自己构建时的版本（`make` 的 `VERSION`）与设备上装的版本，不同时顶部提示刷新。

“回到上一版本”在页面底部，只在上一版本仍在软件源中时显示：每次检查都核对，软件源不再有它时不再显示。

打开页面时，上次检查已超过一小时就检查一次；这样的检查与定时检查一样，不记入活动记录。

## 场景

### 定时检查

- Given：设备开机运行，软件源可以访问。
- When：更新服务开机 2 分钟后运行，之后约每小时一次（时刻随机错开 10 分钟以内）；每次先同步暂存目录，有推送来的文件、上次检查已满一天或上次检查失败时检查。管理员打开页面时，上次检查超过一小时也检查一次；点“检查更新”立即检查。
- Then：先把暂存目录中推送来的软件源同步到本机软件源（设置了 `ANAS_UPDATE_STAGING` 时），再只读取 A-NAS 软件源的签名索引，不下载软件包；镜像设备只取约 300 字节的清单与签名。有比当前版本新的版本时，状态变为“有新版本”，概览的“需要处理什么”出现一项“有新版本 X”，设置侧栏的“系统更新”带一个标记。检查只用管理员配置的软件源，不访问其他地址。

### 开发机推送了新版本

- Given：设备设置了 `ANAS_UPDATE_STAGING`，开发机按部署手册第 1、2 步构建 X 并推送到暂存目录。
- When：下一次定时检查，或管理员在页面上点“检查更新”。
- Then：同步只复制暂存目录中 `dists` 与 `pool` 下的普通文件：先复制软件包，最后复制索引，所以 apt 读到的索引不会指向还没到的文件；不跟随指出暂存目录的链接，不复制设备、管道或其他目录中的文件；已有且大小、修改时间相同的文件不再复制。复制前核对系统盘的可用空间：要复制的大小再留 2 GiB，推送中已经没有、同步要删除的文件腾出的空间也算上。复制完成后，删除本机软件源中推送已经没有的文件，旧版本的软件包与模型不会堆在系统盘上；要先删除它们才放得下时（例如推送换了模型），先删除再复制，复制完成前 apt 读到的旧索引可能指向已删除的文件，这时安装在改动任何东西之前失败，下一次同步补齐。仍放不下时一个文件也不复制、也不删除，记录写明还差多少：已经“可以安装”或“有新版本”的照常提供，否则状态为“检查失败”。同步之后，apt 核对签名：被改过或签名不对的文件让检查失败（见“软件源不可达或签名不对”），不会被安装。状态变为“可以安装”。

### 下载

- Given：有新版本 X，设备的软件源是网络地址。
- When：自动下载打开，或管理员点“下载”。
- Then：下载 X 需要而设备上还没有的文件：软件包设备只下载变了的软件包，模型与运行环境没变就不下载。下载前核对系统盘的可用空间：需要下载的大小加上安装后的大小，再留 2 GiB；不够时不下载，状态写明还差多少。进度按 apt 缓存中已经下载的文件计算，约每 2 秒更新一次。下载在后台进行，离开页面或关闭浏览器不影响；断网后下次检查时从断点继续。apt 按签名索引中的 SHA-256 核对每个文件，不符时丢弃它，状态写明“下载没有完成”，下次检查时重新下载。

### 安装

- Given：X 已下载，没有执行中的硬盘计划、数据卷转换、应用安装或卸载，也没有另一个更新在进行。
- When：管理员点“安装”，确认对话框写明“安装期间 A-NAS 的服务会重启，正在进行的上传、终端与相册整理会中断后重连”；或到了自动安装的时段。
- Then：
  - 软件包设备：执行部署手册第 6 步的安装命令，`preinst` 先复制数据库，`postinst` 按顺序重启服务。页面在服务重启时显示“正在安装，页面会在服务恢复后自动刷新”，恢复后显示结果。
  - 镜像设备：系统组件写进空闲的分区，状态变为“等待重启”；只有产品层变了时不重启，换上新的产品层并重启服务。
  - 有上面列出的任务在进行时，按钮不可用并写明在等什么；自动安装等它们结束，时段内结束不了就等下一个时段。
  - 安装在改动任何东西之前失败，例如等不到 apt 的锁：dpkg 记录的每个软件包（包括依赖）的状态与版本都与安装前相同，设备仍完整地在 Y 上，不回退，也不拒绝 X。状态回到“可以安装”，记录“安装 X 没有完成”和原因。只要有一个软件包变了，哪怕只是依赖，就按安装失败回退并运行检查。

### 安装后的检查与自动回退

- Given：X 刚装好（软件包设备）或刚从 X 启动（镜像设备）。
- When：更新服务运行健康检查：软件包设备是 `a-nas-check`，镜像设备是开机的健康检查（`boot-complete.target`）。
- Then：通过时状态变为“已是最新”，记录“已更新到 X”。不通过时：
  - 软件包设备：回到安装前的版本 Y（部署手册的回滚命令），数据库由 Y 启动时按 X 留下的反向步骤退回；Y 的检查也不通过时，从安装前的数据库副本恢复（部署手册“回滚或恢复”）。状态变为“已回退”，记录 `a-nas-check` 失败的项。
  - 镜像设备：失败的版本试启动 3 次后，systemd-boot 回到 Y；更新服务在 Y 上发现启动过的 X 没有被标为成功，状态变为“已回退”，并且不再自动安装 X。
  - 已回退的版本不再提供：页面不显示它，也不自动安装；检查到更新的版本时照常提示。

### 回到上一版本

- Given：X 已装好并通过检查，安装前的版本 Y 仍在软件源中（软件包设备）或仍在另一个分区上（镜像设备）。
- When：管理员点“回到上一版本”并确认。
- Then：与自动回退相同的步骤回到 Y，记录“由 admin 回到 Y”。之后不再提供 X，直到出现比 X 更新的版本。装 Y 失败时回到 X（什么都没改动时不用回）；回到 X 也失败或 X 的检查不通过时，状态为“已回退”，页面显示“回到原版本时出错”，直到 `a-nas-check` 再次通过。

### 安装中断电或重启

- Given：软件包设备在安装 X 的过程中断电。
- When：重新开机。
- Then：更新服务在开机时发现上次的安装没有完成，先让 dpkg 把中断的安装做完（`dpkg --configure -a`），再看发行的各个包：a-nas、a-nas-host，以及 dpkg 中有的 a-nas-console 与 a-nas-assistant-trial。
  - 都装好在 X 上：运行检查，按“安装后的检查与自动回退”处理。
  - dpkg 记录的每个软件包都与安装前相同，包括依赖：安装还没有改动什么，按上面“安装在改动任何东西之前失败”处理。
  - 其他情况回到 Y：apt 重新安装 Y 的各个包，包括做到一半的（`--reinstall`，解包到一半的包在 dpkg 中还记着 Y 的版本，不重新安装 apt 会当它已经装好）。回到 Y 之后检查仍不通过，记录为“没有完成”，页面显示“回到原版本时出错”。
  - 回退或回到上一版本时断电：下次运行接着做完，原因与数据库副本随状态保存，不会反过来装回要离开的版本。镜像设备写分区时断电，下次启动仍是 Y，空闲分区里写了一半的内容被丢弃，下次下载重新写（ADR 0034 第 3 步已验证）。

### 软件源不可达或签名不对

- Given：软件源暂时访问不到，或它的签名与设备信任的 A-NAS 存档密钥不符。
- When：检查更新。
- Then：前者显示“无法检查更新：连不上软件源”，保留上次检查的结果；后者显示“软件源的签名不对，没有使用它”，不下载也不安装，记入活动记录。两种情况都不影响设备的其他功能。

### 自动下载与自动安装

- Given：管理员在页面的“设置”中操作。
- When：打开或关闭“自动下载新版本”（默认打开）；打开“自动安装”（默认关闭）并选时段（默认 03:00–05:00）。
- Then：自动下载打开时，发现新版本就下载。自动安装打开时，在时段内安装已下载的版本，每个时段只请求一次：更新服务没有安装时（例如系统盘空间不够），下一个时段再试。安装与检查的结果照常记录，自动安装的请求以“系统”为操作者；镜像设备需要重启的更新在同一时段内重启。时段内有进行中的任务时等它们结束，结束不了就等下一个时段。

## 边界与失败

- 权限：只有管理员能检查、下载、安装与回到上一版本；成员的请求返回 `403`。服务端执行权限，页面只是不显示入口。
- 同一时间只有一个更新操作；第二个请求返回 `409 update_busy`，写明正在做什么。
- 请求：Host Agent 把请求留给更新单元并启动它。单元没有启动时删掉请求，管理员看到失败；10 分钟内没有被取走的请求作废，不会在之后的定时运行中执行（那时可能已出了安装时段，或存储、应用正在忙）。请求恰好与定时运行同时开始时，由那次运行做完自己的事后接着执行。
- 执行位置：安装会重启产品服务与 Host Agent，所以同步、下载、安装、检查与回退在独立的 systemd 单元中由 root 运行，不是任何一个要被重启的服务的子进程。产品服务经 Host Agent 的类型化接口发起操作、读取状态，与网页搜索的开关一样；更新服务把状态写在自己的状态目录中，服务重启后照常读到。
- 暂存目录不受信任：它属于暂存账号，谁都可能往里放东西。同步只读它、只写本机软件源，不执行其中的任何东西；能装上的只有 A-NAS 存档密钥签过的软件包，安装前 apt 逐个核对。
- 版本只能前进：自动操作只装比当前版本新的版本；“回到上一版本”只回到安装前的那一个。软件包设备的版本由 [`release-version.sh`](../../scripts/release-version.sh) 的规则排序。
- 内容包的保留：上一版本用到的模型与运行环境保留到下一次更新通过检查，更早的才删除，所以“回到上一版本”不需要重新下载它们。
- 系统盘空间：推送同步、下载与安装前都核对；安装中空间耗尽时按安装失败处理并回退。
- 活动记录：管理员的下载、安装、回到上一版本与设置改动各记一条；更新服务的结果（检查失败或签名不对、下载完成、已更新、已回退、回到上一版本、没有完成）在产品服务读到时各记一条，时间是结果发生的时间，带发起者（管理员或“自动”）、版本与原因；同一条结果只记一次，几个读取同时写也一样。它们在活动记录的“系统”类别中，只有管理员看得到（[日志](logs.md)）。
- 时间与版本号按[网页错误与时间](web-errors-and-time.md)的格式显示；大小用[大小单位](size-units.md)。

## 验收证据

- 单元测试（[更新服务](../../internal/systemupdate/updater/service_test.go)）：推送同步只取暂存目录中的普通文件；检查找到推送来的新版本；网络软件源按设置下载；没有推送时一天检查一次；签名不对时检查失败；安装通过、安装失败与检查失败后的回退；没有改动什么的安装失败不回退、再次提供，只改了依赖的回退；已回退经后来的检查不变，更新的版本取代它；断电后完成、回退或再次提供，按发行的全部包判断，解包到一半的包（包括 a-nas-console）重新安装；回退与回到上一版本断电后接着做完，原因先于安装保存；回退后检查仍不通过时记为没有完成，修好之后的检查消去它；回到上一版本，回不去或回去后检查不通过时显示“回到原版本时出错”直到检查通过；软件源不再有的上一版本不再提供；连不上软件源只记一次；下载进度；空间不够时不下载、不同步推送，不同步的推送不收回可以安装的版本；推送没有的文件从本机软件源删除，删除后才放得下的推送先删除；作废没被取走的请求；跨午夜的安装时段。Host Agent 只留下请求、启动单元，请求未被取走时算作运行中，单元没有启动时删掉请求（[执行器](../../internal/hostops/linux/update_test.go)、[root 代理](../../internal/hoststate/agent/rootagent/update_test.go)）。
- 接口测试（[`systemupdate_test.go`](../../internal/httpapi/systemupdate_test.go)，按契约核对）：成员 `403`；存储或应用在忙时安装返回 `409 update_waiting`，运行中返回 `409 update_busy`；安装、回到上一版本与设置；请求与结果各记一次活动记录。自动安装每个时段只请求一次、以“系统”为操作者，结果按发生的时间记录（[产品服务](../../internal/systemupdateapi/systemupdateapi_test.go)）；同时写的同一条结果只记一次（[账号服务](../../internal/accounts/systemupdate_test.go)）。
- 系统测试（软件包设备，[`system-test.sh`](../../scripts/system-test.sh) 的系统更新一节）：签名软件源中有上一 release、本 release 与下一 release，暂存目录就是这个软件源：
  - 经产品接口检查，同步推送，找到下一 release；安装，`a-nas-check` 通过，数据库多出下一 release 的一步；
  - 回到上一版本，数据库按反向步骤退回，再检查不提供刚离开的版本；
  - 下一 release 上 `anas-site.service` 启动失败、`a-nas-check` 不通过，自动回到本 release，数据库退回，再检查仍是“已回退”，不提供它；
  - 安装中 dpkg 工作时杀掉更新单元，下一次运行完成安装、回退，或在 dpkg 只碰过依赖时回到“可以安装”，dpkg 没有半装的包，`a-nas-check` 通过；
  - 成员读取与请求返回 `403`，活动记录中看不到；管理员的请求与结果在活动记录的“系统”类别中。
- 前端测试（[系统更新分区](../../web/src/settings/SystemUpdateSection.test.tsx)、[设置](../../web/src/settings/SettingsPanel.test.tsx)、[活动记录的句子](../../web/src/settings/logs/describe.test.ts)、[版本号与原因](../../web/src/systemupdate/texts.test.ts)）：可以安装、下载中、安装中服务重启后接着读到结果并提示刷新页面、已回退与原因、检查失败与重试、在等存储或应用、确认后安装与回到上一版本、服务拒绝时的提示、打开页面时补一次检查、自动更新的设置与时段；概览与侧栏的新版本提示；成员看不到分区。
- 镜像设备（第 5 步）：在第 3 步的虚拟机验证（[研究记录](../research/sysupdate-image-verification.md)）上加一轮：经更新服务的检查、下载、重启、坏版本被退回后状态为“已回退”；`systemd-sysupdate --json=short` 输出的解析。
