# 基础存储与共享

状态：implemented

## 目标

v1.0.1 让一名管理员和普通成员通过 Web 与 SMB3 对同一份个人或共享文件执行基本管理，并能从回收站或只读手动快照恢复单个文件。所有真实写入只进入用户确认初始化的单盘 Btrfs 数据卷。

## 角色与可见性

- 尚无有效管理员时，本地控制台只要求用户设置账号和密码；首个账号成为 A-NAS 产品管理员。不存在初始化码、默认账号或默认密码，产品管理员也不是 Linux root。只有直接回环连接（本机屏幕的 Kiosk 或 SSH 隧道）可以启用：局域网浏览器经 Caddy 访问时只看到到本机启用的说明，`POST /api/v1/setup/admin` 返回 `403 setup_local_only`，`GET /api/v1/setup/status` 的 `setupAllowed` 为 `false`，防止局域网中的其他人抢先认领新设备（[#98](https://github.com/zhongwater123/A-NAS/issues/98) E06）。
- 设备启用完成后，同一入口不可再次创建管理员，同时到达的多个启用请求也只有一个成功，其余返回 `409 setup_complete`；日常 Web 与 SMB 访问使用设备启用时设置的账号密码。账号名与密码规则见[统一身份与文件授权](unified-identity-and-file-acl.md#账号名与密码规则)。
- 管理员可创建、重置和禁用成员；普通成员不可调用账号、格式化或共享快照管理操作。
- 每名有效用户拥有一个个人空间，且加入唯一 `Shared` 空间。管理员的普通浏览也不能列出或推断其他成员的个人空间。
- Web 使用 Argon2id 与服务端会话，所有变更请求验证 CSRF；Samba 使用同次输入设置独立凭据。
- 浏览器会话自登录起固定 12 小时有效，使用中不续期。在设备本机屏幕（Kiosk 以 `?local-console=1` 打开）登录或启用设备时，会话不会自行过期，跨夜和重启后仍保持登录，直到主动退出、管理员重置该账号密码或账号被禁用；本人修改密码不影响。能接触本机屏幕的人即可使用已登录的桌面，离开时应主动退出。
- 服务端只对没有 `Forwarded`/`X-Forwarded-For` 头的直接回环连接授予本机会话，否则按 12 小时会话处理。Kiosk 与 SSH 隧道直接连接回环；局域网浏览器经 Caddy 入口访问，Caddy 总会附加转发头（[局域网 Web 访问](lan-web-access.md)）。Chromium 把 Cookie 寿命上限定为 400 天，页面每次加载读取会话时续签本机会话的 Cookie。
- 会话过期、在别处注销或账号被禁用后，已登录页面的任一请求返回 `401` 即回到登录页并提示“登录已过期，请重新登录”，不显示为连接中断；重新登录即可继续，无需重启或刷新。

## 数据卷初始化

1. 只有稳定身份、SATA/NVMe、非系统、非 USB、不可移除、未挂载且不是 swap/md/dm 成员的磁盘可生成计划。
2. 计划公开稳定磁盘 ID、型号、容量、身份指纹、破坏性动作、确认短语、状态与十分钟过期时间；不公开 `/dev/sdX`。
3. 用户必须准确输入带磁盘 ID 后缀的确认短语。执行前 Host Agent 再次枚举并核对身份。
4. 状态依次为 `planned → confirmed → running → succeeded`；失败进入 `failed` 或 `needs_attention`，过期进入 `expired`。成功重复执行不再次格式化；中断后不自动执行。

## 文件、回收站与快照

### 置顶与手动排列

- 当前目录的排列栏和右键菜单可置顶或取消置顶一个或多个文件夹；普通文件与应用资源入口不可置顶。置顶文件夹显示图钉标记，并在所有排序方式及升降序下保持在最前。
- 排列栏在列表和图标视图中都提供名称、修改时间、类型、大小及手动排序。自动排序继续按文件夹、应用资源、文件分组；手动排序只保留置顶区与普通区，区内可自由排列不同类型项目。
- 首次选择手动排序时沿用当前完整顺序；拖到另一项的位置完成重排，也可单选后使用上移、下移按钮（键盘 Tab 聚焦后激活）。置顶区与普通区不可互相拖入。搜索期间仍按既有顺序显示结果，清除搜索后才可重排；内部拖动不移动实际文件，也不创建上传任务。
- 偏好按登录账号、空间 ID、父目录 ID 保存在当前浏览器，列表和图标视图共用；刷新、关闭重开、切换目录后恢复，切换自动排序不会覆盖手动顺序。首次进入其他目录或账号使用名称升序。此版本不跨浏览器或设备同步；清除浏览器数据会重置偏好。
- 偏好只记录稳定条目 ID：重命名保留位置，删除或移走的项目不再显示，新项目在手动模式下按名称追加到所在区的末尾。加载失败不会清空偏好。浏览器存储损坏时使用默认顺序，保存受限时提示只能在本次打开期间保留。

### 文件操作

- Web 支持列出、新建目录、可续传的分片上传（含文件夹与拖入）、Range 下载与文件夹或多选的 ZIP 下载、重命名、移动、复制和删除，移动与复制可跨空间；上传与下载的进度、同名处理和异常恢复见[传输中心](transfer-center.md)。
- Web 文件管理采用可调宽的目录树、当前目录与只读详情三栏；窗口变窄时先隐藏详情栏，再以空间选择器替代目录树。路径、搜索和成熟图标组成的文件命令位于内容上方，上传入口常驻当前目录右下角。
- 当前目录支持列表与图标视图。列表的名称、修改时间、类型和大小均可排序，自动排序时文件夹在任何升降序下始终位于非文件夹项目之前；文件夹类型使用独立的暖色标签，浏览器原生支持的图片、HEIC/HEIF 照片和视频文件在两种视图中均显示真实缩略图，加载失败时回退为文件图标。单击选择项目，双击打开目录；图片（JPEG、PNG、GIF、WebP、BMP、AVIF、HEIC、HEIF）与 PDF 双击后在文件管理窗口内预览，其他文件双击下载，名称下方按类型提示“双击预览”或“双击下载”。Ctrl/Command、Shift 和空白处左键拖框支持多选，右键菜单复用工具栏的新建、预览、打开或下载、打包下载、剪切、复制、粘贴、重命名、删除和刷新逻辑；可预览的文件在菜单中同时提供“预览”和“下载”。
- 预览直接读取同源文件接口，不经过传输中心、不保存文件：顶部显示名称、大小、像素尺寸和在当前目录中的序号，左右方向键或两侧按钮在当前目录（含搜索与排序结果）的图片和 PDF 之间切换，单击图片在适合窗口与实际大小之间切换；“下载”是预览中的独立按钮，也可在新标签页打开预览内容；Esc 或关闭按钮回到列表并选中最后看过的文件。转换或浏览器解码失败时显示“无法预览这张图片”并提供下载。普通文件不是相册的照片资产，预览不跳转相册。
- 用户自己的个人空间根目录提供图库、音乐和影视三个应用资源入口：图库是个人图库的投影并交由相册打开，不暴露受管存储路径；影视打开[影视中心](media-center.md)，视频仍是普通文件；音乐打开[音乐](music.md)应用，音频同样是普通文件。应用资源不是普通目录，不参与剪切、复制、重命名或删除。
- 视频（MP4、MOV、MKV、WebM、AVI、M4V、MPG、MPEG、MTS、M2TS、FLV、F4V、WMV、3GP）通过隔离媒体 Worker 抽取时长 10% 处、至多第 10 秒的画面；HEIC/HEIF 通过 libheif 转成 PNG，支持缩略图、详情栏和双击预览。视频双击仍下载原文件；本功能不增加视频播放器。扩展名不区分大小写，损坏或不支持的内容回退到图标，图片预览失败时保留下载入口。
- 派生预览使用同源 `GET /api/v1/files/{fileId}/preview?size=thumbnail|preview`，尺寸分别为 320 与 1600（HEIF 最长边、视频宽度）。每次请求均以当前用户通过 File Broker 打开源文件，包括缓存命中与 HTTP 304；缓存按渲染版本、用户、文件身份、ctime、mtime、大小与尺寸隔离。内存最多 64 项 / 32 MiB；产品服务状态目录 `file-previews` 保存最多 4096 项 / 512 MiB 的可删除磁盘缓存，按最近使用淘汰，服务重启后可复用。目录权限 0700、文件 0600，不保存源路径，不写入用户目录；磁盘缓存不可用时仍可生成预览。删除或撤权后的旧派生文件可保留至淘汰，但不能再通过接口读取。
- 成功预览响应 `private, no-cache`、`Vary: Cookie` 与 ETag；浏览器每次复用前须向服务端校验，未变化返回无图片正文的 304，错误响应不缓存。文件修改、替换、删除或撤销权限均重新校验。只有缓存未命中的请求串行等待解码，排队随请求取消、排队时不持有源文件描述符；出队后再次打开并校验源文件，解码限时 30 秒。缓存命中不等待解码，首次浏览新文件仍需抽帧。HEIF 输入最多 256 MiB，Worker 使用自己的匿名内存文件供 libheif 读取，输出最多 12 MiB；下载始终返回原文件。
- 详情栏只显示所选资源的预览、元数据与说明，不承载文件操作按钮；JPEG、PNG、GIF、WebP、BMP 与 AVIF 使用同源文件接口内联预览，预览图保持原始宽高比并随详情栏宽度自适应，单击打开预览；HEIC/HEIF 和视频使用上述派生预览，HEIC/HEIF 可单击打开；PDF 使用浏览器内嵌预览，1 MiB 以内的 Markdown、纯文本和常见源代码文件显示真实文本内容。Word 与 PowerPoint 在文档转换服务落地前明确显示为暂不可预览，不得伪装为真实预览；剪切、复制、粘贴、重命名和删除统一从命令栏或右键菜单发起。
- 目录栏底部显示数据卷文件系统的已用空间与总空间；容量由 Host Agent 从已挂载的数据卷实时观测，观测暂不可用时显示未知，不得把缺失值解释为磁盘已满。
- 剪切或复制后在另一个空间粘贴时，条目先完整复制到目标位置，新文件继承目标空间的权限并获得新的文件 ID；剪切在复制完成后删除原条目，不经过回收站。剪切需要两个空间的写权限，复制只需能读取原条目。目标文件夹只在目标空间中查找，未指定空间时为原条目所在空间。
- 路径穿越、符号链接和设备文件被拒绝；名称冲突（含只差大小写）返回 `409`，名称不符合[名称规则](#名称规则)返回 `422`，目录不能移动或复制到自身之内。
- Web 与 Samba 删除均进入隐藏的按空间、按删除者回收站，默认保留 30 天。回收站条目只有删除者能看到、恢复和清空（[统一身份与文件授权](unified-identity-and-file-acl.md)）。
- 回收站窗口顶部汇总项目数、占用空间与 7 天内将被清理的数量，不另写保留规则的说明文字。项目按删除日期分组（今天、昨天、具体日期），每项一行：类型图标、名称与类型，原位置（空间与文件夹路径），大小（文件夹为其中已索引文件的合计），删除时间，剩余天数（圆环显示剩余比例，7 天以内标黄、1 天以内标红，悬停显示确切的清理时间），以及“恢复”和永久删除。可按名称搜索、按空间筛选，或改为按“即将清理”排序（分为 7 天内与更晚两组）。窗口变窄时每项变为两行，原位置、大小、删除时间与剩余时间带文字标签排在名称下方。
- 原位置可以点击，在文件管理中打开那个文件夹。原文件夹被改名或移动后显示它现在的位置；原文件夹已被删除时标注“已不在”，恢复会放到该空间的根目录，而不是失败。
- 恢复单个项目前确认恢复位置与名称；目标位置已有同名项目时返回 `409`，界面提示改用“名称 (恢复)”这样的新名称，绝不覆盖。恢复成功后可直接在文件管理中打开所在文件夹。
- 勾选多项（或全选当前筛选结果）后可一起恢复或永久删除：批量恢复按原名称放回各自的原位置，原位置已有同名项目的留在回收站并保持选中，以便逐个改名恢复，结果以一句话汇总。永久删除单项、所选项目或“清空回收站”都需要再次确认，并写明数量与大小；进行中显示进度，Esc 取消选择。
- 个人空间所有者管理自己的手动快照；共享空间快照仅管理员创建和删除。快照只读且不通过 SMB 暴露。快照的浏览、找回与定时快照在[备份中心](backup-center.md)。
- 恢复始终复制或移动到指定新位置，不覆盖已有文件，不提供整卷回滚。

## 名称规则

文件与文件夹的名称同时要能放进文件系统、并在 Windows 与 macOS 的 SMB 客户端里使用。用户新起的名称（新建文件夹、重命名、上传、复制或恢复时换的名字）必须满足：

- 不为空，不是 `.` 或 `..`，不以 `.a-nas-` 开头（留给 A-NAS 自己的临时文件与回收站）；
- 不超过 255 字节（约 85 个汉字），超过时返回 `422 name_too_long`；
- 不含 `\ / : * ? " < > |` 和控制字符（包括制表符、换行），不以空格或句点结尾，主名不是 `CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`（不区分大小写，带扩展名也算）；不满足时返回 `422 name_not_portable`；
- 同一文件夹中不能有只差大小写的名称（`dup` 与 `DUP`），这时与同名一样返回 `409 name_conflict`。上传文件夹时遇到只差大小写的文件夹，上传进入已有的那个；“保留两者”生成的编号名称也避开只差大小写的名称，名称加上编号后超过 255 字节时截短主名。

已有项目保持原名：经 SMB 在 Linux 上创建、或在本规则之前创建的名称，在移动、复制、移到回收站与恢复时都可以沿用原名；只有改成新名称时才按上面的规则检查。界面在提交前按同一规则提示，接口错误也显示为中文说明。SMB 端仍是 Samba 默认的名称处理，Windows 看到不合规的旧名称时显示为缩写名。

## 服务与错误

- `/healthz` 免认证；其他状态和产品接口要求会话。
- 产品服务只监听 `127.0.0.1`。本地 Kiosk 与受控 SSH 隧道直接访问；安装 Caddy 后，局域网浏览器经 80 端口以 HTTP 访问（[局域网 Web 访问](lan-web-access.md)）。
- `401`、`403`、`409`、计划过期、卷离线、空间不足与需人工处理使用统一 JSON 错误结构。
- SMART、温度、容量、占用、文件系统、数据卷角色与不可初始化原因可由磁盘接口读取。
- SMART 与温度由 Host Agent 在后台读取，每块盘至多每 10 分钟一次，只读健康结论与温度；处于待机的硬盘不被唤醒，沿用上次的结果，超过 24 小时没有新结果时显示为未知。磁盘接口和文件请求都不等待 smartctl，文件请求前的数据卷确认也不读取主机状态（[调查](../investigations/2026-10-15-host-agent-smart-on-every-request.md)）。

## 非目标

相册与 AI、NFS、多共享空间、配额、外链、定时快照、外接盘备份、整卷回滚、RAID、Scrub 修复、运行中 SATA 热插拔与自动恢复、局域网 Web、TLS、远程访问、OTA、应用中心及生产数据迁移均不属于 v1.0.1 的验收范围；其中相册、Docker 与应用中心已合入主干并部署在实验 NAS，局域网 Web 以明文 HTTP 过渡实现（[ADR 0012](../adr/0012-serve-the-web-desktop-on-the-lan-over-http-through-caddy.md)），定时快照随[备份中心](backup-center.md)实现，均不作为 v1.0.1 发布闸门。数据卷离线拒写仍是本版安全要求，但完整热插拔生命周期留待后续实现。
