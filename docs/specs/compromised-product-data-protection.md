# 产品服务失陷后的数据保护

状态：draft；安全目标由设备所有者于 2026-11-10 确认，目标架构与参数为实施提案，尚未实现或部署。
更新时间：2026-11-10

## 目标

产品服务被攻破，也不能造成用户数据不可恢复的损失。攻击者可控制产品服务进程、其可写目录、它提供的页面与脚本，并使用其见过的有效成员或管理员会话。所有由它调用的接口都按此条件设计。

保护承诺从可信端完成受保护提交并持久签发提交收据时开始；收据关联操作、资源版本、恢复集与完整性摘要，可由可信恢复入口核验。被攻破的产品页面可以伪造“成功”文字，不能把该文字当作已接收数据的证据；产品服务尚未交给可信端的输入不在接收保证内。升级前的数据必须先建立、验证保护基线。未完成上传的临时字节不算已提交数据。保护内容包括文件字节及目录关系、照片原件及动态片段、相册/标签/纠错、歌单/收藏/播放记录、用户反馈，以及恢复它们必需的 UserID、UID、资源身份、权限、引用、应用配置和应用持久数据。可重建的缩略图、向量、缓存、索引及临时进度不要求逐版本保留。

用户可以从不依赖产品服务的可信恢复入口，找回受保护版本及其必要元数据。只有经该入口明确确认的销毁授权，可以使指定版本不再受此保证保护。

## 威胁范围与承诺边界

- 假定内核、启动与安装链、身份权威、保护服务、必要的 Host Agent 执行器及恢复入口可信；攻击者不能取得宿主机 root。Docker Engine 与能控制它的容器代理属于宿主机可信计算基，不属于产品服务。
- 攻击者可以长期驻留、调用合法接口、等待、批量写入、伪造客户端时间、洪泛版本、清空回收站、关闭展示界面或删除产品服务的全部可写状态。
- 当前页面和活动数据可能被改变，产品服务可用性与其已取得的明文内容保密性不在此完整性保证内。恢复与保护不能依赖它仍然正常。
- 不涵盖物理损坏、丢盘、独立可信模块被同时攻破，以及人员经可信入口明确授权的不可逆销毁。同盘保护版本只能抵抗本威胁模型下的逻辑破坏；介质故障仍需独立备份。
- 已完成的受保护提交不采用“每天一次快照”式恢复点目标：对纳入保证的每次提交，字节和必要用户元数据必须可恢复。SMB 写入的成功确认边界须由相应 Adapter 明确；未实现该保证前 SMB 为只读。

## 场景

### 产品服务伪造身份或滥用真实会话

- Given：攻击者有产品服务的全部文件权限和一个真实管理员产品会话。
- When：修改旧 control.db、调用重置/授权接口，或直接调用相册清空、快照删除、容器卸载接口。
- Then：不能产生可信身份或敏感授权；普通会话可以改变被允许的活动视图，但不能销毁任何仍受保护的版本。已有身份缺口与真实会话滥用分别验收。

### 删除、覆盖后继续等待或洪泛

- Given：文件及相册、音乐等元数据已受保护提交。
- When：覆盖全部文件，删除照片和标签，清空回收站，产生大量新版本并持续等待。
- Then：原受保护版本及其引用仍能从可信入口恢复；达到容量、版本或任务预算时拒绝后续写入，不能为满足攻击者的新请求而回收旧保护版本。

### 上传仍持有写描述符

- Given：产品服务持有暂存文件的可写 FD。
- When：提交完成后继续用该 FD 写入、截断或替换暂存路径。
- Then：已确认版本不受影响；暂存 inode 不能以硬链接直接成为受保护原件。提交采用独立不可变对象或等价隔离机制。

### 系统盘丢失或产品数据库被改写

- Given：产品服务的数据库全部被删除；另在可丢弃设备中模拟系统盘重建。
- When：使用离线恢复材料及数据卷上的受保护恢复集恢复。
- Then：可还原文件、照片、标签、歌单和应用数据，UserID/UID/文件 ID/照片 ID 的对应关系保持；会话默认撤销。产品服务及其 files.db、storage.db 不是恢复的必需权威。

### 保护不可用或空间不足

- When：保护写入、校验、配额、持久化或恢复索引不可用，或攻击者用尽活动区/暂存区预算。
- Then：修改前失败关闭，不确认新的成功写入；已有保护版本不删除。保护服务保有独立的元数据与恢复工作空间预算，故障不能触发在系统盘另建用户数据空间。

### 销毁受保护版本

- Given：管理员从独立认证、独立程序提供的可信管理入口操作。
- When：确认列明资源、版本、后果及计划摘要的销毁请求。
- Then：产生短期、单次、绑定目标与版本的授权；执行器校验并在持久日志中消费。变更目标、重复提交、过期或仅持产品会话均失败。批量销毁必须明确列出范围与数量，不提供任意未来版本的通配授权。

## 边界与失败

- “清空回收站”只清除活动视图；受保护历史单独展示、恢复和销毁。原先的 15 天回收站、每日 14 份定时快照不能作为安全保护的淘汰规则。
- 首版不按时间、数量或磁盘压力自动销毁受保护版本。人工可信授权可以释放指定旧版本；自动精简只删除可证明字节、用户元数据与引用完全等价的冗余表示，并保留版本身份的恢复映射。
- 格式化、擦盘、移除最后恢复副本、缩短保护范围、删除恢复密钥、改变身份归属、账号接管和授予应用写挂载均为敏感操作。删除产品账号本身不删除其保护数据。
- 共享文件夹、Samba、Web 终端、SSH 用户、容器挂载和长期可写 FD 不能形成未保护写路径。首版未通过资格验收的入口只读或停用；产品服务启动 Shell 或改变容器挂载的能力必须撤销。
- 第三方应用只承诺恢复一致性级别已标注的持久化数据；需要应用一致性时必须有经验证的冻结/备份 Adapter。不能从“容器目录快照成功”推导数据库应用一致。
- 普通读取与快照恢复同样在可信端按权限授权，不能以加强恢复为由向产品服务暴露其他成员的内容。

## 验收证据

此处定义待实现门禁，不表示已经通过：身份伪造、真实会话破坏、写 FD 延迟变更、SMB/终端/容器绕过、原件与用户元数据恢复、崩溃与重放、容量洪泛及跨版本升级，均按[实施方案的验收矩阵](../architecture/compromised-product-data-protection.md#验收矩阵)在可丢弃环境验证。
