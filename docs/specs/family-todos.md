# 家庭待办

状态：implemented
更新时间：2026-11-25

## 目标

家里要办的事（缴费、复查、续保、换证）记在 NAS 上，全家都能看到，谁都能处理；快到截止日时，提醒能看到它的每个人。

这是待办的第一步，只做三块：手工新建、桌面上的“待办”窗口、到期提醒。待办是 A-NAS 本体的能力，范围按来源分，虚拟伙伴以后只读汇总；先做这一步，不等单据识别（[决定](../decisions/2026-11-16-family-todos-first-step.md)，[#503](https://github.com/zhongwater123/A-NAS/issues/503)）。待办由家庭服务持有，按“共享 / 本人”授权，不按家人授权（[ADR 0029](../adr/0029-keep-the-baby-as-a-profile-and-channel-photos-in-the-shared-library.md) 决定 6）。

## 非目标

- 单据识别、邮件来的待办、水墨屏设备、虚拟伙伴读汇总、本地控制台上的整屏待办画面、手机推送：#503 的后续步骤。
- 只给自己看的待办：第一步手工新建的一律是共享待办，界面上没有“只我自己”。
- “待确认”状态与“请确认”这一档、来路不明发件人的提示、“夜里不推送”：前两者只对识别来的事有用；网页只在打开时提示，没有推送通道。
- 删除待办（用“忽略”代替）、建好后改范围。
- 把 VNAS 的“提醒我……”接进待办：它仍是 AI 助手的定时任务（[AI 助手](ai-assistant.md)）。
- 新的服务、系统账号、systemd 单元或存储。

## 本稿补充的默认规则

以下规则让实现和验收可以执行，2026-11-24 已定为全部保留（[决定记录](../decisions/2026-11-17-family-todos-default-rules.md)）。

### 一件待办

- 标题必填，1–10 个字，按字数算。这是原型给以后上水墨屏留的长度；输入框下只写已填的字数，如“4/10 个字”。
- 类别六种：账单、医疗、保险、证件、合同、其他，不选就是其他。类别只决定界面上写的动作：缴费、复查、续保、换证、续约、办理。
- 截止日可选，只到日（YYYY-MM-DD），按 NAS 的本地日历日算；不填就不提醒。
- “谁的”可选：一个在用账号，或者不选（算全家）。只用于显示，不决定谁能看。下拉里只列在用账号（`GET /api/v1/todos/owners`），停用和等待删除的不列；编辑一件已经是某个停用账号的待办时，这个账号照旧留在下拉里、保持选中。
- 金额可选，只记人民币，按分存；输入框按元填，最多两位小数；显示用 `Intl.NumberFormat` 的人民币格式，如“¥1,234.50”。
- 已处理、已忽略的在窗口的“最近处理”里留 30 天，之后不再列出。
- 推迟 1–30 天，从今天算；界面上给 1、3、7 天。已处理、已忽略的不能推迟。
- 已处理、已忽略的仍可以编辑。

### 处理与重新打开

- 标为已处理或忽略时，记下关闭人和关闭时间，并清掉推迟。
- 设成它已有的状态什么都不改，保留第一次的关闭人，与[问题反馈](feedback.md#边界与失败)重复标记已处理时相同。
- 已处理与已忽略互换时，记下新的关闭人和时间。
- 重新打开清掉推迟和关闭信息。

### 提醒

- 三档：快到了（截止前 1–3 天）、今天（截止当天）、过期（截止日已过）。每档只提醒一次，所以一件事最多提醒三次；新建时离截止已不到 3 天的，从当时所在的那一档开始。
- 已处理、已忽略、推迟中、没有截止日的不提醒。
- 推迟、重新打开、改截止日以后从头算，之前点过的“知道了”不再算；推迟到的那天起重新提醒。改截止日和重新打开一样清掉推迟：新的截止日当天就按它所在的档提醒，不等推迟结束。
- “知道了”按人记：A 点了，B 照样会被提醒。
- 只有本人点“知道了”才算看过。提示自动隐藏、点关闭、点“去看看”都只在这一页藏起来。
- 点“知道了”时只记下此刻还该提醒本人的那几条，其余的忽略，所以刚被别人处理掉的那条不会报错。

## 场景

### 新建一件待办，全家都能看到

- Given：账号 A、B，以及没有加入家庭中心的账号 C。
- When：A 在待办窗口点“新建”，填“交电费”，类别选账单，填截止日和金额 235.6 元，保存。
- Then：
  - 这一条出现在 A 的“待处理”里，显示“缴费”、截止日文案与“¥235.60”；
  - B、C 打开待办窗口也看到它，都能编辑、处理、推迟；
  - A 的活动记录多一条 `family.todo_added`。

### 重复提交

- Given：A 点了“保存”，请求超时后页面自动重试。
- When：服务端收到同一账号、同一请求键的第二次新建。
- Then：返回第一次建的那一条，状态码与第一次相同，列表里只有一条。

### 到期提醒，每档一次，按人记

- Given：一件共享待办 3 天后截止，A、B 都登录了桌面。
- When：两人的桌面读取提醒。
- Then：
  - 两人右上角都出现“交电费 还有 3 天”；
  - A 点“知道了”后，刷新页面不再出现；B 没点，刷新后仍然出现；
  - 到了截止当天，两人各自再收到一次“今天截止”；过了截止日，再收到一次“已过期 1 天”。

### 不点“知道了”，下次还会出现

- Given：B 的桌面上有待办提醒。
- When：提示自动隐藏，或 B 点了关闭，或点了“去看看”。
- Then：
  - 这一页里提示不再出现，刷新页面或下次登录时还在，直到 B 点“知道了”；
  - 鼠标指着提示或焦点在提示上时，它不自动隐藏；
  - “去看看”打开待办窗口，滚动到这一条并高亮。

### 推迟

- Given：一件待处理的待办，截止日在明天。
- When：B 在这一条的“更多操作”里选“推迟 7 天”。
- Then：
  - 它移到“推迟中”，写明推迟到哪天，这期间谁都不会收到它的提醒；
  - 到了那天它回到“待处理”，从所在的那一档重新提醒，之前点过的“知道了”不再算。

### 改截止日或重新打开

- Given：A 已经点过一件待办“今天截止”的“知道了”。
- When：有人把截止日改到后天；或者把一件已处理的待办重新打开；或者这件待办正推迟着，有人改了它的截止日。
- Then：提醒从头算，推迟清掉，A 会再收到当前那一档的提醒。

### 不提醒的待办

- Given：一件已处理、一件已忽略、一件没有截止日的待办。
- Then：它们都不出现在提醒里；没有截止日的排在“待处理”的最后。

### 处理与重新打开

- Given：一件待处理的待办。
- When：A 标为已处理，之后 B 也标为已处理，再之后 B 选“重新打开”。
- Then：
  - A 标完，它移到“最近处理”，显示“A 已处理”和时间；
  - B 再标已处理时什么都不变，仍显示 A；
  - 重新打开后它回到“待处理”，关闭信息清掉。

### 两人同时编辑

- Given：A、B 同时打开同一条的编辑框，B 先保存。
- When：A 保存。
- Then：A 的保存被拒绝（`409 changed`），窗口提示“别人刚改过这件事，已刷新，请再改一次”，显示 B 保存后的内容。

### 本地控制台上的医疗类待办

- Given：一件医疗类待办“儿保复查”今天截止。
- When：宿主机的本地控制台（全家共用的屏幕）上弹出待办提醒。
- Then：这一行写“一件医疗的事 今天截止”，只显示类别，不显示标题；在本地控制台上打开待办窗口时照常显示标题，因为那是有人主动打开的。别的浏览器上的提醒照常显示标题。

### 删除账号以后

- Given：alice 建了一件共享待办，“谁的”是她，后来由她标为已处理。
- When：alice 的账号到期删除（[重新启用与删除账号](account-enable-and-delete.md)）。
- Then：这件待办保留；关的人与“谁的”显示原名字 alice，接口里建的人（`createdByName`）也是原名字，不会算到之后同名的新账号头上。

## 边界与失败

- **谁能看、谁能改**：所有有效账号都能使用待办，不要求加入家庭中心；“全家”就是所有有效账号，因为 NAS 的账号就是家人（[ADR 0029](../adr/0029-keep-the-baby-as-a-profile-and-channel-photos-in-the-shared-library.md) 决定 3），与[共享空间](../../CONTEXT.md)、问题反馈的范围相同。设备管理员没有额外权限。
- **只给本人看的待办**：表里留着“给谁看”的字段，为以后邮件、个人空间来的待办准备。字段为空的是共享待办；不为空的只有那个账号能看、能改。读和写都只认这两种，别人按 ID 请求一律得到 `404 not_found`，不暴露它存在。第一步新建的都是共享待办：新建请求里没有范围这个字段，返回的范围都是 `shared`。
- **校验**：标题、类别、日期（如 2026-02-30）、金额小于 0、推迟天数、“知道了”的提醒键格式不对时，返回 `422 validation_failed`。“谁的”必须是在用账号（查账号在开事务之前，`family.db` 只有一个连接，不让跨进程的查询占着它）；编辑时只有改了“谁的”才核对，原来的账号停用后这一条仍能编辑。
- **编辑**：编辑带读取时的版本号，对不上返回 `409 changed`；编辑时没给的字段一律清空。改状态与推迟不改版本号，不会让别人正在进行的编辑失效。推迟已处理或已忽略的返回 `409 conflict`。
- **日期**：“今天”按 NAS 的本地日历日算，推迟到哪天由服务端算。浏览器在别的时区时，窗口里显示的天数可能和提醒的档位差一天。
- **提醒何时读取**：登录后读一次，页面回到前台时读，并在本地次日零点过几分钟再读一次，以便跨天进入新的一档（本地控制台的页面一直在前台）；本地控制台上屏保或黑屏被唤醒时也再读一次，并重新显示这一页里藏起来、还没点“知道了”的提醒。打开着的待办窗口也在次日零点过几分钟重读。桌面提示与待办窗口共用一份提醒，在一处点了“知道了”，另一处同时去掉。不另设定时轮询（[Web 桌面的数据获取](../architecture/web-desktop.md#数据获取)）。
- **提醒的样子**：
  - 文案只有三种：快到了写“还有 N 天”，当天写“今天截止”，过期写“已过期 N 天”；窗口里每条待办的截止日也这样写。
  - 桌面提示在右上角，最多三行，多出的写“另有 N 件”；和家庭中心的疫苗提示、AI 助手的任务提示同时出现时上下排开，互不遮挡。
  - 提示是读屏软件会读出的状态区域，并且和桌面上的其他提示一样，VNAS 看桌面画面时跳过它。
- **窗口**：自上而下是“要提醒的”（每条带“知道了”）、“待处理”（最急的在上，3 天内到期或已过期的用危险色标出）、“推迟中”与“最近处理”；什么都没有时写“都处理完了”。窗口变窄时，截止日与操作移到标题下一行，不出现横向滚动。
- **数据卷**：待办存在数据卷上家庭服务的 `family.db` 中。数据卷离线时窗口显示“待办暂时不可用（数据盘未就绪），请稍后再试”；桌面提醒读取失败时不显示错误，保留这个账号已显示的提示（会话失效即 `401` 时清空；换了账号登录，上一个账号读到的一律不显示），接口返回 `503 family_unavailable`，不在系统盘暂存。
- **活动记录**：新建、编辑、标为已处理、忽略、重新打开、推迟分别记为 `family.todo_added`、`family.todo_updated`、`family.todo_done`、`family.todo_ignored`、`family.todo_reopened`、`family.todo_snoozed`，资源类型是 `todo`，详细信息是标题；按 `family.` 前缀归入[日志](logs.md)的“家庭中心”类别，只给操作者本人看；保留期与家庭中心相同。点“知道了”不记。
- **账号删除**：只给她看的待办随账号删除（第一步还没有这种待办），她点过的“知道了”也删掉；共享待办保留。待办关闭超过 30 天后，每个人对它点过的“知道了”在家庭服务定期清理回收站时一并删掉；读提醒时只查当前要提醒的那几条键。建的人、关的人与“谁的”都存账号 ID 和当时的名字，查不到账号时显示记下的名字（[重新启用与删除账号](account-enable-and-delete.md#边界与失败)）。
- **退回旧版本会丢掉待办**：待办表是 `family.db` 的第 4 步迁移。退回没有待办的版本时，旧版本打开数据库会执行这一步的反向步骤，删掉待办表与待办的“知道了”记录，待办全部丢失；要找回，只能用升级前的数据库备份恢复（[ADR 0034](../adr/0034-release-as-signed-debian-packages-and-update-devices-with-sysupdate.md) 决定 4 的迁移一项）。

## 原型规则的对应

原型的规则见 #503，这里只记要点与 A-NAS 的写法：

- **规则 21（共享与个人的范围）**：按来源分。共享空间里的事全家都能看，个人邮箱、个人空间来的事只有本人能看；全家共用的屏幕上不显示个人的事。第一步没有来源，手工新建的都是共享。
- **规则 5（健康类遮蔽）**：原型写“一份健康文件请查看”；A-NAS 在全家共用的屏幕（本地控制台）上医疗类只显示类别，写“一件医疗的事”。
- **规则 22（手工新建）**：只有标题必填，最多 10 个字；截止日、谁的、金额都可以不填；手工新建的一律算全家。A-NAS 的“谁的”存账号 ID 与名字，原型只存名字。
- **规则 23（分档提醒）**：快到了、今天、过期，每档只提醒一次；点了“知道了”才算看过；推迟、重新打开、改截止日以后从头算。原型的“知道了”全家一份，A-NAS 按人记。

## 验收证据

- Go 存储测试：
  - 共享待办 A、B 与没加入家庭中心的 C 都能读写；只给本人看的待办别人列不出来，按 ID 编辑、改状态、推迟都是“不存在”；
  - 字段校验（标题为空或 11 个字、未知类别、2026-13-01、停用的账号、金额 -1）；
  - 处理、忽略、重新打开与关闭人，已关闭的再推迟被拒绝，关闭超过 30 天的不再列出；
  - 版本冲突与重复的请求键；
  - 提醒档位的表驱动测试（离截止 4、3、1、0、-1 天，已处理、已忽略、推迟中、推迟到期当天、没有截止日），“知道了”按人记，换档、推迟、重新打开、改截止日后重新提醒，确认时忽略不在当前提醒里的键；
  - 账号删除后只给她看的待办与她的“知道了”没了，共享待办留着原名字；
  - 迁移的反向步骤由现有的可逆性测试检查。
- 接口：`internal/httpapi` 的 OpenAPI 契约测试以三个账号走遍八个操作，每个至少一次 2xx，另有 `404`（不存在的 ID；别人只给本人看的待办由存储测试覆盖）、`409 changed`、`409 conflict` 与 `422`（契约允许、服务端拒绝的请求，如不存在的账号或 2026-02-30）；外壳契约测试覆盖读取提醒。
- Web 测试：截止日与提醒文案的纯函数（还有 N 天、今天截止、已过期 N 天，跨年，本地控制台上医疗类只写类别）；待办窗口的新建（带请求键、没有范围字段）、处理、忽略、推迟 7 天、编辑冲突、重新打开、已处理的原地编辑、提醒栏的“知道了”与定位；桌面提示只在点“知道了”时提交，自动隐藏、关闭、“去看看”都不提交，本地控制台被唤醒时重新显示；外壳上有“打开待办”。
- Fake 预览中的浏览器检查：管理员建 4 条（今天、后天、昨天截止的，以及一条医疗类）；成员不加入家庭中心也能看到并收到提醒；点“知道了”后刷新不再出现，只自动隐藏的刷新后还在；推迟或改截止日后提醒重新出现；同时有疫苗提示和待办提示时互不遮挡；手机宽度下的窗口。
