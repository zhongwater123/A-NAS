# 语音处理

状态：implemented（本地开发机验证，尚未合并、未部署）
更新时间：2026-10-21

## 目标

成员把会议、课堂、访谈、通话或语音备忘的录音交给 Web 桌面的“语音处理”，后台完成四件事：

1. **转写**：豆包语音的录音文件识别（标准版，模型 2.0）把说话变成带时间、标点的文字，并分开不同的说话人。
2. **认出发言人**：在本机计算每位发言人的声纹，与成员命名过的人比对；同一个人在以后的录音里自动标出名字，声音拿不准时先问成员。
3. **翻译**：逐句译成 15 种语言之一，与原文对照。
4. **按场景总结**：按会议纪要、课堂笔记、访谈记录等模板整理要点、结论和待办。

翻译与总结沿用 AI 助手（VNAS）的文本模型（DeepSeek），经助手的模型网关访问，网关持有密钥。

## 非目标

- 不做实时转写（边录边转）、不录音；录音由手机或录音笔录好后导入。
- 不移动、复制或改写录音文件；导入只登记文件，删除只删除语音处理里的结果。
- 不跨成员共享转写、发言人或声纹；共享空间里的同一个文件，每个成员各自导入、各自命名。
- 不提供“本地 ASR”或“本地文本模型”的选项：转写只接豆包语音，翻译与总结只用 VNAS 的模型。声纹始终在本机。
- 不按说话人合并或拆分之外的方式编辑发言（例如把一句拆成两句）。

## 结构

- **左栏**：“导入录音”、搜索（标题、文件名、发言人、内容预览），录音列表（标题、导入时间、时长、状态或发言人数、总结概述的开头、认出的人），底部“发言人与声纹”“服务与设置”。上传中的文件以占位卡片列在最前。
- **右栏的录音**：标题（点击改名）、导入时间、时长、发言人数和文件名；导出与“从语音处理中移除”。播放条的进度轨按每句话的时间与发言人着色，可拖动、前进后退 15 秒、调整倍速；文件浏览器不能播放（例如 AMR、WMA）时由媒体 Worker 解码播放，拖动时从新位置重新解码。发言人条列出每位发言人及其说话时长占比，按声纹认出的标“声纹”，接近某人但不确定的标“可能是 XX？”。
- **转写**：按发言轮次分段，每段是发言人的圆标、名字、开始时间与句子；点击句子从那里播放，正在播放的句子高亮并可跟随滚动；双击修改文字；右键菜单“从这里播放”“修改文字”“复制这句”“这句是谁说的”。可在转写中查找。
- **翻译**：已有译文的语言标签与“翻译成…”；对照（原文在上、译文在下）或仅译文；导出 TXT、SRT；删除。
- **总结**：已有总结的场景标签与“其他场景”；标题、关键词、概述、模板的各栏目、待办（负责人与期限）；以 `mm:ss` 开头的条目可点击播放；复制或导出为 Markdown、重新总结、删除。
- **发言人与声纹**：成员命名过的每个人：声纹来自几段发言、出现在几段录音、一共说了多久、最近的录音；改名、合并、删除。
- **服务与设置**：语音识别、翻译与总结、声纹、音频转换四部分是否可用以及在云端还是本机；管理员在这里填写、测试和清除豆包语音的密钥。

## 场景

### 从电脑导入

- Given：成员已登录，个人空间可写。
- When：点“导入录音”，选择或拖入音频（也可以直接把文件拖进窗口），选择场景模板、录音语言、是否同时翻译与容易听错的词，点“开始处理”。
- Then：文件经传输中心的分片上传进入个人空间的“录音”文件夹（没有时创建，同名时保留两者），每个文件传完即导入并排队处理；关闭语音处理窗口不影响上传和导入，传输中心里能看到这批上传。刷新页面后，尚未传完的文件仍由传输中心续传，但传完后需要从“NAS 上的文件”导入。

### 从 NAS 导入

- Given：个人空间或共享空间里已有录音。
- When：在导入对话框选“NAS 上的文件”，浏览空间与文件夹，勾选一个或多个音频文件。
- Then：文件留在原处并按稳定文件 ID 登记；之后改名或移动仍能找到。同一成员不能重复导入同一个文件（`already_imported`），没有声音的文件（`not_audio`）或超过 5 小时的录音（`too_long`）被拒绝。任何能读到的文件都可以导入，包括带声音的视频。

### 后台处理

- Given：录音已导入。
- When：后台依次处理排队的录音，一次一段。
- Then：录音显示“准备音频 → 识别文字 → 识别发言人”的进度，可以关闭窗口。媒体 Worker 把录音转成 16 kHz 单声道 Opus，放进管理员设置的 TOS 存储桶，把签名链接作为一个识别任务交给豆包语音（开启说话人分离、标点与数字规范化，传入成员的热词和已命名的人名），之后定时查询结果，任务结束即删除桶里的录音；每位发言人算一个声纹。豆包语音排队时“识别文字”会停留较久；产品服务重启后继续查询同一任务，不重新提交。完成后发言人按第一次开口的顺序编号为“发言人 1、2…”，按声纹认出的直接显示名字；导入时选了场景或翻译语言的，总结和翻译随即开始。没有识别到说话的录音完成后显示“没有识别到说话”。

### 命名发言人，以后自动认出

- Given：一段录音已完成，发言人 1 是“张伟”。
- When：成员点击“发言人 1”，输入“张伟”（或从已有的人中选择）。
- Then：这段录音里的发言人 1 显示为张伟；张伟的声纹记住了这段发言，成员其他录音里声音足够接近的发言人随即显示为张伟并标“声纹”，接近但不够确定的显示“可能是 张伟？”。之后导入的录音在处理时直接认出。说话太少、没有声纹的发言人只在这段录音里改名，不教声纹。

### 确认或否定建议

- Given：发言人标着“可能是 李四？”或按声纹显示为李四。
- When：成员在发言人菜单中点“是 TA”，或点“不是”“不是李四”。
- Then：“是 TA”等同命名为李四；“不是”撤掉名字或建议，之后这位发言人不再被认成李四，可以再给出次接近的人的建议。

### 合并两位发言人、改句子的发言人

- Given：识别服务把同一个人分成了两位，或把一句话归错了人。
- When：在发言人菜单里选“和另一位是同一个人”，或在句子的右键菜单里选另一位发言人。
- Then：合并后只剩一位，名字保留被并入的一方的（成员命名的优先），声纹按两者的说话时长合并；改归属只影响那一句。两者都使已有总结显示“转写或发言人改过了”。

### 修改转写

- Given：识别结果有错字。
- When：双击句子修改并按回车。
- Then：句子保存并标为已修改；已有翻译显示“转写在翻译之后修改过”，已有总结显示需要重新总结，可一键重新生成。

### 翻译

- Given：转写已完成，这台 NAS 接入了 VNAS 的文本模型。
- When：在“翻译”中选择语言（或导入时选“同时翻译成”）。
- Then：译文每 40 句一批生成并显示进度；完成后逐句与原文对照，可只看译文、导出 TXT 或 SRT。模型漏掉的句子保留原文；某一批两次都失败时整份翻译失败，可重试。

### 按场景总结

- Given：转写已完成。
- When：选择场景模板：通用摘要、会议纪要、课堂笔记、访谈记录、通话摘要、讲座 · 播客或语音备忘。
- Then：模型按模板的栏目输出标题、概述、各栏目条目、待办（负责人与期限，录音中没提到则留空）与关键词，只依据转写；发言人有名字时用名字。超过约 4 万字的转写分段整理后再合并。导入时所选模板的第一份总结的标题成为录音标题，除非成员已改过标题。同一段录音可以有多个场景的总结。

### 导出

- Given：录音已完成。
- When：在标题栏导出转写，或在翻译、总结页导出。
- Then：转写可导出为纯文本（按发言轮次）、Markdown 或 SRT 字幕（每句一条，带发言人）；译文为 TXT 或 SRT；总结为 Markdown（待办为任务列表）。文件在浏览器中生成，不经过 NAS。

### 配置豆包语音与录音中转

- Given：管理员已在火山引擎开通“豆包语音 · 录音文件识别 2.0”（资源 `volc.seedasr.auc`）和对象存储 TOS，建好一个存储桶，并有一组能在桶里写入和删除的 Access Key（建议子账号）。
- When：在“服务与设置”中选择新版控制台的 API Key，或旧版控制台的 APP ID 与 Access Token，再选 TOS 的地域、填写存储桶、Access Key ID 与 Secret Access Key，点“测试并保存”。
- Then：A-NAS 把一秒钟的静音放进存储桶并提交识别，等最多 20 秒：豆包语音回答静音，或接受了任务但仍在排队，才保存，等待密钥的录音随即开始；测试文件随后删除。存储桶拒绝时提示检查地域、桶名与 Access Key，豆包语音拒绝时提示检查密钥与是否开通了 2.0。之后页面只显示密钥与 Access Key 的最后 4 位、地域、桶名与设置人；“测试已保存的设置”“清除”可随时使用，修改任何一项都要重新填写全部密钥。成员看到各部分的状态，但看不到也改不了这些设置。

## 边界与失败

- **授权**：录音文件只经文件服务以成员本人身份读取（生产中由文件代理以其 Linux 身份读取，[ADR 0008](../adr/0008-use-unified-linux-identities-and-filesystem-acls.md)），导入时与每次处理、播放时都重新检查；成员只能导入、看到和操作自己的录音与人。后台处理借用成员最近的有效会话；产品服务重启后成员尚未登录过时，录音显示“等待你登录”，登录后约 30 秒内继续。
- **离开设备的数据**：录音（转成 Opus 后）上传到管理员的 TOS 存储桶，在识别结束前留在那里，由豆包语音（火山引擎）凭 24 小时有效的签名链接下载；任务结束（完成、失败或录音被移除）后 A-NAS 删除它，设备意外中断留下的由桶的生命周期规则清理（设置页建议为 `a-nas-voice/` 设 1 天过期）；转写文字、发言人名字和录音标题发送给 VNAS 的文本模型。声纹在声纹 Worker 中计算，只保存在 `voice.db`，从不发送（[ADR 0027](../adr/0027-transcribe-in-the-cloud-and-keep-voiceprints-on-the-device.md)）。导入对话框和设置页写明这些。
- **声纹的范围**：每个成员的人与声纹只在自己的录音间比对，不跨成员；删除一个人会忘记其声纹，删除一段录音会忘记这段录音教给声纹的发言。声纹模型更换后，旧录音的声纹不再参与比对（需要重新处理录音）。
- **认出的阈值**：声纹模型为 3D-Speaker 的 CAM++ 中英文版。两段发言的声纹相似度不低于 0.74 时自动显示名字，0.60 到 0.74 之间只给出“可能是”；录音分段识别时（目前一段录音就是一个识别任务，不分段），两段的发言人相似度不低于 0.70 时合为一人。阈值的依据与误认率见[声纹评估](../research/voiceprint-evaluation.md)。
- **识别服务没有分开说话人时**：声纹 Worker 把长于 1 秒的句子按声音聚类（余弦距离 0.5），更短的句子归给时间上最近的那一类。
- **组件缺失**：没有配置豆包语音或存储桶时录音等待（`recognizer`），配置后自动开始；豆包语音或 TOS 繁忙、连不上，或超过半小时的提交上限时，提交先重试两次（15 秒、1 分钟后），查询连续失败 10 次，都转为等待下一次轮询（`busy`），已提交的任务保留；密钥或存储桶被拒绝（`recognizer_rejected`）、文件丢失（`file_missing`）或不是音频（`not_audio`）时失败，可在修正后“重新处理”。豆包语音不再认得的任务重新提交一次；提交一天后仍没有结果判为识别失败（`recognizer_failed`）。其他意外错误重试 3 次后失败。没有声纹 Worker 时转写照常完成，发言人只按识别服务分开、不跨录音认出，页面标“未使用声纹”。没有文本模型时翻译与总结不可用，转写不受影响。
- **限制**：单段录音最长 5 小时，作为一个识别任务提交（至多约 54 MB Opus，服务上限 512 MB）；热词最多 100 个、每个 30 字以内；人名 40 字以内；标题 120 字以内；单句 4000 字以内。一次只处理一段录音，一次只运行一个翻译或总结。
- **数据**：结果在产品服务状态目录（系统盘）的 `voice.db` 中，转写、译文和总结可以重新生成；发言人名字、人与声纹、对转写的修改、豆包语音的密钥与存储桶设置是用户数据；`recognition_tasks` 记着已提交、尚未取回结果的任务。录音从语音处理中移除时，这些一起删除，录音文件保留。

## 验收证据

- Go：[语音处理测试](../../internal/voice/voice_test.go) 用替身的识别服务、媒体 Worker 与声纹覆盖导入、处理、热词去重、发言人编号与说话时长、按模板的总结与录音改名、逐句翻译与修订号、成员隔离、命名后在其他录音和新录音中认出、“不是”、删除人与录音后忘记声纹、改名冲突与合并、修改句子与合并发言人使结果过期、等待登录与等待密钥后继续、密钥被拒绝后重新处理、重启后继续查询同一任务、服务不认得的任务重新提交一次、移除录音时删除中转的录音、长录音分段与跨段合并发言人、没有说话人标签时聚类、没有声纹 Worker 时照常完成、拒绝不能处理的文件，以及管理员才能设置且不回显的密钥与存储桶；同一文件用 HTTP 替身覆盖豆包语音标准版的提交与查询（新旧控制台的鉴权头、签名链接、音频格式、按时长与场景选择的说话人分离、热词）与状态码（处理中、排队、静音、密钥无效、繁忙、提交上限、格式错误、任务不存在），用本地 HTTP 服务覆盖 TOS SDK 的上传、签名链接下载、删除与拒绝，连接测试的成功、排队与存储桶被拒，以及经 Unix 套接字访问模型网关。[HTTP 测试](../../internal/httpapi/voice_test.go) 覆盖未登录、缺少 CSRF、其他成员读不到录音、成员读不到密钥设置；[OpenAPI 契约测试](../../internal/httpapi/openapi_test.go) 的 35 个用例对照 [OpenAPI](../../api/openapi.yaml) 校验每个接口的请求与响应。
- 媒体 Worker：[测试](../../internal/mediaworker/worker_test.go) 覆盖 `speech` 请求的范围校验与 FFmpeg 参数；`TestRealFFmpegSpeech` 在 Debian 13 与 FFmpeg 7.1 的容器中把立体声 AAC 解码为 16 kHz 单声道样本与 Ogg Opus。
- 声纹 Worker：[Python 测试](../../ai/tests/test_voice.py) 用替身模型覆盖分组向量、聚类、输入校验与释放；[协议测试](../../internal/voiceworker/python_test.go) 让 Go 客户端与 Python Worker 交换样本描述符与向量。
- 前端：[窗口测试](../../web/src/voice/VoicePanel.test.tsx) 覆盖打开第一段录音、发言人与建议、转写分段、总结与可播放的时间、命名发言人、请求翻译、等待密钥的说明、空状态，以及 SRT 与 Markdown 导出。
- 浏览器检查：Fake 模式本地栈（Debian 13 + FFmpeg 7.1 容器）中用 AISHELL-4 会议录音截取的 M4A、MP3、Ogg 检查了从 NAS 导入三段录音、处理进度、转写与跟随播放、播放条的发言人着色、命名发言人后其他两段录音自动认出、总结、翻译进度与对照、发言人与声纹页、服务与设置页，窗口 1500×900。
