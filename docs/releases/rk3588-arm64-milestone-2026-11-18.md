# RK3588 ARM64 实机部署里程碑

冻结日期：2026-11-18

## 里程碑结论

**A-NAS 已在一台 ATK-DLRK3588 上完成 ARM64 软件包安装、产品启动、管理员与数据卷创建，以及重启恢复验证。** 五寸屏开机进入 A-NAS，用户现场确认“点亮进入了”。这使 ARM64 从编译和仿真候选进入可实机部署的开发基线。

这是指定板卡与固定制品的部署里程碑，不创建新的语义版本标签；完整产品验收、其他 ARM 板卡兼容性和性能承诺仍按下面的边界推进。

## 已验证的范围

公开记录中的设备 CID、序列号、卷 UUID 和一次性计划 ID 已脱敏，截图仅含账号和密码均为空的登录页；原始证据保存在本地封存目录。`board-config` 是部署过程的脱敏参考，不是可直接安装的配置；执行手册前必须从本地清单恢复真实身份约束并重新确认目标。

- 固定源码通过完整原生 `make check-steps`（与 `make check` 使用相同检查目标），包括 Web、Go 全包、静态检查、漏洞检查、AI 与 SDK；小屏 CSS 后续另通过格式、lint、类型、构建、浏览器布局及 ARM 嵌入资源检查，未冒充重跑完整门禁。
- ARM64 CGO 二进制、架构独立的运行环境身份、Python 哈希锁、上游清单和 Debian 依赖交付已形成；最终 24 包审计覆盖 202 个 AArch64 ELF、8 个模型和 8 个嵌套归档。全包 ARM 用户态仿真仍保留原始失败，限制与补测见[研究记录](../research/rk3588-deployment-feasibility-2026-11.md#最新主干与补齐后的内核)。
- 真机文件代理普通用户测试 45 项通过；实际成员 ACL 写入、Btrfs 只读快照与清理通过，未放宽既有数据权限。
- 同一 Qwen3.5-4B 权重在正式 Worker 的原有 cgroup 和沙箱中完成两次票据请求。精度、耗时、内存与并发边界以[正式 Worker 实测](../research/rk3588-deployment-feasibility-2026-11.md#正式-worker-的-4b-实测)为准，不将“可运行”写成性能或质量验收通过。
- 正常重启后，API、Host Agent、相册、分享、家庭与 kiosk 均 active，Host Agent `NRestarts=0`；管理员初始化状态保留，数据卷自动挂载，ADB 自动恢复，重建主机转发后 HTTP 200。
- 本次镜像激活先完成全盘备份与独立 recovery 启动验证，再按受身份保护的步骤写入；原 GPT、loader、uboot 和 recovery 保留。恢复范围与摘要见[内核和系统部署手册](../runbooks/build-rk3588-kernel.md)。

## 必须保留的失败与限制

首次开机图形因 Mali 节点和显存分配节点权限不足失败；首次无网线重启又暴露 `/run/samba` 缺失，使 Host Agent 的 namespace 创建失败。二者已在本板修复并完成重启回归，首轮失败未删除。截图采集输出 PNG 后触及时间限制的退出值也保留，后用 ffprobe 和目视核验有效 PNG，并独立完成服务结果断言。

- **网络**：当前没有有线地址，产品健康检查仅余 `unit:smbd.service`；还没有完成真实局域网 Web/SMB 端到端验收。
- **输入**：用户确认已进入画面；物理触控坐标、最终安装方向、无外接键盘的文字输入仍未验收。
- **AI 与媒体**：中文证件/票据完整精度、生产核对流程、并发和长期负载，GPU/NPU 加速、MPP 硬解以及各应用的完整体验仍需实测。
- **发行**：本板显示、USB、常开和离线运行目录修复是部署配置，未全部回写到封存的原始 rootfs 或通用产品包；正式 ARM 签名源、整机更新和其他板卡部署不在本次通过范围内。不能直接重刷旧 rootfs 后省略手册中的本机配置。
- **厂商单元**：`bootanim.service` 和 `rkaiq_3A.service` 另有失败；本次未将它们写为已修复，也未停用它们来凑全绿。
