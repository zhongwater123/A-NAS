# 0017：影视中心经文件代理读取媒体，FFmpeg 在隔离 Worker 中运行

状态：proposed（2026-10-10，随影视中心 PR 提交评审）；行为见[影视中心规格](../specs/media-center.md)，实现见[影视中心技术设计](../architecture/media-center.md)。

影视中心要读取用户放在个人空间和共享空间里的视频，而这些文件只由数据卷 POSIX ACL 授权、以登录者本人身份访问（[ADR 0008](0008-use-unified-linux-identities-and-filesystem-acls.md)），产品服务账号 `a-nas` 不在任何 ACL 中。同时，扫描、截图与转码需要用 FFmpeg 解析来自任何人的媒体文件，这是历史上漏洞最多的一类代码。我们决定：影视中心作为产品服务内的模块，只经文件代理以某个有效会话的用户身份读取文件；FFmpeg 只在一个没有网络、看不到数据卷和产品服务状态、按连接启动的动态身份 Worker 中运行，只接收只读文件描述符。

## 决定

1. **不新增数据卷身份**：影视中心不像相册那样拥有存储（[ADR 0011](0011-run-the-photo-library-as-a-dedicated-service-identity.md)），视频始终是普通文件，用户继续用文件管理和 SMB 整理。媒体库只引用文件目录中的稳定文件 ID；所有读取都经 `files.Service` 与文件代理，以请求者或后台会话的用户身份打开，内核按 ACL 决定能否读取。
2. **可见性由空间决定**：共享空间的媒体库对所有有效账号可见（共享空间对全体账号可读），个人空间的媒体库只对所有者可见。这与空间的读权限一致，因此影视中心不引入新的授权规则；管理员查看模式不扩展到媒体库。共享空间媒体库的管理只对管理员开放，避免成员改变所有人看到的内容。
3. **后台任务借用有效会话**：扫描、探测与截图沿用目录对账的做法（[存储与文件架构](../architecture/storage-and-files.md#身份与一致性)），只为本进程见过且仍有效的会话执行：个人空间用所有者的会话，共享空间用任一有效会话。没有会话的媒体库等到下次登录。
4. **FFmpeg 隔离运行**：`anas-media.socket` 以 `Accept=yes` 为每个连接启动一个 `anas-media@.service` 实例：动态身份、`PrivateNetwork=yes`、只允许 Unix 套接字、看不到 `/srv/a-nas` 与 `/var/lib/a-nas`。产品服务把以用户身份打开的只读描述符随请求传入，Worker 只接受类型化的请求（探测、截图、字幕、按起点与画质转码），自己拼装 FFmpeg 参数，从不接受路径或任意参数。被恶意文件攻破的 FFmpeg 只能读到这一个文件描述符。
5. **派生数据放在系统盘**：目录、进度、收藏和合集保存在产品服务状态目录的 `media.db`；海报缩略图、截图和字幕缓存放在同一目录的 `media-cache`，可以删除并重建。读取它们时按第 2 条的可见性判定。

## 后果

- 不需要新的系统用户、子卷、ACL 或会话查询接口；安装器多装一个 `ffmpeg` 包、一个 socket 和一个模板服务。
- 长期没有人登录时，SMB 新放入的视频不会被扫描，直到有人打开影视中心；本地控制台常驻的会话通常让共享媒体库保持更新。
- 产品服务被攻破时，可以读到 `media-cache` 中私有视频的截图、海报缩略图和字幕，以及目录中的片名，但读不到视频本身；这比 ADR 0008 下只能看到文件名多暴露了派生画面。若要消除，需要把缓存写回用户空间或交给专用身份，代价见“未选择”。
- 每个请求都要经文件代理打开文件；播放时打开一次，之后由产品服务流式读取或交给 Worker，不经过 root。
- 共享空间中的只读共享文件夹不影响可见性，因为共享空间对全体账号可读；将来若引入只对部分人可读的共享文件夹，需要重新审视第 2 条。

## 未选择

- **影视中心专用身份并在媒体库文件夹上加只读 ACL**（Jellyfin 式）：后台任务不依赖会话，但给一个身份读取所有媒体库的能力，等于 ADR 0008 之外的第二套授权，并且 ACL 要随文件夹增删维护。
- **在产品服务进程内直接运行 FFmpeg**：实现最简单，但解析恶意文件的漏洞会直接拿到产品服务身份、会话库与全部目录。
- **在用户的文件 Worker 中运行 FFmpeg**：攻击者可以借此以文件所在空间读者的身份读写其全部文件。
- **把派生数据写回用户空间的隐藏目录**（类似 `@eaDir`）：产品服务读不到截图，但会在 SMB 中出现额外目录，占用用户容量、进入快照，并允许有写权限的成员篡改他人看到的海报。
