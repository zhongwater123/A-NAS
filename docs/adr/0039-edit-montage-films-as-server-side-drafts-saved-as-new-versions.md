# 0039：剪辑中心出片后的二次编辑存为服务端的修改稿，改完另存新版本

状态：superseded（2026-11-27 用户决定 Venus 一律以 PRD v3 为准，本 ADR 作废，被 [ADR 0041](0041-edit-venus-films-on-one-timeline-per-project.md) 取代；正文保留原样。原状态：accepted，2026-11-19 起草，同日接受：用户说“你评审就行了，没问题的话可以拆子票准备开发了”，评审没有遗留问题；第 4、5、7、8、10 项由用户 2026-11-19 定下，同日用户要求照原型补齐第 1、2、8、11 项里的界面与规则；“确认这一版”的做法与镜头清单的格式按默认定下，见[决定记录](../decisions/2026-11-19-montage-edit-defaults.md)；修订[剪辑中心规格](../specs/videocut-center.md#非目标)的非目标“挑一版、快捷微调、精修”；2026-11-25 记下实现与原文不同的四处和新交互要修订的项，见“实现与后续修订”）

剪辑中心出了方案一、方案二两条成片之后，成员要能在成片上直接改：确认一版、按音乐槽换镜头，或者说一句话让 VNAS 重剪（[#596](https://github.com/zhongwater123/A-NAS/issues/596)，父 issue [#514](https://github.com/zhongwater123/A-NAS/issues/514)）。第八版网页原型已经做出了这套交互，但修改只存在浏览器里，“重剪”“修改后的渲染”“预览”都是模拟的。

我们决定：
- 修改以“修改稿”的形式存在剪辑中心的服务端，按音乐槽记录每个槽用哪个节拍；
- 预览在浏览器里按槽轮流播原片，存为新版本时才渲染，渲染结果另存为相册里的新版本；
- 只有“说一句话重剪”调用 VNAS、占规划授权的轮数；
- 文字搜镜头用相册的剪辑窗口向量。

这些选择牵涉剪辑中心的数据表、任务种类、相册授权套接字的新操作和窗口向量集合的第一个读者，改回来都要迁移数据或改协议，所以写成 ADR。

本 ADR 对上面这些难以逆转的选择负责。第 1、2、8、11 项里照原型写的界面与数值（每版显示的信息、候选列几个、场景列几个、修改页的布局与提示文字）是 R1 写进规格的输入：R1 合入后以规格为准，这里不随之修改。两项可以改回来的默认做法写在[决定记录](../decisions/2026-11-19-montage-edit-defaults.md)里。

## 实现与后续修订（2026-11-25）

**结论**：服务端按本 ADR 实现，合在 [#631](https://github.com/zhongwater123/A-NAS/pull/631)；有四处做法与下面的原文不同，以代码为准。2026-11-24 用户确认的新交互会修订第 1、3、4、5、7、11 项，新 ADR 随 [#632](https://github.com/zhongwater123/A-NAS/issues/632) 写；其中两处是设计取向的改变，不是补功能，要在新界面开工前定下。

**与原文不同、以代码为准的四处**：

- **修改稿存什么**（第 3 项）：`drafts` 与 `draft_revisions` 只存镜头（`shots_json`），槽位每次从版本的时间线读出，不随每个修订各存一份。
- **窗口集合怎样读**（第 8 项与“后果”）：搜索按集合自己的名字读；别名 `video_windows_v1` 只标记“已写满”的集合，没写满时搜索退回 Catalog 精确计算（[向量索引](../architecture/vector-index.md#剪辑中心的窗口集合)）。原文“改为经别名读取”没有做。
- **重剪的“不支持的要求”**（第 7 项）：词表只在页面上提示（`web/src/montage/words.ts` 的 `limitsOf`），服务端不过词表。
- **规划没有完成时**（第 7 项的重剪与生成一样）：系统 1 分钟后自动重来，同一个任务对同样的输入最多 3 轮，仍没完成就让任务失败并通知成员（2026-11-25 用户[决定](../decisions/2026-11-25-montage-planning-retries.md)），不再停下等成员点“重新规划”。

**新交互要修订的项**（2026-11-24 用户确认，[#632](https://github.com/zhongwater123/A-NAS/issues/632)）：

| 新交互 | 本 ADR 与 #631 的服务端 | 修订方向 |
|---|---|---|
| 一次只出一版，“换个版本”可以切回原来的版本 | 生成仍出两版；`confirm` 记住项目显示哪一版 | 保持一次两版（2026-11-25 用户：“一次出两版可以”）；切回原版本用现有的 `confirm` |
| 在成片页上直接改，撤销与重做 | 第 3 项只有撤销，撤销本身写成一个新修订 | 加重做：撤销时记下被撤掉的修订，别的操作清掉它 |
| 没改过播成片，改过播粗预览；导出时才渲染，可选 1080p 或 4K | 第 4、5 项：存为新版本时渲染 1080p，相册里多一条成片，修改稿留在原版本上 | **要先定**：导出是存一个快照还是换一个新的起点；导出后修改历史接着哪一份；4K 要改渲染常量与成片校验。粗预览成为主播放器后，浏览器不能直接播的原片经转码，切点处可能短暂黑屏，开工前用真实素材试一次 |
| 助手判断找素材还是整体调整；整体调整与“按我的改动顺一遍”保留手动改过的镜头 | 第 7 项：对版本重剪，从原规划出发，手动改动不带进去 | **要先定**：重剪改为从修改稿出发，规划要知道哪些镜头不能动，重新规划后钉住的节拍要重新对应；`POST /versions/{id}/recut` 很可能被替换 |
| 锁定与重洗、搜索与景别场景筛选、镜头清单 | 第 2、8、9 项已实现 | 不变 |

**交付的实际情况**：R2–R5、R7 与 R6 的服务端合在 #631；R6 的网页（#616）与规格（#604）不合入，随新界面重做。

## 背景

- **原型**：第八版的[网页原型](https://github.com/zhongwater123/A-NAS/blob/feat/video-montage-v5/ai/montage_v8/web/index.html)（#454 的分支，只作参考）。选版页 `#/choose` 每版下面有“修改镜头”“确认这一版”和一句话的“重剪”；修改页 `#/edit/<方案>` 按音乐段落排出镜头，可以替换、拖动、删除、锁定、重洗、撤销、预览、导出镜头清单。说明见[第七版研究](https://github.com/zhongwater123/A-NAS/blob/feat/video-montage-v5/docs/research/video-montage-v7.md)：换镜头与锁定存在浏览器的 `localStorage`，预览按槽依次播原片片段，重剪只放 3 秒动画。
- **首版**：[实施方案](../architecture/videocut-center.md#首版范围)把精修、挑一版和说一句重剪都列为延后，理由是要在服务端保存编辑记录并让修改进入导出，文字搜镜头还要窗口向量的检索。
- **main 上的代码**（`99446cf5`，2026-11-19 核对）：
  - 时间线是 `fill`/`fill-N` 步骤的结果 `{clips, known}`（`internal/montage/render.go`）。音乐槽按“段落 → 画面 → 小节槽”嵌套，长度与切点来自配乐分析；一个槽由选中的节拍填，不够长时由 `fill` 按规则补上别的片段，所以一个槽可能有几段。
  - 每个画面有第一步规划写的画面描述 `query`，第二步答案还多列了一两个备用节拍；`fill` 把 `query` 抄进每个镜头，备用节拍只留在 `shots` 步骤的结果里。
  - 渲染按镜头逐段 `segment`，再 `assemble` 配乐（`renderFilm`）；存回的版本键是任务 ID 加渲染键，版本号在项目内递增（`save`）。
  - `jobs` 没有种类，每个任务都跑完整的生成步骤。
  - 相册的剪辑分析不保留关键帧图片；授权套接字上没有搜索。文字编码是 AI Worker 的 `embed_query`，与窗口向量同一个模型（EmbeddingGemma 2）。

## 决定

1. **选版页的三个操作**。两个方案并排的每一条成片下面有“确认这一版”“修改镜头”和一个说一句话的输入框加“重剪”。
   - **确认这一版**：在项目上记下选定的版本（`projects.chosen_version_id`），项目列表与主页以它为这个项目的成片。另一条怎么处理是[决定记录](../decisions/2026-11-19-montage-edit-defaults.md)的第 1 项：不删除，收进“其他版本”，可以改选。
   - **每一版显示的信息**（照原型）：
     - 成片播放器，同一时刻只播一条；
     - 镜头缩略图条，每格宽度按槽的长短；
     - 剪辑思路：第一步规划的 `design`；段落名串成一行；“看完整规划”展开 `design`、`opening`、`ending` 和各段的名称与概要；
     - 统计：几个镜头、用了几段原片、几个竖拍，有竖拍时标黄；
     - 规划时 VNAS 指出素材里找不到的内容（规格已有）。
   - 改过的版本（`edit`）标“改自第 N 版”，重剪的（`recut`）标“按‘<这句话>’重剪自第 N 版”，没有自己的规划，剪辑思路取它所来自的规划。
   - 修改镜头、重剪见下面几项。任何版本（包括更早的、改过的）都可以修改或重剪。

2. **修改的单位是音乐槽，槽的长度与切点不动**。修改稿记录每个槽钉住哪张卡片的哪个节拍、是否锁定；不直接改时间线里的帧。
   - **重新填槽**：渲染前由计算 Worker 的 `fill` 按修改稿重算时间线。`fill` 增加输入 `pins`（槽 → 卡片与节拍）：钉住的槽首段就用这个节拍，不够长时仍按原规则放慢或补段，无遮挡区间照旧经重入取帧。不带 `pins` 时结果与现在逐个相同，第八版的黄金比对不受影响。
   - **换镜头**：候选依次是同一张卡片里还没用到的其他节拍、这个画面在第二步答案里的备用节拍，再往后是文字搜索全部素材（第 8 项）。搜索框默认填这个画面的 `query`，成员可以改。只列卡片够长、按 `fill` 的放慢上限填得满这个槽的节拍。已经用在别的槽里的节拍照样列出，标“已用在第 N 镜”，不能选：一个节拍在一条成片里只用一次。手动换镜头可以选竖拍，卡片上标“竖”，渲染时照旧垫模糊背景。
   - **拖动**：只在同一个段落里换顺序；锁定的镜头不动，其他镜头按新顺序依次占没锁的槽。卡片不够新槽长度时这次拖动不成立，页面说明原因。拖动用成熟的库（例如 dnd-kit），不手写。
   - **删除**：不留空，由前一镜或后一镜延长补上，延长的那一镜的卡片要盖得住两段之和。两边都够时选画面更像的一边：两个节拍的窗口向量均值的余弦，由计算 Worker 的新操作 `likeness` 算。两边都不够时拒绝删除，提示换一个镜头代替。原型还有“放弃踩点、后面整体提前”，不采用：成片时长要等于音乐选段，这是时间线校验的规则。至少留一个镜头。
   - **锁定后重洗**：每个没锁的槽用所在画面的 `query` 搜索，从最像的 4 个里随机挑一个，规则同原型：一个节拍只用一次，不和前一镜同卡片，卡片够长，横拍的槽不换成竖拍。随机种子记进这一步的修改记录，不调用模型。
     - 横竖按相册 `lookup` 给出的原片宽高判断，和渲染判断要不要垫模糊背景用同一条规则（宽高比小于 16:9），由剪辑中心在挑候选时过滤，`fill` 不用改。
     - 一个镜头都没锁时先确认：“还没有锁定镜头，重洗会换掉全部 N 个镜头”，选“先去锁定”或“全部重洗”。
   - **还原**：“还原这一镜”把一个槽恢复成这个版本原来的节拍；“全部还原”把整个修改稿恢复成这个版本原来的样子。都是可撤销的一步。

3. **修改稿存在剪辑中心的服务端**。
   - 新表 `drafts`（id、owner_user_id、project_id、base_version_id、revision、slots_json、updated_at）与 `draft_revisions`（draft_id、revision、op、slots_json、created_at）。每位成员每个版本一份修改稿，刷新页面、换一台电脑都接着改。
   - 每个操作是一次请求，带 `baseRevision`；服务端按第 2 项的规则校验并应用，写一个新的修订，回答新的修改稿。修订号对不上（例如两个窗口同时改）回答 409，页面重新读取。
   - **撤销**：回到上一个修订，本身也写成新修订；保留最近 100 个修订。
   - 不选原型的浏览器本地存储：#514 要求编辑记录在服务端，修改要能进入导出。

4. **预览按槽轮流播原片，存为新版本时才渲染**（用户 2026-11-19 定）。
   - **粗预览**：页面放这一版的音乐选段，同时按槽轮流播每个槽用到的原片片段，静音，在槽的切点换下一段。原片用相册现有的视频播放；两个 `<video>` 交替，下一段提前载入并跳到起点，切换时不等跳转。以音乐的播放时间为准，原片跟着它换。
   - **片段取哪一段**：没改过的槽按这一版时间线里的镜头取原片，起点与成片相同；放慢过的镜头按原速播，播到的原片比成片里用到的长；改过的槽从所选节拍的起点取一个槽长，是近似值，精确的截取等存为新版本时由 `fill` 算。
   - **不含的东西**：放慢、竖拍的模糊垫底、开头结尾的淡出和无遮挡的截取，页面写明“粗预览，不含放慢、竖拍垫底与淡出”。浏览器不能直接播的原片走相册的转码播放，跳转慢，切点处可能短暂黑屏，粗预览接受。
   - 可以从任意一镜开始播，改一步就能马上再看，不占 FFmpeg 的后台槽位。
   - **音乐**：剪辑中心按这一版任务快照里的配乐副本与选段起点，经 `GET /drafts/{id}/song` 按 Range 送出。
   - **存为新版本**：`edit` 任务按修改稿走“查素材 → 重新填槽 → 渲染 → 存回”，不留中间的预览文件。存回的是新版本、原版本不动，所以先渲染出来再看是不是想要的；不满意就在相册里删掉，修改稿还在，可以接着改。
   - **即时的辅助**：镜头与候选的缩略图由剪辑中心经 `open` 加 FFmpeg `frames`（JPEG，长边 320，`Interactive` 优先级）现取，不存盘，靠浏览器缓存（内容对象不可变，可以 `private, immutable`）。成员在页面上等着看，所以不用 `Background`；这是剪辑中心第一个不走 `Background` 的 FFmpeg 请求，实施方案“[FFmpeg Worker 的新操作](../architecture/videocut-center.md#ffmpeg-worker-的新操作)”中“新操作都用 `Background`”在 R1 改写。单个节拍的试看也用相册的视频播放，从节拍起点播到终点。`VideoPlayer` 还不支持起止时间，实施时补上，粗预览与试看共用。
   - 不选“每次预览都先渲染一遍”：一次预览就是一次完整渲染，几分钟里占着后台 FFmpeg 槽位，改一步看一次等不起；存为新版本又不覆盖原片，渲染一次就够。

5. **改完另存新版本，原版本不动**（用户 2026-11-19 定）。
   - `versions` 增加 `kind`（`plan` 规划出的、`edit` 修改后渲染的、`recut` 重剪出的）、`source_version_id` 与 `draft_revision`。`plan` 列只对 `plan` 版本有意义。
   - 版本号照旧在项目内递增，文件名照旧是“<项目名> v<版本号>.mp4”。修改版本的版本键是修改稿 ID、修订号与渲染键，重试只存一次。
   - 每个版本都留下自己的时间线与音乐槽，所以改过的版本还能再改、能导出镜头清单。
   - 这与规格“已存进相册的方案是定局”一致：要换掉旧的，成员在相册里删。

6. **任务分种类，一个项目同一时刻只跑一个任务**。
   - `jobs` 增加 `kind`：`generate`（现在的生成）、`edit`（按修改稿渲染并存回）、`recut`（第 7 项）。步骤表仍由 `steps()` 一处按种类给出。
   - 项目已有进行中的任务时，“生成”“重剪”“存为新版本”都回答 409，页面写“等这个任务做完”；修改稿随时可以改，粗预览随时可以看。
   - `edit` 任务里素材缺失或进了回收站：照规格停下或暂停，页面标出用到这些素材的槽，由成员换掉后再渲染；`edit` 任务没有“去掉这些继续”。

7. **说一句话重剪：只重剪这一版，只有它占规划授权的轮数**（用户 2026-11-19 定）。
   - `POST /versions/{id}/recut` 建一个 `recut` 任务：素材、歌、起点与是否按拍摄时间都取这个版本的任务快照，只出一个方案，得到一个 `recut` 版本。一句话的上限与规格的“一句话要求”相同（200 字），也过“不支持的要求”的词表。
   - 这一轮的 brief 多带两项：`base`（这个版本收下的大纲与镜头）和 `change`（这句话）。提示词模板升到 `plan-v3.md`，规则是从 `base` 出发、只改这句话要求的地方。修改版本的 `base` 取它所来自的规划；手动改的镜头不带进重剪，页面写明。
   - 这条请求成为 anas-api 在转发前登记规划授权的第五条（另外四条是 `generate`、`replan`、`drop-assets`、`retry-analysis`）：刷新 7 天与 5 轮，这一轮照常计数。
   - 换镜头、搜索、重洗、删除、粗预览、存为新版本都不调用模型，不需要规划授权，不占轮数。

8. **文字搜镜头用相册的剪辑窗口向量**（用户 2026-11-19 定）。
   - 相册授权套接字新增 `searchWindows(grantId, texts, k)`：相册用自己的 `embedQuery` 编码文字，在窗口集合里按这条授权的内容对象过滤后检索，回答每段文字最像的窗口（资产、窗口序号、分数）。一次可以带多段文字，重洗时没锁的画面一起查。
   - 成员在等结果，所以它走相册的交互查询路径，和照片搜索一样算“有人在用相册”。文字与窗口向量的模型不一致时（换了模型、窗口还没重算）回答明确的错误，页面写“分析模型已更新，重新分析后才能搜索”。
   - 这是窗口集合的第一个读者，所以要满足[向量索引](../architecture/vector-index.md#换模型)的“先改为集合别名”，Qdrant 不可用时照照片搜索退回 Catalog 精确计算。
   - 剪辑中心把窗口换算成节拍：节拍的分数取它覆盖的窗口里最高的一个（同原型），再按第 2 项的规则过滤。分数只用来排序，不设门槛。
   - **筛选**（照原型）：景别（节拍描述里的 `shot_size`）、场景、只看横拍，由剪辑中心在搜索结果上过滤，不进相册的检索。
     - 场景用卡片描述里的 `scene`（每张卡片一句，最多 20 字）。原型的场景是事先归好的类，产品里是模型写的原话，同一地点可能写法不同；按卡片数从多到少列出，后面写个数，最多列 8 个，其余并进“其他”。
     - 写了字时列最像的 3 个，往下滚动看更多；没写字时按拍摄先后列出筛选下的全部节拍，不调用搜索。
   - 不选剪辑中心自己调 AI Worker 编码文字：它在 `a-nas-photos` 组里连得上，但那会绕过相册的准入（[ADR 0038](0038-keep-montage-media-in-the-photo-library.md) 决定 4）。不选等 [#207](https://github.com/zhongwater123/A-NAS/issues/207) 的相册视频分段：范围是全相册，#596 要排在它之后。

9. **导出镜头清单**：`GET /versions/{id}/shots` 与 `GET /drafts/{id}/shots`，由服务端按版本或修改稿的时间线生成，每个镜头一行，删掉的槽写明由哪一镜补上。格式与列是[决定记录](../decisions/2026-11-19-montage-edit-defaults.md)的第 2 项：CSV。

10. **文档**：按用户 2026-11-19 的要求，这次只写本 ADR（两项默认做法另写决定记录），不改规格与实施方案，不开 PR。实施第一个子 issue 时，把规格的非目标、场景与验收，实施方案的首版范围、数据、接口、FFmpeg 的新操作与交付，[向量索引](../architecture/vector-index.md#剪辑中心的窗口集合)中窗口集合“首版没有读者”的说法，以及 [CONTEXT](../../CONTEXT.md) 的术语（修改稿、音乐槽、锁定、重洗、重剪）按本 ADR 改写，并在那里链接回来。三版并排与快捷微调按钮仍不做。

11. **修改页照原型的样子**（用户 2026-11-19 要求补齐）。
    - **顶栏**：“换一版”回到项目页的两版并排处，版本名与“精修镜头”，镜头数，“重洗没锁的”，“全部还原”，“粗预览”，“导出镜头清单”，“存为新版本”。
    - **配乐条**：按音乐段落排开，按段落强度着色（安静、中等、铺垫、高潮），标出每段的起点。强度与标签来自配乐分析。
    - **镜头区**：按段落分组，每组写段落名与概要，有两镜以上时提示“拖动换顺序”。每个镜头一张卡片，宽度按长短：缩略图、镜号、在成片里的时间与长度、景别、段落强度色条，角标“已换”“延长”（删除后被拉长的）“竖”，右下角的锁。
    - **点开一镜**：在所在段落下面展开抽屉，写“第 N 镜”、强度、起止与长度和“规划要：<画面描述>”，按钮有锁定这一镜、还原这一镜（改过时）、删除这一镜、收起；下面列出同卡片与备用的节拍。这张卡片没有可换的节拍时，提示去右边搜，并把搜索框填上画面描述。
    - **右栏**：上面是搜索框与筛选（第 8 项），下面是试看区。单击一个候选在试看区播放它会用到的那一段，写“候选”和它的内容，给出“取消”与“替换第 N 镜”；双击候选直接替换。没有候选在看时，试看区播当前这一镜。
    - **每一步之后**：底部提示做了什么（例如“第 3 镜已替换”“已删除，由前一镜延长补上”“换了 12 个镜头，锁住的 4 个没动”），带“撤销”按钮。
    - **存为新版本之后**：回到项目页，进度照生成任务的样子显示；存好后新版本排在最前面，标“改自第 N 版”，修改稿保留。原型的完成页 `#/done` 不单独做，它的内容（成片、修改镜头）都在项目页上。原型的后台确认记录 `#/records` 不做。

## 接口

挂在现有的 `/api/v1/montage`，约定同[实施方案](../architecture/videocut-center.md#接口)：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/versions/{id}/confirm` | 确认这一版 |
| POST | `/versions/{id}/recut` | `{requestKey, change}`：202 与任务；anas-api 先登记规划授权 |
| GET | `/versions/{id}/draft` | 这一版的修改稿，没有就按版本建一份：音乐段落与槽、每槽的节拍、锁定与粗预览用的片段、音乐选段起点、修订号、能否撤销 |
| POST | `/drafts/{id}/ops` | `{baseRevision, op}`：`replace`、`move`、`delete`、`lock`、`unlock`、`shuffle`、`revert`（还原这一镜）、`reset`（全部还原）、`undo` |
| GET | `/drafts/{id}/candidates` | `?slot=&q=&size=&scene=&landscape=`：同卡片、备用节拍与搜索结果（没写 `q` 时按拍摄先后列出全部），标明够不够长、已用在第几镜、横竖；回答里附场景的列表与个数 |
| GET | `/drafts/{id}/song` | 粗预览用的配乐副本，支持 Range |
| POST | `/drafts/{id}/save` | `{requestKey}`：202 与 `edit` 任务，按当前修订渲染并存为新版本 |
| GET | `/versions/{id}/shots`、`/drafts/{id}/shots` | 镜头清单（格式见第 9 项） |
| GET | `/projects/{id}/frames/{assetId}` | `?t=` 毫秒：缩略图 |

## 后果

- **数据迁移**：`projects.chosen_version_id`；`jobs.kind`；`versions` 的三列与每个版本的时间线；`drafts` 与 `draft_revisions`。删除项目、删除账号时一并清掉修改稿。
- **相册**：授权套接字多一个操作；窗口集合改为经别名读取，并补 Catalog 的退回路径；`leak_test` 覆盖新操作。
- **计算 Worker**：`fill` 的 `pins` 与 `likeness`；黄金比对照旧。
- **规划**：新模板 `plan-v3.md` 与 brief 的 `base`、`change`；文件代理和唤醒服务不变，授权的计数照旧。
- **渲染负载**：只有存为新版本时渲染，占用全机 2 个后台 FFmpeg 槽位中剪辑中心的那一个，和生成一样。粗预览只用浏览器和相册的播放；转码播放与缩略图用 `Interactive`、`Streaming`，会和别人的播放一起排队。
- **网页**：`ProjectView.tsx` 的 `Films` 加三个操作与每版的信息（第 1 项）；新增修改页（第 11 项）。接口要把第一步规划的 `design`、`opening`、`ending`、段落，以及镜头数、原片数、竖拍数交给网页。

## 未选择

- **覆盖原版本**：相册里只留一条，但要推翻“已存进相册是定局”，重渲染失败时还得能退回原片。
- **重剪也出两个方案，或重剪不占轮数**：前者耗时与费用翻倍；后者让一句话就能绕过 5 轮的上限。
- **修改存在浏览器**：换浏览器就没了，也进不了导出。
- **每次预览都先渲染**：见第 4 项。
- **剪辑中心自己编码文字、等 #207**：见第 8 项。
