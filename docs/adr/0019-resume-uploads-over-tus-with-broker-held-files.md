# 0019：上传经 tus 分片到达，写入文件代理以用户身份创建的临时文件

状态：proposed（2026-10-12，随传输中心 PR 提交评审）；行为见[传输中心规格](../specs/transfer-center.md)。

Web 上传原本是每个文件一个 multipart 请求：连接一断整个文件重来，批量上传在第一个失败处静默停止，进度无从得知。家庭 NAS 上的上传常常是几十 GB 的视频和成百上千张照片，走的是不稳定的 Wi-Fi，可续传是基本要求。我们决定：上传使用开放的 [tus 1.0](https://tus.io/protocols/resumable-upload) 协议，浏览器端用 [tus-js-client](https://github.com/tus/tus-js-client)（MIT），产品服务用 [tusd](https://github.com/tus/tusd) 的 `pkg/handler`（MIT）处理协议；tusd 的数据存储由我们实现，字节写入文件代理以登录者本人身份（[ADR 0008](0008-use-unified-linux-identities-and-filesystem-acls.md)）在目标文件夹中创建的临时文件，产品服务在上传期间持有这个文件描述符，文件代理协议不增加任何操作。

## 决定

1. **协议与库**：`POST /api/v1/uploads` 按 tus creation 创建上传，`HEAD` 取偏移，`PATCH` 追加分片（客户端 8 MiB），`DELETE` 终止。tusd 负责偏移校验、按上传加锁、60 秒无数据断开和协议错误；协议错误以外的失败按产品 API 的 JSON 错误格式返回，客户端在所有接口上用同一套错误码判断。tusd 保留请求上下文中的值，所以数据存储的每次调用都带着登录者与文件代理需要的会话令牌。
2. **一次授权，持有描述符**：创建上传时，文件服务检查空间写权限、文件名、按需创建文件夹上传的子文件夹、检查整个文件能否放进保留空间，再经文件代理以用户身份创建 `.a-nas-upload-*` 临时文件并取得描述符（`files.PendingUpload`）。之后的分片直接写这个描述符，每片写入前再检查一次保留空间。完成时同步到磁盘，再经文件代理以用户身份重命名为真实名称（不覆盖），因此能否写入、能否重命名仍由内核 ACL 决定。临时文件放在目标文件夹中，继承它的 ACL，文件夹被移动时随之移动。
3. **同名策略在上传开始时决定**：`ask` 在发送任何字节前以 `name_conflict` 拒绝，让用户选择；`rename` 保存为第一个空闲的“名称 (n)”；`replace` 把原文件移到上传者的回收站后放入新文件，文件夹从不被替换。上传期间才出现的同名文件一律保留两者，已经传完的字节不会因为别人的操作而作废。
4. **会话在内存中，记录在系统盘**：进行中的上传及其描述符只存在于产品服务进程内；每个上传的状态与进度写入 `transfers.db`，以便其他浏览器、刷新后的页面和传输记录看到它。一天没有数据的上传被结束并删除临时文件；产品服务重启后，未完成的上传记为 `service_restarted`，浏览器若仍持有文件则从头重新上传一次。
5. **临时文件的回收**：文件服务在内存中记录正在被持有的临时文件。目录整理时，扫描到的、无人持有且超过 10 分钟未修改的临时文件以当前用户身份删除，回收重启或崩溃留下的残片；原 multipart 上传接口也登记它的临时文件。删除不了的（例如别人在共享空间留下而当前用户无权删除）留给有权限的用户。

## 后果

- 断网、暂停、关闭页面后重新选择同一文件，都从 NAS 已收到的位置继续；批量上传每个文件独立成败，失败原因可以逐一呈现。
- 一个上传在完成前占用产品服务的一个文件描述符；每名账号最多 64 个未完成上传，Go 运行时会把软限制提升到 systemd 给出的硬限制。
- 产品服务重启会让进行中的上传从头开始，残留的临时文件在 10 分钟后的目录整理中删除，在此之前仍占用数据卷空间。
- 上传期间被删除到回收站的文件夹会带走临时文件；该上传在完成时失败，临时文件随回收站一起过期删除。
- 引入 tusd 模块使 Go 依赖图中的 OpenTelemetry 间接依赖升级到 tusd 要求的最低版本；`pkg/handler` 本身只依赖标准库与 `golang.org/x/exp/slog`。

## 未选择

- **自己设计分片上传协议**：要同时手写客户端的分片、重试、续传与偏移协商，以及服务端的偏移校验与并发控制；tus 已有成熟的两端实现与公开规范，IETF 的可续传上传草案也源于它。
- **tusd 自带的文件存储（filestore）**：字节由产品服务以自己的身份写到它的目录，再搬进用户空间。产品服务身份不能写数据卷（ADR 0008），而且要多一次复制或跨子卷移动，并让上传绕过用户的 ACL。
- **为续传新增“重新打开临时文件”的文件代理操作**：产品服务重启后也能续传，但要扩大 root 文件代理的类型化接口，并让产品服务凭路径反复以用户身份打开半成品文件。重启在家庭 NAS 上不常见，目前接受从头上传；需要时再单独评审。
- **保留每个文件一个 multipart 请求，只在前端加队列**：能显示进度，但任何中断都要整个文件重传，NAS 重启或 Wi-Fi 切换时大文件几乎传不完。
