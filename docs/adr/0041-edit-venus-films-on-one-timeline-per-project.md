# 0041：Venus 按 PRD v3 编辑：每个项目一条时间线，只撤一步，导出覆盖；成片存在项目里，删项目只删成片，原片留在相册

状态：accepted（2026-11-27，用户：“全部以prd为准，adr0039可以抛弃”；取代 [ADR 0039](0039-edit-montage-films-as-server-side-drafts-saved-as-new-versions.md)，修订 [ADR 0038](0038-keep-montage-media-in-the-photo-library.md) 中成片的存放；同日用户转达产品经理的确认：“删除成片的时候，相关素材不删除”，所以第 6 项与 PRD 3.5 不同）

剪辑中心按《Venus PRD v3》改版为 Venus（[#689](https://github.com/zhongwater123/A-NAS/issues/689)）。PRD 的编辑模型与 ADR 0039 的修改稿有多处相反，成片的存放也和 ADR 0038 的“成片归相册”不同；用户决定以 PRD 为准，ADR 0039 作废。数据上唯一的例外是删除项目：PRD 3.5 要求原片一起删，产品经理确认原片保留，ADR 0038 的“原片归相册”不变。行为写在 [Venus 规格](../specs/venus.md)，网页结构写在[技术设计](../architecture/videocut-center.md#venus-改版的网页结构)。

## 决定

1. **一个项目只有一条成片。** 生成只出一版，界面上没有版本，不再“确认这一版”，也不切换版本。
2. **在一条时间线上直接改。** 镜头操作（替换、删除、调整入点、段落换序、添加素材）立即改这条时间线，规则见规格的[编辑模型](../specs/venus.md#编辑模型)：
   - 删除镜头是把这个槽换成下一个候选，槽数和总时长不变；不再由前后的镜头延长补位；
   - 段落换序可以换到别的段落，镜头按新位置的槽重新填；
   - 候选不含已在片中的和方向不符的；
   - 成员改过的镜头是锚点，之后的自动操作不改它。没有锁定与重洗。
3. **撤销只有一步。** 只撤最近一次镜头操作，撤销后不能再撤，不做重做；切换项目或刷新页面后清空。
4. **并发修改靠修订号拒绝。** 每次操作带时间线的修订号，对不上时服务端拒绝，网页重新读取。这一条沿用 ADR 0039 的做法，因为同一个项目可以同时在两个标签页里打开（PRD M1-1 的验收就这样做）。
5. **导出覆盖上一次的文件。** 导出按当前时间线从原片渲染 1080p，完成后浏览器自动下载；再次导出覆盖上一次的成片文件，不在相册里另存一个版本。
6. **删除项目只删它自己的东西，原片留在相册。** 删除项目时，成片、时间线、候选、锚点和导入的歌（只属于这个项目，PRD M4-1）一起删，删除后用原链接打不开项目、也下载不到成片；正在处理的任务先停。原片仍是成员个人图库里的照片资产，连同相册给它做的分析，都不随项目删除，和 ADR 0038 一致。

## 后果

- ADR 0039 的修改稿、版本另存、重剪和它的[默认做法](../decisions/2026-11-19-montage-edit-defaults.md)都不再适用。已经实现的服务端（[#631](https://github.com/zhongwater123/A-NAS/pull/631)：`drafts`、`draft_revisions` 与 `/drafts` 接口）在 Venus 的接口契约定下后改造或删除，由后端决定；能沿用的只有修订号的冲突检测。
- 上传照旧：点“开始生成”后，勾选的原片传进成员的个人图库，剪辑中心经项目授权读取（ADR 0038）。PRD 3.5、M1-2 的验收、M10-1 和范围表里“删作品一起删素材”的说法要改；删除确认的文案“成片和编排会删除，不可恢复”本来就是这样写的。
- 成片不再进相册，导出的文件存在项目里，下载靠浏览器。
- ADR 0038 除了成片的存放，其他决定都不变：原片与分析归相册、独立服务、服务账号、项目授权、规划在成员的规划进程里。

## 未选择

- **沿用修改稿，只改规则。** 修改稿是按版本建的，Venus 没有版本；多步撤销、另存新版本也都要拆掉，剩下能用的只有修订号，所以只保留这一条。
- **按 PRD 3.5 删除项目时连原片一起删。** 产品经理确认不删，未记录理由。不删时上传与存储都沿用 ADR 0038，不用为 Venus 另建一套素材存储。
