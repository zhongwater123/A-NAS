# 0023：成员分享的固定副本由独立服务持有

状态：proposed（已实现；部署与验收进度见[当前状态](../status/CURRENT.md)）

成员分享需要在发送者离线后继续向指定接收者提供固定内容，并区分自然到期和手动撤回。[ADR 0008](0008-use-unified-linux-identities-and-filesystem-acls.md) 的个人空间和共享空间仍按用户身份与文件系统 ACL 访问；本提案为独立创建的分享副本增加受管存储边界，不修改源空间权限。

## 提案

- 增加以专用系统身份 `a-nas-shares` 运行的分享服务，独占已验证数据卷中的 `shares` 存储及其中的目录、消息和任务状态。该身份不获得个人空间、共享空间或图库访问权。固定 UID/GID 为 31001，安装时拒绝已有身份冲突，不复用成员 UID。
- 产品服务仅转发会话和类型化请求。分享服务经 Host Agent 的会话查询接口自行确认身份，对分享内容、私聊和任务实施 Catalog 授权；管理员角色没有隐式访问权。
- 源文件由文件代理以发送者身份读取，内容导入分享存储；目标文件由文件代理以接收者身份创建。分享服务不能要求 root 按任意源路径代读，不能自行声明成员身份，也不能持久保存发送者会话用于后续访问。
- 同一次分享的多个接收者共用一份发布后不可修改的副本，各自拥有独立讨论和查看、已读、保存状态。第一版不做跨分享内容去重，避免到期和撤回受到其他分享引用的影响。
- 有效期结束后仅允许此前已接受的保存任务继续读取其固定范围。撤回使这些任务同样失效；目标提交必须与撤回有明确的先后顺序。读描述符已打开不等于任务可以永久继续。
- 普通文件仍遵守 ADR 0008。此提案被接受后，只对服务独占的分享副本增加 Catalog 授权例外，类似 [ADR 0011](0011-run-the-photo-library-as-a-dedicated-service-identity.md) 的受管图库边界。

## 权衡

选择独立服务需要新增进程、安装身份、Socket、服务健康检查和故障恢复，也使临时副本成为明确的受管资源。收益是发送者离线不会影响访问，不需要在源个人空间或单个普通文件上临时增加接收者 ACL，产品服务仍无全盘读取权。

另一个可行方向是由文件代理管理有 ACL 的独立分享容器。它保留文件系统授权，但需要扩展现有授权粒度，并协调只读发布、临时访问 ACL、自然到期后仍允许保存的任务和撤回。这些复杂度集中在现有特权边界，故本提案优先选择独立服务。

不采用产品服务持有全体源空间权限或长期借用发送者会话的做法：前者扩大其泄露面，后者不能可靠支持退出登录和离线接收。

## 实现与验证边界

源文件由成员身份打开后传递只读描述符；生产使用同一 Btrfs 文件系统上的 FICLONE 获得每个文件的原子副本。清单前后重扫发现树变化，失败不发布；多个文件之间不承诺同一时刻的事务快照。

目标提交沿用成员文件操作，并将分享代次和撤回栅栏传到 Host Agent，避免产品进程断连后旧请求继续发布。源/目标 ACL、原始会话和分享参与者授权分别在其所属边界检查。具体协议、故障恢复与验证入口统一记录在[技术设计](../architecture/member-sharing.md)。
