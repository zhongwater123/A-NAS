# 0026：VNAS 经 NAS 上的 PAIR 节点使用家里电脑的算力

状态：proposed（2026-10-20 按用户要求评估 NVIDIA PAIR 后起草；尚未在容器或实机上验证，待用户决定隐私边界）。外部事实见[可行性研究](../research/nvidia-pair-lan-inference.md)，行为见[局域网算力规格](../specs/lan-ai-compute.md)。

[ADR 0024](0024-run-a-sandboxed-hermes-agent-per-member.md) 决定 7 让 VNAS 的模型在开发期走云端、之后换成本地模型，并规定本地模型接入前不在保存真实家庭数据的设备上开启助手；但 8 GB、无独显的 NAS 跑不动 Hermes 需要的模型。NVIDIA PAIR 能把家里装了 RTX 显卡的电脑组成推理集群，而它只接受本机与已配对节点的请求。我们决定：NAS 以不带推理引擎的 PAIR 节点加入家里电脑组成的集群，VNAS 的模型网关只经本机回环上的 PAIR 代理把请求交给配对的电脑；相册 AI 仍只在 NAS 上运行。

## 决定

1. **NAS 是集群中的请求方**：NAS 运行 PAIR 的服务，与家里的电脑配对，但自己不运行推理引擎，也不接受别的节点派来的推理工作。VNAS 的模型网关以 `http://127.0.0.1:11434`（PAIR 的 Ollama 代理）为上游，由 PAIR 选择有该模型、最空闲的电脑并在失败时换节点；A-NAS 不自己实现节点选择与重试。不在电脑上开放明文中继，也不使用 PAIR 尚未合并的 API 密钥方案。
2. **只分发 VNAS 的模型请求**：相册的向量、检测、人脸与宠物仍在无网络的 AI Worker 中运行（[ADR 0016](0016-ship-photo-ai-as-a-built-in-offline-capability.md) 不变）；照片 OCR 等其他工作是否分发另行决定。
3. **只在局域网内**：选了家里的电脑后，电脑都关机或没有该模型时 VNAS 报告“模型暂不可用”，从不改走云端。
4. **随系统送达**：PAIR 的服务二进制包（不是带图形界面的 `.deb`）固定版本、核对 SHA-256，与 AI 运行环境一样按内容存放在 `/opt/a-nas` 并由 release 引用；设备上不下载 PAIR、引擎或模型，不使用 PAIR 的自更新与引擎安装。
5. **专用身份与沙箱**：PAIR 以专用服务账号运行，只写自己的状态目录，看不到数据卷与产品服务的状态。A-NAS 的一个服务作为 broker 的父进程，保持它的 JSON-RPC 连接，只向产品服务提供节点、模型与配对的窄接口。只启用 Ollama 代理（llama.cpp 代理默认占用 8080，与产品服务冲突），不提供引擎管理与节点信息两个工作进程，因此配对的电脑不能在 NAS 上安装或启动任何东西，NAS 也不在局域网上公开未认证的硬件信息。
6. **管理员决定**：是否开启、与哪台电脑配对、VNAS 用哪个模型，只能由管理员在“设置”中操作；默认关闭，关闭时 NAS 不运行 PAIR、不开放任何端口。

## 后果

- VNAS 读到的文件内容、照片元数据与照片画面会经 mTLS 发到配对的电脑上处理，电脑的使用者与电脑上的软件可能看到。VNAS 的隐私说明要改为“在你家里的电脑上处理”，这一边界需要用户确认；确认后，ADR 0024 中“本地模型接入前不开启助手”的条件以此满足。
- NAS 在局域网开放 5353/udp（mDNS）与 14319–14321；配对只有 6 位 PIN，不防局域网上的主动中间人，集群信任是传递的。
- PAIR 是 beta，Linux 没有服务模式，broker 的集成契约尚未版本化；A-NAS 固定一个版本，升级 PAIR 要像升级其他依赖一样先在系统测试中验证。Debian 13 不在官方列出的系统中，须先在 Debian 13 上验证。
- 每台电脑上的 Ollama 都要设同样的 `OLLAMA_CONTEXT_LENGTH`，并按完全相同的标签持有 VNAS 的模型；这些在电脑上的 PAIR 中设置，A-NAS 只检查并提示。
- 电脑上的模型被卸载后，下一次对话要等它重新加载；超过 PAIR 的 120 秒会失败一次。
- 原型验证若发现缺少引擎管理进程时代理无法工作，决定 5 需要改为运行它并以别的方式阻止远程安装，或等待 PAIR 的轻量请求方客户端。

## 未选择

- **NAS 不装 PAIR，直接请求电脑上的代理**：PAIR 只接受回环明文与已配对节点的 mTLS，这条路按设计不通。
- **在电脑上加回环中继或用 API 密钥 PR**：中继让局域网上任何设备都能用这台电脑的 GPU 并看到请求；密钥方案未合并、仍在安全评审。
- **不用 PAIR，模型网关直连各电脑的 Ollama 并自己做选择与重试**：等于重写 PAIR 的路由，且没有加密；电脑装了 PAIR 后 Ollama 只在回环上，这条路也走不通。
- **在 NAS 上运行本地小模型**：8 GB 内存与 i3 CPU 只能跑很小的模型，Hermes 的工具调用与看图质量不够；相册 AI 与其他服务也要内存。
- **继续用云端模型**：与 ADR 0016、ADR 0024 的隐私承诺冲突，只用于开发测试。
