# 0030：网页搜索由随系统安装的 SearXNG 服务提供

状态：proposed（2026-10-30）；行为见[网页搜索规格](../specs/web-search.md)。

成员想在 A-NAS 上直接搜索互联网，但不应该自己去安装搜索引擎、挑选引擎或改配置。单台 NAS 不可能自建全网索引，可行的是元搜索：把查询转发给现有的公网引擎并合并结果，成熟的开源实现是 SearXNG（AGPL-3.0-or-later）。我们决定像相册 AI（[ADR 0016](0016-ship-photo-ai-as-a-built-in-offline-capability.md)）一样把它做成随系统安装、默认开启的内置服务，由 A-NAS 自己的窗口显示结果，管理员可以整体关闭（用户 2026-10-30 决定）；它是第一个代成员访问外网的内置服务，所以网络边界和许可证义务在这里一并定下。

## 决定

1. **随系统安装，默认开启，管理员可以整体关闭。** 每次安装或升级都同时安装与该 release 匹配的 SearXNG 运行环境、设置与服务单元。产品不提供单独下载、安装、更新或选择引擎的入口；成员只看到“网页搜索”窗口。管理员在“设置 → 网页搜索”中关闭时，经 Host Agent 写入 root 所有的标记文件并停止服务；服务单元以该标记不存在为启动条件，所以安装器照常启用并重启单元时不会把它重新打开。产品服务从 Host Agent 读取开关状态。被盗用的管理员会话可以打开开关，但这只让已登录的账号能够搜索，不带来其他权限。种子分类（海盗湾、1337x 等种子站）另有一个管理员开关，默认关闭（用户 2026-10-30 要求支持，用于测试能力边界）。它由产品服务执行并保存在产品服务的状态中：关闭时产品服务不向搜索服务请求这一分类，不需要重写设置或重启服务。
2. **版本固定，随 release 更新**（用户 2026-10-30 决定）。SearXNG 不发布版本标签，只有主干提交，所以按完整提交 SHA 固定，构建时冻结它的 `YYYY.M.D+<提交>` 版本号。设备不运行 pip，也不自行更新。引擎因目标网站改版失效时，要等下一个包含上游修复的 release。
3. **运行环境沿用 ADR 0016 的方式。** 在开发机上用 Debian 13 自带的 `python3`（3.13）建 venv：依赖按锁定哈希只装 wheel，SearXNG 本身来自固定提交的源码包（核对 SHA-256），不带依赖安装。运行环境按内容存放在 `/opt/a-nas` 下，由 release 的清单引用；暂存时只上传 NAS 还没有的内容。相册 AI 的构建与安装脚本目前写死了 AI 的路径，Qdrant 又复制了一份同样的做法；这里把它们改为按组件参数化，不复制第三份。
4. **只有产品服务能连。** `anas-search.service` 以专用系统账号 `a-nas-search` 运行 Granian，经 Unix 套接字 `/run/a-nas-search/search.sock`（`0660`，属 `a-nas-search` 组）提供 HTTP，没有 TCP 端口；产品服务加入该组，与相册服务的套接字相同。SearXNG 没有登录认证，所以会话校验、按账号限流与结果映射都在产品服务中完成。产品服务以 POST 调用它的 JSON 接口，搜索词只在请求体中，再按自己的 OpenAPI 契约返回给 Web。
5. **只能访问公网。** 服务单元允许 `AF_UNIX`、`AF_INET` 与 `AF_INET6`，再用 systemd 的 IP 访问控制拒绝回环、链路本地、组播、私有网段（含 Docker 地址池所在的网段）、运营商级 NAT 与其他保留地址，只放行设备当前的 DNS 服务器；DNS 服务器由 DHCP 写入 `/etc/resolv.conf`，root 的 path 单元在它变化时更新允许列表。网页内容决定了结果里的网址，缩略图代取会请求这些网址，没有这一层，搜索服务就能被用来访问家里或公司内网的设备。其余沙箱与其他内置服务相同：系统目录只读、看不到数据卷、没有设备、不能提权，并有内存上限。
6. **不修改 SearXNG，不使用它的网页。** 只由安装器生成一份 root 所有、只读的 `settings.yml`：
   - 在上游默认设置之上只保留随 release 选定的引擎（`keep_only`），因为标记为停用的引擎仍会加载和初始化；
   - 打开 JSON 输出；
   - 密钥在安装时生成，存入只有 root、搜索服务与产品服务能读的环境文件，用于缩略图代取地址的签名；
   - 关闭限流器（不需要 Valkey）与查询日志；
   - 不加载启动时就联网的插件与引擎（ClearURLs 规则下载、电台目录），所以没人搜索时它不访问外网。

   结果由 A-NAS 的窗口显示；缩略图经 SearXNG 自带的图片代取，只接受它密钥签名的地址，再由产品服务转发。需要改代码时先提交上游；确需本地补丁时，补丁随源码一起公开，并按 AGPL 第 13 条向使用它的成员提供修改后的源码。
7. **AGPL 义务由发布物承担，A-NAS 本身不受其约束。** A-NAS 与 SearXNG 是两个进程，只经 HTTP 接口通信：A-NAS 不导入它的模块、不复制它的代码，因此不是它的衍生作品。release 携带构建运行环境用的同一个 SearXNG 源码包、它的许可证，以及运行环境中全部 wheel 的许可证清单（构建时从包元数据生成）；“设置 → 网页搜索 → 开源许可”显示许可证，并由 NAS 自己提供这一版本源码的下载。对外发行前请法务确认，与 ADR 0016 对模型许可证的要求相同。
8. **不保存搜索词，VNAS 不使用。** 产品服务不记录搜索词、不写审计，SearXNG 与 Granian 的访问日志都关闭，服务端与浏览器都不保存搜索历史。AI 助手仍不联网（[ADR 0024](0024-run-a-sandboxed-hermes-agent-per-member.md) 决定 8）；以后若让它用网页搜索，经同一个服务桥接，另行决定。

## 后果

- 所有成员的搜索都从 NAS 的出口地址发出。实验 NAS 在公司网络中，引擎看到的是公司的出口 IP，公司网络能看到访问了哪些引擎（HTTPS 下看不到搜索内容）。全家共用一个出口地址，一个账号搜得太快会让引擎对所有人弹验证码，所以产品服务按账号限流。
- 元搜索靠抓取各引擎的结果页，不符合多数引擎的服务条款。遇到验证码时 SearXNG 暂停该引擎一段时间，A-NAS 不尝试绕过。默认引擎列表以实验 NAS 上的实测为依据；Google 在上游仍不稳定，默认不打开。
- 种子站的结果多为未经授权的影视内容。按《信息网络传播权保护条例》第二十三条，搜索或链接服务明知或应知所链接的作品侵权时要承担共同侵权责任，所以种子分类默认关闭、只由管理员打开，A-NAS 也不把种子交给下载应用。对外发行前要重新决定是否保留这一分类。
- 多一个常驻进程。内存占用与运行环境大小在首次构建后实测，内存上限先定为 512 MiB 并按实测调整；服务停止或崩溃只影响网页搜索。
- 这是第一个设置 IP 访问控制的单元。系统测试证明它连不上回环、局域网与保留地址，也证明只有产品服务能连接套接字；能否连上公网只在实验 NAS 上验证，因为门禁不访问外网。
- 每个 release 多携带一份 SearXNG 源码包与许可证清单；运行环境与源码包按内容存放，依赖不变时不重复传输。

## 未选择

- **上架到应用中心，由用户安装官方镜像。** 用户要自己安装和配置引擎，结果也只能在 SearXNG 自己的网页里看；用户要求免去这些操作（2026-10-30）。
- **把官方 Docker 镜像作为内置服务运行。** 内置能力会依赖 Docker 常驻和 Docker Hub 拉取，后者在国内网络下不稳定，镜像也不属于 release 制品；容器默认的能力与 A-NAS 的 systemd 沙箱也不一致。
- **使用或改造 SearXNG 自带的网页（反向代理或内嵌）。** 风格与桌面不统一，它还有自己的设置页与 Cookie；为统一风格改它的模板就是修改 AGPL 程序，要公开修改并向网络用户提供源码。
- **商业搜索 API**（Brave、Mojeek、Tavily 等）。要密钥、费用和调用上限；Bing 搜索 API 已于 2025-08-11 停用，Google 可编程搜索的全网搜索将于 2027-01-01 停用。以后可以作为补充引擎接入 SearXNG。
- **自建索引**（YaCy、Stract 等）。单台 NAS 能收录的内容太少，不能作为主要搜索。
- **在产品服务中自己抓取各引擎。** 维护各引擎的解析与反爬处理正是 SearXNG 的价值所在，自己写就是重复造轮子。
- **让设备自动更新 SearXNG。** 与 release 固定制品、设备不自行联网更新的模式不符；用户决定先跟随 release（2026-10-30）。
