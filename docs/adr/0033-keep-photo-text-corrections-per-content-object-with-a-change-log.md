# 0033：照片文字的更正按内容对象存，修改记录对能看到照片的人公开

状态：accepted（2026-11-05；做法由用户 2026-11-03 定下，实现时的细节按 Claude 的建议，用户 2026-11-05 让直接实现）

相册从证件、票据照片上读出的字段可以由成员更正。步骤 3 的第 15 号迁移按“图库 + 内容对象”存更正，与人物的用户决定相同。用户 2026-11-03 改为按内容对象存，所有图库共用，并要求每次修改留下对所有能看到照片的人公开的记录。改回按图库存要迁移数据，所以写成 ADR；它修订 [OCR 实施方案中采纳的建议](../decisions/2026-10-30-ocr-plan-defaults.md)中“共享图库所有成员都可以更正，记入活动记录”一项。

## 背景

- 一张小票常常同时在私有图库和共享图库里。按图库存，要在两处各改一遍；只改一处，两边显示的值就不一样。
- 第 15 号迁移已随 `70853075ca40` 部署到实验 NAS，但没有任何代码写过更正，表是空的。

## 决定

用户 2026-11-03 的决定：

1. **更正只按内容存，所有图库共用**：任何人在任一处修改，所有持有这张照片的图库都显示新值。
2. **以最后一次修改为准**：不加锁，也不做冲突处理。
3. **能看到这张照片的成员都能改**：管理员经“查看私有图库”授权看到的仍是只读。
4. **每次修改都留记录**：内容对象、字段、旧值、新值、修改人、从哪个图库改的、时间。
   - 对所有能看到这张照片的成员可见，显示修改人的名字；从私有图库改的也照样显示，不做匿名处理。
   - 从记录可以看出谁改过什么，并能改回去。
5. **生命周期**：
   - 关闭某个图库的“照片中的文字”开关时，更正与记录都保留；
   - 照片的内容对象彻底删除时，更正与记录一起删除；
   - 文字内容仍不写进系统的活动记录。

实现时定下的细节，是 Claude 2026-11-04 的建议，用户没有逐项确认：

- **存储**（第 16 号迁移）：
  - `text_corrections(object_id, field, value, account, account_name, updated_at)`；
  - 修改记录 `text_changes(object_id, field, old_value, new_value, restored, account, account_name, library_id, created_at)`。`library_id` 不加外键，图库删除后记录仍在，只剩图库 ID；修改人的名字存下修改时的那个。
  - 两表都随内容对象删除。
- **旧值**是修改时显示的值，也就是上一次更正，或者当时读出的值。换了读文字的模型重读，不改动已有的记录。
- **改回去**：
  - 照着记录再改一次，也记一条；
  - “恢复为识别结果”删掉更正，字段重新显示读出的值，也记一条（`restored`）。没有这一项，旧更正会一直盖住新模型的读取结果。
- **关了开关的图库**不显示、也不搜索文字与更正；同一张照片在另一个开着的图库里照常显示。
- **谁不能改**：
  - AI 助手不能改，也看不到修改记录，因为记录里有它不该知道的值；
  - 回收站里的照片不能改。
- **系统活动记录**不记更正：修改记录就是它的记录，一项事实只在一处。
- **AI 助手的句柄**存在同一迁移的 `text_handles(handle, account, asset_id, key)` 中，随照片删除。句柄是随机值，绑定“本人 + 照片 + 字段或号码”（[决定](../decisions/2026-10-30-ocr-assistant-handles.md)）。

## 后果

- 退回第 16 号之前的版本，要先执行方案“交付”一节的撤销语句，更正与修改记录会一并删除。
- 关闭开关后，修改记录里仍留着旧值，其中可能有模型读出的证件号、卡号，直到照片彻底删除。所以“关闭即清除派生文字”不包括这些记录。
- 能看到一张照片的成员，会从记录里看到别人也在自己的私有图库里有它。用户接受这一点（“家人之间无所谓”）。

## 未选择

- **按图库存**（第 15 号的设计）：同一张照片要改多次，各图库显示不一致。
- **加锁或冲突提示**：家庭规模下同时改同一个字段很少见，以最后一次为准更简单。
- **修改记录匿名或只给本人看**：用户要求显示名字，从私有图库改的也照样显示。
