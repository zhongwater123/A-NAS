# 0038：剪辑中心以独立服务运行，素材、基础分析与成片归相册，经项目授权访问

状态：accepted（2026-11-18，用户；2026-11-17 起草；2026-11-18 用户把规划改为由 NAS 在后台发起，决定 5 已改写；同日评审人定为 Hermes 探针（实施方案的 P1）通过后再决定，[Hermes 探针](https://github.com/zhongwater123/A-NAS/pull/546)的两项必过都过了，决定 5 按它的结果改写；已修订 ADR 0011 决定 4、0016 决定 4、0024 决定 3、8 与 10；实施方案见[剪辑中心技术设计](../architecture/montage-center.md)，行为见[规格](../specs/montage-center.md)）

[#514](https://github.com/zhongwater123/A-NAS/issues/514) 要把视频剪辑原型接进 A-NAS。接入后，剪辑要在成员离线时继续读原片，要用本地模型看画面，要用成员的 VNAS 做规划，还要把成片放回相册。这带来几个难以逆转的选择：
- 剪辑以什么身份运行；
- 素材与分析归谁；
- 成员离线时凭什么读相册；
- 规划怎样接进成员的沙箱，成员离线时凭什么用成员自己的 VNAS 规划。

我们决定：
- 剪辑中心是内置的独立服务；
- 素材、基础分析与成片都归相册，剪辑中心凭相册持有的项目授权访问它们；
- 规划经成员 VNAS 里的 MCP 工具完成，由 NAS 在后台发起，凭成员点“开始”时留下的规划授权。

## 决定

1. **内置独立服务。** 剪辑中心照家庭中心（[ADR 0029](0029-keep-the-baby-as-a-profile-and-channel-photos-in-the-shared-library.md)）接线：单元 `anas-montage.service`，系统账号 `a-nas-montage`，固定 UID 31003。
   - 它不做可移除模块（[ADR 0037](0037-plug-removable-modules-in-as-separate-services.md)），因为它要连相册的授权套接字和 FFmpeg Worker，而模块看不到这两样。
   - 它只持有剪辑中心子卷里的四样东西：项目、规划、时间线与任务，以及成员选歌时复制的配乐副本。
2. **素材、基础分析与成片归相册。**
   - 原片与成片都是相册里的照片资产：上传的原片与成片在成员的个人图库，从相册选入的视频留在原来的图库。
   - 窗口向量、卡片、画质与卡片描述按内容对象计算，存在相册 Catalog，跨项目复用（[决定记录](../decisions/2026-11-17-montage-center-first-version.md)）。
   - 剪辑中心不保存原片、分析结果或成片的副本。
   - #514 说“项目特定的卡片分组、候选、规划、时间线与人工编辑由剪辑中心持有”。这里的理解是：卡片按视频内容切，与项目无关，所以归相册；项目特定的是从卡片里选出的目录、规划与时间线，归剪辑中心。
3. **项目授权。**
   - **登记**：成员在场时，剪辑中心用这次请求转发来的会话，请相册登记一条授权，列出项目里的资产。
   - **使用**：之后剪辑中心经相册的授权套接字凭授权做这些事：查资产状态，请求并读取分析，取原片的只读描述符，存回成片，撤销授权。
   - **相册的检查**：
     - 套接字由 systemd 持有，只有剪辑服务的账号能连；相册再用 `SO_PEERCRED` 核对 UID；
     - 每次按授权主人重新构造一种新的“授权身份”走 Policy：能看到视频、打开原片，只能往主人的个人图库导入，不带管理员身份与查看授权；
     - 主人账号停用、资产不可见或授权已撤销时拒绝。
   - 剪辑中心不保存会话。
   - 这是相册在“成员会话”与“成员助手”之外的第三条身份路径，已写进 [ADR 0011](0011-run-the-photo-library-as-a-dedicated-service-identity.md) 决定 4。
4. **基础分析在相册的 AI 调度里运行。**
   - **排队范围与准入**：相册只为授权里请求过的视频排分析任务，用自己的前台、压力与内存准入。
   - **各项分析怎么算**：
     - 窗口向量照 [ADR 0028](0028-index-vectors-in-a-rebuildable-qdrant-instance-per-owner.md) 存进 Catalog，经独立的 outbox 同步到相册实例里的新集合；
     - 卡片与画质由新增的剪辑计算 Worker 算出，它运行第八版 `domain/` 的纯计算；
     - 卡片描述由 AI Worker 新增的 `describe_frames` 写出。
   - **AI Worker 的客户端**：按设计只有相册调用（剪辑服务因所在的组也能连上，见“后果”）。它收到的关键帧由相册从自己的原片里取出，已写进 [ADR 0016](0016-ship-photo-ai-as-a-built-in-offline-capability.md) 决定 4。
   - **视频与相册 AI 功能**：视频照旧不进相册的搜索、聚合与找相似，也不进助手用的相册接口。
5. **规划在成员自己的 VNAS 里，由 NAS 在后台发起。**（用户 2026-11-18 改定，此前是成员打开桌面时由桌面发起）
   - **在哪跑**：照定时任务，跑在成员自己的定时任务单元里：同一个沙箱、同一条通往模型的桥，没有实例凭据，成员不登录也能跑。Hermes 里是一个任务，跑完连同运行记录删除；成员在哪里看得到它，见[规格](../specs/montage-center.md#本稿补充的默认规则)的默认规则。
   - **谁发起**：root 的唤醒服务。剪辑中心只留下“这位成员有任务在等规划”的记号；唤醒服务核对规划授权后才启动单元，剪辑中心自己启动不了。
   - **规划授权**：成员做开始、重新规划等操作时（见[规格](../specs/montage-center.md#本稿补充的默认规则)），产品服务带着这次请求的会话请文件代理登记，文件代理照“立即运行”核对会话。授权按成员，有期限、有轮数上限：文件代理写授权，唤醒服务另记领取了几轮，只有 root 能读写。
   - **提示词**：规则是随助手运行环境发布的固定模板，沙箱里的回合脚本只填进经过校验的编号与数字。剪辑中心只经工具给数据，不能决定提示词。
   - **这一轮只开放 `montage` 工具组，结束后也不跑后台复盘**：没有文件、终端、相册与看图的工具，复盘也写不了记忆与技能，所以剪辑服务被攻破时诱导不了能动成员数据的模型，“只发文字、不发画面”也有保证。这两项是探针的必过项（评审人 2026-11-18），[Hermes 探针](https://github.com/zhongwater123/A-NAS/pull/546)实测都过了：任务带 `enabled_toolsets=["montage"]` 时模型只拿到 montage 的工具；Hermes 对定时任务的运行固定不跑复盘。
   - **成员的记忆照样进这一轮的提示**：Hermes 对定时任务固定加载成员的记忆，按任务关不掉；这一轮没有记忆工具，写不进去。
   - **工具**：新增 MCP 服务器 `montage`，不加进任何 `platform_toolsets`，只有规划任务点名它。它的套接字由 systemd 持有，只绑定进定时任务单元，不绑定进对话实例与整理单元。剪辑中心按对端 UID 认出成员，只回答这位成员自己的任务。
   - 剪辑中心不连 Hermes，也不保存会话。
   - 已修订 [ADR 0024](0024-run-a-sandboxed-hermes-agent-per-member.md) 决定 3（沙箱的出口）、决定 8（A-NAS 的 MCP 服务器与定时任务的工具）与决定 10（会话闸门之外，经成员在场时留下的规划授权在后台调用成员的助手）。
6. **媒体只经类型化操作。**
   - 渲染用 FFmpeg Worker 新增的 `frames`、`segment`、`assemble` 操作，参数由 Worker 自己拼，输入只有只读描述符。
   - `assemble` 一条消息带 2 个描述符：拼好的画面与歌曲音源。

## 后果

- **原片、成片与分析各只有一份**，生命周期都由相册管理：素材进回收站或被删除、成片被删、账号被删除，都只在相册一处发生。删除剪辑项目不动相册里的任何资产。
- **改剪法要动相册**：第八版的卡片与画质规则成为相册分析的一部分，调整剪法要改相册的分析身份并重算。这是[决定记录](../decisions/2026-11-17-montage-center-first-version.md)第 8 项带来的代价。
- **剪辑服务被攻破时的影响**：
  - 它在 `a-nas-photos` 组里，能连相册接口，可以用当时收到的成员会话操作相册；也能直接连 AI Worker，绕过相册的准入占用模型。这两点与家庭中心相同。
  - 成员离线时，它凭授权只能读成员授过权的资产并存回成片，读不到别人的。
- **相册多了有人在等的 AI 工作**：剪辑分析排在相册自己的积压之前；前台有人用时照样让路。
- **规划依赖成员的 VNAS**：没有密钥或 VNAS 不可用时，任务停在“等待规划”，上传、浏览与播放照常。
- **后台规划的代价**：
  - 成员不在线也会用成员自己的 VNAS 调用模型，范围限在成员本人点了“开始”的剪辑、授权的期限与轮数之内。
  - 剪辑服务被攻破时，能让已授权的成员在期限内跑满授权的轮数，并经工具结果送数据。这一轮只开放 `montage`、结束后不跑复盘，模型即使被诱导也碰不到成员的文件、照片与记忆，能做的只是交回不合格的答案；没有授权的成员不受影响。探针已证明，见决定 5。
  - 一轮规划要起一个 gateway（内存见实施方案的风险表），所以全机同一时刻只跑一轮。
  - 规划依赖 Hermes 定时任务的内部接口，和现有的定时任务一样，升级 Hermes 时要一起核对。
- **窗口集合首版没有读者**：实例被清空时，从 Catalog 重写即可。

## 未选择

- **做成可移除模块**：看不到相册与 FFmpeg Worker。
- **原样运行第八版的服务**：等于另起一套服务、任务表和模型调用，违反 [ADR 0001](0001-use-go-for-product-services.md) 与 #514 的接入边界。
- **相册只算窗口向量，卡片、画质与描述归剪辑中心**：好处是调整剪法不碰相册；代价是分析分两处存、生命周期分两处管。用户改为全部归相册。
- **剪辑中心自己调 AI Worker，与相册跨进程共享准入**：要新造这些协调机制：可写的共享目录、跨进程的前台标记、模型槽，以及已加载模型的同步。
- **成片存在剪辑中心**：#514 要求相册是成片的事实源。
- **剪辑服务保存成员会话**：违背 #514“不长期保存明文会话令牌”的要求。
- **剪辑服务以任意成员的名义读相册**：违背 ADR 0011 的授权模型。
- **在助手网关加结构化任务 RPC**：要成员在线的会话才能开始一轮，做不到后台发起。
- **成员打开桌面时由桌面发起**（2026-11-17 定的做法）：沿用成员在线的会话，安全模型不变，规划留在成员的对话历史里；但没人开着桌面就不规划，用户 2026-11-18 改为后台发起。探针已通过；以后 Hermes 升级使后台发起不可用时退回哪种做法，先问评审人。
- **剪辑中心直接请唤醒服务启动单元，不要规划授权**：少一份授权；但剪辑服务被攻破时，能随时让任何有 VNAS 的成员调用模型。
- **按名字把规划任务从“定时任务”里隐藏**：成员看不到后台规划的痕迹；但任务表在成员可写的目录里，对话里的 VNAS 也能建任务，按名字隐藏会让人建出成员看不见、删不掉的定时任务。
- **剪辑中心给出整段提示词**：实现更直接；但剪辑服务被攻破时，能让成员的 VNAS 按它的指令读成员的文件再交回来。
- **到时启动成员的实例，经它的接口运行**：要让后台服务持有登录实例的能力，[gateway 运行方式的决定](../decisions/2026-11-10-hermes-gateway-runtime.md)出于同样的理由没有选它。
