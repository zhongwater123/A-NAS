# 成员分享技术方案与开发切片

状态：proposed；开发入口已建立，产品代码尚未实现。
更新时间：2026-10-15

目标是实现[成员分享规格](../specs/member-sharing.md)。产品行为以该规格为唯一来源；本页描述拟议组件、实现顺序与各切片的验证出口。生产权限边界需按 [ADR 0023](../adr/0023-isolate-member-share-copies-in-a-dedicated-service.md) 评审，不能把本文当成当前架构已经具备的能力。

## 组件与数据流

```text
Web 文件管理：选择文件、接收者和初始留言
    │ 会话 + CSRF
    ▼
产品服务 ── 转发分享请求 ──► 分享服务（专用非特权身份）
    │                       ├── Host Agent 会话查询
    │                       ├── 分享目录与固定内容清单
    │                       ├── 每位接收者独立的讨论与游标
    │                       ├── 保存任务与内容引用
    │                       └── 数据卷上的受管副本与清理
    │
    ├── 文件代理：以发送者身份打开源文件 → 导入分享副本
    └── 文件代理：以接收者身份创建目标 → 从副本写入 → 检查后提交

Web 桌面：分享/回复小通知 → 收到的分享、我发出的分享 → 详情与私聊
```

开发模式使用相同领域模块与可丢弃目录 Adapter；生产模式在独立进程运行。Fake 不能只绕过授权而伪造成功，须执行同一参与者、时间、任务范围和撤回规则。

## 责任与计划路径

以下路径是计划创建或修改的入口，并不表示代码已存在。

| 路径 | 责任 |
|---|---|
| `internal/shares` | 分享生命周期、参与者授权、持久目录、私聊、已读游标、保存任务与到期清理 |
| `internal/sharesapi` | 类型化 HTTP 接口、校验、分页和错误映射；只接收服务层确认的身份 |
| `internal/shareservice` | 生产进程、UDS、独立会话确认、卷检查和恢复调度 |
| `internal/files`、`internal/filebroker` | 源内容读取和接收者目标文件创建、提交、取消；不持有分享业务规则 |
| `internal/sessionlookup` | 复用现有会话确认协议，按需要补充最小的账号状态查询契约 |
| `internal/httpapi`、`cmd/anas-api` | 开发模式装配和生产模式转发，统一浏览器同源与 CSRF 边界 |
| `internal/filepreview`、`internal/mediaworker` | 使用分享授权后打开的内容产生预览，不借用原文件访问地址 |
| `web/src/shares` | 分享发起、收发列表、详情、接收者私聊、emoji 输入、保存与任务状态 |
| `web/src/App.tsx`、`web/src/api.ts` | 文件菜单与桌面入口、通知接线及 API 类型；新增主要逻辑放在独立目录 |
| `api/openapi.yaml` | 分享接口、错误和状态的公开契约 |
| `deploy/systemd/system`、`scripts/install-v1.0.1-system-services.sh` | 专用身份、受管目录、Socket 与服务安装、升级和验证 |

## 数据与并发模型

- `shares` 保存发送者、准备/发布/撤回状态、发布时间和到期时间；到期是由服务端时间判断的访问条件，不依赖清理定时器已经运行。
- `share_entries` 保存每份固定内容的稳定 ID、父子关系、名称、大小及内部内容键。API 不暴露磁盘路径，不通过源文件 ID 向接收者提供内容。
- `share_recipients` 保存每位接收者的独立讨论身份、首次查看时间和已读消息序号；唯一键为分享与接收者。
- `messages` 归属某个讨论，消息顺序由服务端序号确定。发送者在发出时附的留言分别写入各讨论；之后的每条消息只属于一段私聊。消息写入与通知事件同事务提交。
- `save_jobs` 保存请求者、固定选取范围、固定目标、幂等键、接受时间、状态和已提交文件集合。任务引用具体分享副本，不能在过期后追加内容。
- `notification_events` 保存仅对收件账号可见的事件与游标。先以分页增量查询完成可靠补收，再视交互测试选择是否增加实时连接；前台轮询目标为 5 秒内出现提醒。
- 撤回和目标提交必须使用同一顺序控制：撤回赢得顺序后不再允许新文件提交；已经先提交的完整文件保留。跨进程提交确认不能仅依靠内容读取前检查一次权限。
- 任务状态进入成功、失败、取消或中断后释放副本引用。清理仅在分享不可再接受新访问且没有获准继续的任务时执行，实际删除成功前保留可重试记录。

## 开发切片

按顺序实现，某一切片通过最小相关验证后继续下一项；所有验收条件闭合前 PR 保持 draft。代码变更必须补充实际测试证据，本页不把计划中的检查计为已通过。

### 1. 生命周期、授权与保存资格

- [ ] 创建 `internal/shares` 包及其包级说明，把时钟和 ID 生成作为测试可注入依赖。
- [ ] 先写行为测试：准备期间不计有效期、正式发布后 7 天到期、第三人和管理员无隐式访问、只允许接收者创建自己的保存任务。
- [ ] 用固定时间验证：到期前接受的任务继续，到期时刻新任务拒绝，到期后撤回停止原任务，清理不会回收原任务仍引用的副本。
- [ ] 在 SQLite 事务中实现保存任务接受与撤回的状态更新；用并发测试明确任务接受、撤回和提交的顺序，幂等键绑定请求者与请求内容。
- [ ] 执行 `go test ./internal/shares`，确认测试先因缺失行为失败、实现后通过；无需接触真实数据卷。

### 2. 副本准备与不可变发布

- [ ] 建立受管存储 Adapter 和可丢弃目录实现，先测试空目录、多选与后代去重、准备失败清理和发布后内容不可修改。
- [ ] 以发送者身份解析并打开源内容，拒绝符号链接、设备文件、目录越界与管理员查看模式带来的临时访问；只读共享文件可导入。
- [ ] 在真实 Btrfs 可丢弃环境比较固定内容捕获方法，验证并发 SMB 写入、源重命名和删除。单纯比较复制前后的大小与时间不能作为一致性的充分证据；在机制验证前不承诺固定内容捕获完成。
- [ ] 原子发布固定清单后才通知接收者；校验卷身份和容量，不在系统盘回退创建内容。
- [ ] 执行 `go test ./internal/shares ./internal/files ./internal/filebroker`，并记录真实文件系统试验；完善 ADR 的源导入契约。

### 3. 私聊、emoji 与未读游标

- [ ] 实现讨论、消息、游标和通知事件的持久化，初始留言按接收者复制，后续消息始终归属指定讨论。
- [ ] 先测甲分别发给乙、丙：乙猜测丙的讨论 ID 不能读写；管理员也不能读取；消息重试不重复，已读游标不倒退或超出已展示消息。
- [ ] 消息使用有效 UTF-8 纯文本；保留换行、emoji 肤色和组合序列，不解析 HTML。候选限制为每条 16 KiB UTF-8，每页最多 100 条，超限明确返回验证错误。
- [ ] 到期或撤回后拒绝新消息但保留历史；通知记录与消息同事务，离线登录后按账号游标补齐。
- [ ] 执行 `go test ./internal/shares`，加入账号隔离、重复发送、过期和 Unicode 的回归用例。

### 4. 保存任务与取消

- [ ] 接收者选择有写权限的目标，接受任务时固定内容范围与目标；以接收者身份创建隐藏临时文件，继承目标 ACL。
- [ ] 同名自动改名且用不覆盖的提交操作处理并发冲突；逐个完整文件提交，记录已成功文件，不能把部分完成显示为全部完成。
- [ ] 测试关闭窗口继续、会话失效停止、目标权限变化、容量不足、目录移动或删除、撤回与提交竞争，以及过期后完成整个固定选取范围。
- [ ] 对目标提交设计窄的类型化协调契约，先完成可丢弃环境中的竞争测试，再接入生产权限链；不能让产品服务仅凭用户 ID 获得提交能力。
- [ ] 重启后把未完成任务标为中断并清理遗留临时内容；重试作为新保存重新授权，过期或撤回时拒绝重试。
- [ ] 执行 `go test ./internal/shares ./internal/files ./internal/filebroker`，确认全部故障路径都有可观察状态。

### 5. 服务与 API 边界

- [ ] 按 ADR 0023 建立分享进程、会话查询、UDS、受管目录校验及重启对账，开发与生产使用相同领域契约。
- [ ] 提供 `/api/v1/shares` 下的创建、收发列表、详情、内容、讨论、消息、已读、保存和撤回接口；分享与讨论 ID 的组合必须在服务端验证归属。
- [ ] 更新 OpenAPI 并加入契约测试，覆盖无会话、CSRF、第三人访问、重复请求、过期、撤回和服务不可用；非法身份不泄露条目是否存在。
- [ ] 预览通过分享授权获取内容描述符，缓存命中也重新检查权限；到期和撤回关闭预览流，缓存清理纳入副本清理。
- [ ] 执行 `go test ./internal/sharesapi ./internal/shareservice ./internal/httpapi`，证明产品服务提供的账号声明不能替代真实会话。

### 6. 桌面工作流

- [ ] 文件菜单增加“分享”，实现多成员选择、初始留言、准备进度、错误与重试。
- [ ] 增加“收到的分享／我发出的分享”、详情、文件夹浏览与部分选择保存；发送者按接收者切换私聊。
- [ ] 接入现有预览呈现，增加纯文本消息与 emoji 选择器，使用 React 文本渲染；过期和撤回保留可读历史。
- [ ] 把分享事件接入桌面小通知与未读标记；正在查看相应私聊时更新内容，避免重复弹窗。
- [ ] 用 React 工作流测试覆盖多成员隔离、离线补收、连续回复、组合 emoji、保存进度、到期继续和撤回停止；执行 `cd web && npm test && npm run typecheck && npm run build`。

### 7. 安装、系统验证与收尾

- [ ] 更新 Host Agent 管理的专用身份、目录和安装器，添加分享服务 systemd 单元；非 root、限制网络与可写路径，服务失败不影响普通文件访问。
- [ ] 在可丢弃 Linux 环境验证分享身份不能读取个人空间、接收者不能直改分享副本、只读源可分享、目标权限正确且无 SMB 发布。
- [ ] 执行 `make check`，然后执行相关 root 集成测试与 `make system-test`，记录失败修复和最终结果。
- [ ] 更新现有架构入口、领域术语、规格实现状态和当前状态；只有运行手册写明目标、确认、回滚和验证后，才能另行安排实验 NAS 部署。
