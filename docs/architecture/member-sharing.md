# 成员分享技术设计

状态：implemented
更新时间：2026-10-23

产品行为以[成员分享规格](../specs/member-sharing.md)为准；权限边界见 [ADR 0023](../adr/0023-isolate-member-share-copies-in-a-dedicated-service.md)。

## 组件与数据流

```text
Web 文件菜单 / 分享桌面应用
    │ 会话 + CSRF
    ▼
产品服务 ── HTTP over UDS ──► 分享服务 a-nas-shares
    │                         ├── Host Agent 独立会话与有效成员查询
    │                         ├── SQLite 分享记录、私聊、游标与任务
    │                         └── 数据卷 shares/ 固定副本
    │
    ◄── 文件桥 UDS：稳定条目 ID + 原始会话
    └── File Broker ── 成员 UID 工作进程
                       ├── 发送者只读打开源文件 → SCM_RIGHTS → Btrfs FICLONE
                       └── 接收者创建临时文件 → 写入 → 不覆盖提交
```

开发模式把同一领域模块和本地文件桥装配在产品进程内，使用普通复制和可丢弃目录。生产中副本捕获必须成功执行同卷 Btrfs FICLONE；不能静默退回普通复制或系统盘存储。复制前后重扫完整树用于发现重命名、类型变化和清单变化；每个文件的原子克隆保证文件自身内容固定，不承诺跨多个文件的同一事务时刻。

## 模块与身份

| 入口 | 责任 |
|---|---|
| `internal/shares` | 生命周期、参与者授权、私聊、查看/已读/保存状态、持久任务、引用和清理 |
| `internal/sharesapi` | `/api/v1/shares`、分页、Range 内容流、HEIC 预览、错误与代理 |
| `internal/shareservice` | 独立会话确认、数据卷与目录身份检查、服务不可用及恢复 |
| `internal/sharefiles` | 产品侧源/目标文件桥、FD 传递、临时文件清理、操作重放与撤回协调 |
| `internal/files` | 严格选择、后代去重、空目录、只读源、可写目标与改名 |
| `internal/filebroker` | 按成员身份操作；在最终提交边界执行分享代次和撤回检查 |
| `internal/sessionlookup` | 只读会话与有效成员显示资料；分享进程不读取账号数据库 |
| `web/src/shares` | 多成员发起、收发列表、逐人私聊、emoji、预览、选择保存与通知 |

分享服务 UID/GID 为 `31001`，独占数据卷 `shares/`，目录为 `0700`，只获得父目录穿越权限。产品服务通过 `a-nas-shares` 组连接分享 API；分享服务通过专用组访问产品侧文件桥和 Host Agent 会话查询。媒体 Worker 只接收授权后的只读描述符。

## 持久状态与并发

每个分享以一个 JSON 文档写入 SQLite `share_documents`。参与者、固定条目、各私聊、请求幂等键、通知事件和保存任务在同一条记录中原子提交，消息不会独立于通知落库。文件内容按服务生成的分享/条目 ID 放在 `content/`；API 不暴露宿主机路径。

一个分享的接收者共用不可修改的内容副本，但只能读取自己的讨论与状态。管理员不获得旁路。原始会话只随正在执行的请求和任务保留在内存中，不持久化；退出或禁用后新的读取、消息与保存提交会拒绝。

保存先固定选取范围与目标，必要祖先目录作为独立条目一同创建。每个目标文件先暂存，完成后自动改名且不覆盖既有文件。完成条目立即记录，失败或撤回不删除已经提交的完整文件；发送者只看到已保存状态及去重后的文件数。

发送消息时，作者自己的已读游标随之前进，但只在此前没有对方未读消息时才前进，所以“已读”不会越过未显示的回复；发布时附的留言同样计为分享者已读。

撤回、保存接受和提交由领域锁排序。文件桥在发布操作结束前持有自己的发布锁，Host Agent 进一步以分享代次和分享 ID 拦截最终文件操作。分享服务重启先重置代次，旧产品请求即使迟到也不能提交。桥对操作 ID 保留结果并协调断连后的查询，避免丢失回复导致重复建目录或重复保存。

自然到期拒绝新读取、消息和保存任务；已接受的任务按原范围完成。撤回同时取消这些任务，并在发布栅栏完成后才返回成功。预览流持有可撤销读取器；HEIC 转换使用封存的匿名内存文件，并在转换与输出时继续检查授权。没有持久预览缓存。

## 恢复与资源上限

重启将准备任务标为失败、进行中的保存标为中断；不保存会话以自动续做。用户可在分享仍有效时发起新的保存。内容清理只针对服务生成的 ID；到期/撤回且没有运行保存引用时回收，失败留待重试。对话与状态历史保留。

| 项目 | 上限 |
|---|---|
| 单次源选择 / 接收者 | 各 100 项 |
| 展开的固定条目 | 10,000 项 |
| 同时准备与保存任务 | 全服务 4 个 |
| 消息 | 16 KiB UTF-8 纯文本 |
| 列表 / 消息 / 通知单页 | 100 项 |
| 同时内容流 / 文件桥连接 | 各 32 个 |
| HEIC 预览 | 源文件 64 MiB，同时 2 个转换 |

通知每 5 秒按账号游标逐页拉取。页面打开时积压的通知只推进游标，不逐条弹出；未读状态来自收发列表首页（随通知与已读变化及每 30 秒刷新），有新内容时弹一条汇总提醒并在快捷栏显示数量。之后到达的通知按讨论合并为一条提醒。关闭提醒不删除分享；正在查看对应私聊时刷新消息而不重复弹窗。关闭窗口或刷新后从服务端读取自己的保存任务，进度不依赖页面存活。

## 验证

领域测试使用注入时钟验证七天期限、到期边界、撤回竞争、私聊隔离、Unicode、幂等与部分完成。真实 Unix socket 集成测试覆盖 FD 传递、改名、空目录、丢回复、会话失效清理及重启代次。产品流程测试跨账号、文件、分享 API 验证发送至保存完整路径。Btrfs 和权限验证仅在可丢弃容器中执行。

完整检查命令为 `make check`；特权系统验证使用现有 `make system-test`。执行结果记录在 PR，不能把未执行的检查当作通过。部署需要同步产品服务、Host Agent、分享服务和安装器；本 PR 不执行实验 NAS 部署。

2026-10-15 本地验证结果：

- `make check` 通过：330 项前端测试、类型检查、Web 构建、文档检查、部署脚本检查、Go vet、全部 Go 测试、AI 测试及二进制构建。在 WSL 原生目录运行；前端测试超时放宽至 15 秒以避开并发测试负载，断言未修改。服务装配修复后重跑受影响的 Go 测试、脚本检查与构建。
- 分享领域、API、服务、文件桥和代理的 race 检查通过；完整 rootintegration 测试通过。
- 可丢弃 Btrfs 容器中的原子克隆、源文件变更后独立性、空目录/同名保存及真实 UID/ACL 矩阵通过，运行入口为 `internal/sharefiles/testdata/btrfs.sh`。
- `scripts/system-test.sh` 在带齐安装器依赖的 Debian 13 systemd 镜像通过，`failures=0`；覆盖新分享服务以及既有文件、SMB、相册、媒体、终端、重启与升级。启动阶段暴露的问题和修复见[调查记录](../investigations/2026-10-15-member-sharing-service-startup.md)。
- 真实 Chromium 中通过双接收者、离线通知、私聊/表情、文本/图片预览、子集保存到指定子目录、关闭重开任务及撤回。既有桌面窗口在浏览器缩屏后不自动收回边界；最大化后 860 px 宽的分享内容正常，该全局窗口行为未在此功能中修改。
