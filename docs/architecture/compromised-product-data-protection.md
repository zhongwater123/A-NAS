# 产品服务失陷保护：架构改造方案

状态：proposed；文档方案可评审，工程未实施，安全保证尚未成立。
更新时间：2026-11-10

本页是职责拆分、接口方向、ADR 修订和改造顺序的权威计划。安全目标、保护范围与用户可见行为由[规格](../specs/compromised-product-data-protection.md)定义；长期取舍由 [ADR 0036](../adr/0036-protect-recovery-from-a-compromised-product-service.md)记录。不得把目标拓扑当作当前架构。

- 2026-11-10 用户确定更强的保护目标，原 E01 延后的优先级由本计划调整；不撤回 #98 中已有的负对照和范围限制，也不把 issue 关闭当成新目标已通过。

## 目标拓扑与可信计算基

```text
普通浏览器 / 产品页面（按可能被控制处理）
    │ 普通会话，能力可被盗用
    ▼
产品服务 a-nas ──► 文件资源 / 相册 / 用户元数据模块
    │                    │ 受保护提交，不持有历史销毁权
    │                    ▼
    │              保护服务 a-nas-protect
    │                ├── 不可变版本、恢复集、保护引用、预算与操作日志
    │                └── 窄 Host Agent 执行器（快照、卷和权限）
    └──► 身份权威 a-nas-auth（独立凭据、会话、角色与授权账本）

独立 SSH 公钥认证 + root 所有的管理工具（首版可信管理入口）
    ├──► 身份权威：重新认证、生成目标绑定授权
    └──► 保护服务：校验、恢复、明确释放保护版本

SMB / 容器 / 终端：通过合格写 Adapter，或保持只读/停用
```

新进程建议名称为 `anas-auth`、`anas-protection`；业务词汇使用“身份权威”“保护服务”“受保护版本”“销毁授权”“可信恢复入口”，见 [CONTEXT](../../CONTEXT.md)。Host Agent 继续只执行固定高层操作，不承载图片解码或通用脚本。身份权威可验证密码，但不以 root 运行；保护服务的特权操作仍进入窄执行器。

本计划可信计算基包括操作系统、安装/升级链、身份与保护模块、必要的文件/相册写入 Adapter、SMB 保护 Adapter 和 Docker 控制面。产品服务即使利用其可调用接口，也不能使这些可信端绕过策略；同时攻破这些模块或宿主机 root 不在本威胁模型内。

## 权限和持久化所有权

| 状态/能力 | 目标权威与存放 | 产品服务能力 |
|---|---|---|
| 密码摘要、账号状态、UserID/UID、会话、敏感授权 | 身份权威，建议 `/var/lib/a-nas-auth`；父目录与备份由可信部署/恢复管理 | 登录转接/普通会话内省、非权威显示投影；不能修改权威库、密钥或替换父目录 |
| 宿主机空间/身份/查看/应用注册状态 | Host Agent，保留当前 root 所有且产品不可替换的 `/var/lib/a-nas-host` | 经授权的类型化查询或请求；不能直接写注册表 |
| 活动文件、照片与用户元数据 | 各领域模块管理，所有确认提交经保护服务；稳定资源身份关联卷身份与文件版本 | 经授权请求读取或可恢复修改；无通用路径写入 |
| 保护版本、恢复引用图、操作账本、销毁消费记录 | 保护服务，系统状态建议 `/var/lib/a-nas-protection`，数据卷私有保护区建议 `.a-nas-protected` | 按权限读取保护状态；不能挂载、写入、删除、创建任意快照或指定物理路径 |
| 账号/卷/快照/文件 ID 的恢复映射与必要密钥 | 受保护恢复集；密钥另有离线材料，不能只存系统盘 | 非权威缓存；丢失缓存不改变资源归属 |
| 歌单、收藏、标签、反馈与应用持久数据 | 领域模块的受保护用户数据，版本化恢复集包含权威记录与引用 | 请求修改；不能直接改唯一事实源数据库 |
| 缩略图、向量、索引、临时进度 | 可丢弃区，独立配额与有界缓存 | 可以重建/丢弃；不影响用户数据与恢复引用 |
| 受保护数据的最终物理回收 | 保护服务核验销毁授权后执行 | 普通会话没有此能力 |

新目录不得位于 `a-nas` 可改写的父目录中。将数据库文件 chown 为另一用户、却仍让产品服务能重命名其父目录，不构成隔离。当前主干已将 Host Agent 注册表放到 `/var/lib/a-nas-host`；P1 保留此布局并验证启动读取、原子替换和目录权限，不重复迁移或恢复旧路径。身份/保护数据库同样必须满足该隔离要求。保护区不进入 SMB 导出、用户 Shell、应用卷、媒体 Worker 或 AI Worker 的可见挂载。

## 身份与敏感命令

普通业务令牌按受众、资源范围、角色及过期时间校验；真实令牌被盗用仍必须受数据保护契约限制。不得把 token 有效当作销毁授权。身份权威同时持有账号恢复、角色变更及查看授权的权威状态，避免只移动 sessions 表后，产品服务仍通过 SetCredential/SyncIdentities/GrantViewing 重新取得权限。

首版可信管理入口使用预先独立配置的 SSH 公钥登录与 root 所有的维护工具，具有单独认证、独立会话与明确的操作确认；密钥不经产品页面生成、上传或保存。现有 Web PTY、回环地址、产品 Kiosk 和在产品页再输密码均不算用户意图证明。入口没有建好时，敏感功能不开放；后续独立 HTTPS 管理站点需独立 origin、Cookie、脚本来源、CSP/防嵌入和认证链，另做验收，不能由产品服务代理其凭据或管理会话。

销毁授权由可信入口提交精确计划，身份权威生成 `approvalID`，权威端保存 actor、action、资源及版本集合、卷身份、计划摘要、nonce、有效期和消费状态。执行器直接内省授权，不信任产品提交的摘要/角色。执行前重新核对目标和版本；以持久操作 ID 保证重试幂等。任务中断只能继续同一已授权集合，不能用旧授权包含新增资源；未消费授权过期后失败关闭。

敏感命令至少包括：最终销毁、格式化/擦盘、删除保护集或密钥、弱化保护范围、重置/接管账号、改权限归属、应用写挂载/安装升级和 Shell 会话。普通管理员产品会话只能提出计划。管理员恢复成员的既有产品能力可保留，但真实恢复发起者在可信账本中记录，不能把改密后的会话伪装为成员本人确认销毁。

## 受保护提交与文件接口

提供较小的统一契约，协议字段名在实现阶段冻结：

| 操作 | 必须保证 |
|---|---|
| `OpenRead(actor, resourceID, version)` | 在可信端核对身份/权限；缓存与派生结果绑定同一资源版本；不给调用方可变路径当身份 |
| `PrepareChange(actor, operationID, expectedVersion, intent)` | 校验预期身份与版本，预留字节/元数据预算，持久记录意图；未准备好不动原件 |
| `CommitChange(operationID, stagedInput)` | 持久保护数据、用户元数据和恢复引用，完成活动视图变更并持久签发可信提交收据后才确认成功；可幂等恢复 |
| `Recover(recoverySetID, destination)` | 从可信入口独立验证并恢复；不依赖产品数据库，不自动覆盖活动数据 |
| `Destroy(approvalID)` | 仅执行明确授权的版本集合；核对共享对象的全部活动/保护引用与最后副本 |

资源身份含数据卷身份及可信目录中的对象/版本 ID，inode 只是查找线索；复用、硬链接、SMB 改名和路径替换不能转移身份。对普通文件，文件代理在真正修改处验证期望对象；一次 Lstat 后再按路径操作不足以封闭竞态。

每个破坏性修改前保留旧字节与旧用户元数据，新版本确认前保留其恢复表示。首版优先正确性：文件可采用可信侧 COW 副本/快照与持久操作日志；照片沿用不可变内容对象，增加保护引用。必须确认旧 inode 的所有可写持有者不能改写保护副本。产品服务获得的上传 FD 只指向配额暂存区；提交时由可信侧生成独立 inode 的保护版本，不把仍可写的 staging inode 硬链接为原件。产品不持有活动用户数据的长期可写 FD。

日志阶段为 `prepared → protected → applied → committed`；失败留有可重放状态，恢复先验证保护结果再决定重做/补偿。操作 ID、预期版本和授权消费的关联必须在可信存储中，不依赖产品传来的“上一步成功”。`committed` 与可信提交收据关联资源版本、恢复集和完整性摘要；收据可从独立恢复入口查询与验证，产品伪造 UI 不构成可信确认。未确认的操作允许恢复后完成或回滚，但不能牺牲此前已确认版本。

## ADR 0011 的具体修订

保留专用相册身份、受管图库、内容去重、Catalog 与原件同一恢复单元、隔离 Worker 和只读 FD。将以下条款作为目标替代：

1. 第 1 条补充保护区独立所有权：相册服务拥有活动 Catalog/对象操作权，但没有删除受保护副本、改变保护策略或最终销毁的权限。
2. 第 2 条把“一起快照”收紧为可验证恢复集：SQLite 一致性备份或受控停写/检查点，与对象引用在同一提交序列关联；不能任意拷贝正在使用的 `.db` 而忽略 WAL。
3. 第 3 条保留资产 Policy，同时要求真实会话修改也经过保护提交；标签、相册、纠错、目录和动态照片双对象一起版本化。
4. 第 4 条身份查询改为独立身份权威；删除“从产品可写库读取便能抵御产品失陷”的假设。浏览器边界防护不能替代下游可信端授权。
5. 第 5 条查看与账号恢复的敏感证明在可信入口完成，审计/通知的权威记录不由产品服务持有唯一副本；沿用成员可见的恢复发起者记录。
6. 第 6 条保留只读 FD，补充暂存到受保护提交的隔离与取消/配额要求。
7. “后果”改为：产品服务可滥用可见会话改变活动视图，但不能销毁保护历史；相册失陷与宿主机 root 的额外威胁范围另行声明，不能由本目标推导其同样安全。
8. 回收站到期和资产 purge 只改变活动可见性；GC 的可回收条件同时计入活动引用、保护引用、未完成提交和销毁授权，不能只按 Catalog 中最后一个资产引用决定。

## 所有写入口与恢复单元

- **Web/传输**：普通上传、同名 replace、跨空间移动、恢复覆盖、删除文件夹都走资源契约；跨空间复制并删除记录为一个可恢复操作。中断和原目录移动不能误提交到路径复用的新目录。
- **相册/AI**：保护原件和用户元数据；AI 结果可丢弃，清理 AI 派生数据不获取原件回收权。管理员产品会话不能通过 emptyTrash/purge 绕开保护服务。
- **SMB**：首个保护版本仅提供只读 SMB。恢复写入需要可信 VFS/等价 Adapter 覆盖所有写入、截断、替换、删除、改名、ACL、租约及 durable handle 路径，定义可恢复提交与成功响应边界，并通过崩溃矩阵；不能凭事后轮询、recycle 或周期快照达标。
- **终端/SSH 用户**：原产品 Web 终端关闭并移除创建 PTY 的旧授权通道；恢复工具使用独立维护身份。未经保护的用户 Shell 不能有活动数据写权限。将来开放文件编辑需合格工作区/提交 Adapter，不能把“本人 UID”视为豁免。
- **容器**：产品服务不能改 Compose、挂载、镜像或通过生命周期动作破坏保护链。保护区及身份目录永不挂载。共享空间在未合格前只读；应用专属持久数据必须先登记为保护单元，通过冻结/快照 Adapter，再允许受信配置的容器写入。需要任意数据库写入的应用不能谎称每事务受保护：首版应使用只读挂载或拒绝启用，直到其一致性 Adapter 明确成功提交边界。现有写容器不满足时先停止/保全，不能直接豁免。
- **媒体/音乐/反馈**：索引和封面可重建，用户歌单、收藏、播放记录、反馈正文与图片进入受保护元数据写入模块。普通产品服务不再直接写入其唯一权威库；显示偏好如需持久承诺也纳入，缓存偏好明确可丢弃。
- **主干新增模块**：成员分享固定副本及私聊、家庭中心档案/记录、照片 OCR 人工更正与助手的持久会话/笔记均先登记用户数据和恢复依赖；Qdrant 派生向量与网页搜索缓存可重建。助手工具和第三方连接器不得经其他代理绕过同一销毁授权；多盘移除、重新平衡及互联网访问带来的敏感能力在 P0 清单逐项判定。未登记的持久用户数据不能默认排除保护范围。

恢复集按资源依赖图枚举：卷 UUID、UserID/UID/空间归属、稳定资源与版本 ID、原件、必要 Catalog/用户数据、应用数据、权限及密钥。身份服务定期生成受保护导出，恢复时可重新认证/撤销会话，不能让保护服务获得替用户签发普通会话的权力。保护索引及其恢复副本要有校验和独立格式版本，产品磁盘全空时能从清单重建。仅备份 UID 注册表不足以还原所有应用引用。

受保护版本不因普通时间或计数自动到期；容量预留先于接受写入，并区分活动区、暂存区、保护字节、保护元数据和恢复工作空间。产品服务、容器与用户写入不得耗用可信侧保留预算；达到阈值停止后续写入。不能接受“先写成功，空间不够再删旧保护”的实现。精简保护集必须使用单次销毁授权，且明确列出哪些历史将永久消失。

## ADR 修订矩阵

以下是文档修订目标；旧 ADR 上的提示用于避免混淆历史实现与待实施方案。目标条款在对应阶段工程通过后才标为 implemented。

| ADR | 保留 | 必须修订 | 生效阶段 |
|---|---|---|---|
| 0005 本地控制台 | 非特权 Kiosk 和普通 Web 桌面 | 明确 Kiosk/回环不是可信确认；独立维护入口与恢复所需认证材料 | P1–P2 |
| 0006 受管图库 | 稳定资产与不可变去重对象 | 最后资产引用归零不再足够回收，增加保护引用与可信销毁条件 | P3 |
| 0007 存储/SQLite/Host Agent | Btrfs、非特权产品与窄操作 | 身份/保护权威不在产品状态目录；卷注册独立于创建计划；格式化、快照删除和恢复读取均在可信端授权 | P1–P3 |
| 0008 身份/ACL | 统一 UID、内核文件 ACL、本人身份 | 身份签发/重置/授予脱离产品；取消普通会话直达 Shell；写 FD 仅限暂存；ACL 不代替受保护提交；保留可信账号恢复及归因 | P2–P4 |
| 0009 容器代理 | 唯一 Docker 入口、类型化操作 | 不信任产品管理员声明；安装升级、挂载和影响数据的操作核验独立授权；保护控制面不可达 | P1/P4 |
| 0010 应用清单 | 固定审查清单和安装策略 | 审查保护单元、一致性 Adapter、写预算与禁止挂载；卸载/升级不能间接销毁用户恢复点 | P4 |
| 0011 相册身份 | 见上节保留项 | 按上节八条修订，资产 Policy 与保护提交共同执行，GC 交保护权威 | P2–P3 |
| 0012 局域网入口 | 产品回环与 Caddy | 首次安全上线使用可信证书的 HTTPS 登录入口；独立管理认证不经产品服务；结束明文管理过渡，不能跳过证书验证 | P2/P6 |
| 0017 影视 | 原地索引、隔离 FFmpeg | 普通读取及派生缓存同一可信授权/版本契约；收藏/进度为受保护用户数据；后台令牌降权 | P3–P5 |
| 0018 音乐 | 原地索引、共用 Worker | 索引与用户数据恢复职责分开，歌单引用可恢复；缓存按源授权；不保留产品可改写的唯一用户数据 | P3–P5 |
| 0019 tus 上传 | tus 协议、断点偏移与队列 | 产品只持暂存 FD，可信提交生成独立受保护 inode；replace/清理不销毁历史；操作持久化与预算失败关闭 | P3 |
| 0020 日志 | 只读白名单、固定参数、有界输出 | 可信操作/销毁审计由身份/保护侧保存，普通产品不能擦除；敏感日志读取验证独立身份，日志不是唯一恢复依据 | P2/P5 |
| 0022 应用身份 | 应用身份与共享访问隔离 | 写挂载仍须保护资格；保留原身份规则，不能重新开放镜像 root 写共享空间 | P4 |
| 0023 成员分享 | 独立服务持有固定副本 | 固定副本、私聊与到期清理纳入保护引用；产品不能借到期策略销毁保护历史 | P3–P5 |
| 0024 AI 助手 | 每成员沙箱和工具权限隔离 | 工具不得以产品管理员令牌取得销毁权；持久会话/笔记纳入恢复，外部系统操作另列范围 | P2/P4–P5 |
| 0025 多盘 Btrfs | 多盘与冗余配置 | 移除/格式化/重平衡核验可信授权及最后恢复副本，不能套用单盘计划假设 | P1–P3 |
| 0028 向量索引 | 所属服务各自管理的可重建索引 | 保护权威 Catalog 和人工元数据，索引本身不成为用户数据的唯一事实源 | P5 |
| 0029 家庭中心 | 档案与照片引用分属权威服务 | 档案、频道引用与原件组成可验证恢复集，跨服务删除不丢保护引用 | P3–P5 |
| 0031 宿主机软件包 | Debian 包声明依赖与权限 | 新身份/保护服务纳入包与升级迁移，旧包回退不得恢复旧销毁接口 | P1/P6 |
| 0032 互联网入口 | 独立边缘转发与 NAS TLS 终止 | 可信恢复/管理入口不经产品页面与会话代理；保留既有网络隔离和证书要求 | P2/P6 |
| 0033 OCR 人工更正 | 按内容对象与变更记录保存 | 更正与原件引用、操作者及历史纳入保护恢复集，不能当作可丢弃 OCR 输出 | P3/P5 |

0001/0002/0003/0004 的语言、REST/前端和传输选择，以及 0013 网络池、0014 屏保、0015 软件源、0016 离线 AI 的核心决定不变；实现接入新权限时链接 0036。备份中心、统一身份、基础存储、终端、应用中心、传输、相册/动态照片、音乐、影视与日志规格，在相应阶段更新实际行为和兼容错误码；本次仅新增目标规格和修订计划，旧 implemented 规格仍描述旧实现。

## 改造顺序与交付门禁

| 阶段 | 依赖与代码范围 | 交付及退出条件 |
|---|---|---|
| P0 清点与先行封堵 | 保留主干已包含的账户修复；`httpapi`、`hoststate/agent`、`filebroker`、容器代理及新增服务工具 | 形成全部数据/密钥/写入口/敏感 IPC 清单；先使产品会话不能执行销毁、格式化、删快照、弱化保护、开 Shell 或改写挂载。旧路由无别名后门。此时尚无全量保护承诺 |
| P1 建立独立恢复和保护基线 | P0；新保护服务、`hostops/linux` 快照执行器、安装器/systemd、独立维护工具 | 先对可丢弃数据实现列出/校验/恢复；再按尚待编写的运行手册停写、登记现有数据并验证基线。验证既有 Host 注册表隔离；保护状态/预算与恢复材料独立；产品离线也能恢复。保护服务或配置缺失时修改失败关闭 |
| P2 身份权威与可信授权 | P1；`accounts`、`sessionlookup`、所有代理、Caddy 与登录入口 | 数据库及父目录独立；普通身份令牌与敏感授权分开；凭据/角色/查看/容器/快照等逐个核验；撤销旧会话，彻底关闭旧身份/管理 IPC。伪造身份、重放及真实管理员普通会话攻击均不能越过销毁权。受信 HTTPS 登录、独立维护认证完成 |
| P3 统一文件/相册提交 | P1–P2；`files`、`filebroker`、`transfers`、`photos`/`photoservice` | 日志、预期版本、暂存 FD、双对象和保护引用全部接通；先留证据后确认成功；旧 raw-path/活动写 FD 入口关闭。每阶段崩溃/断电均保留已确认版本 |
| P4 收拢所有外部写入口 | P3；Samba 配置/未来 VFS、终端、容器代理、应用目录策略 | 首版 SMB 只读、产品终端关闭、未合格容器停用/只读；逐项资格验收后才开放写入。保证作用于整个设备，不能仅保护 Web/相册；任一遗留直写会使设备状态为“不满足保护目标” |
| P5 用户元数据与完整恢复 | P3–P4；音乐/影视/反馈、文件与快照目录、身份导出/应用备份 Adapter | 唯一用户事实源迁出产品可写目录，恢复集贯穿 UserID/UID/资源 ID；重装系统盘恢复、产品数据库全删、容量洪泛及长期驻留测试通过。恢复路径可在新产品版本不可用时工作 |
| P6 分批迁移与发布 | P0–P5 全通过；安装器、版本协议、运维手册、系统测试 | 可丢弃 systemd 环境完成冷启动、恶意产品替身、升级/回退演练；再经手册在实验 NAS 迁移。迁移覆盖完整且独立恢复实测成功后才允许显示“已满足保护目标” |

P1 把恢复先做出来，P2 关闭伪造身份/管理命令，P3 保证修改可恢复，P4 封闭绕过路径，P5 覆盖用户元数据。各阶段可以在内部拆多个 PR，但不能把“身份隔离完成”当作整体安全目标完成。新的破坏性入口在这些门禁完成前不得增加。

## 迁移、兼容与回退约束

1. 实施保留主干中 PR #101 的账号格式、首次启用、重置归因与部分失败修复；不得因重构恢复已修的缺口。保持审计历史，迁移身份保留 UserID/UID，不静默重新分配。
2. 新增只读协议版本/能力握手与可信端全局保护开关。状态为 `legacy / migrating / protected / attention`，由保护服务判定覆盖范围；产品提供的绿色状态不是权威。新旧进程混跑只允许已协商的只读或保护写协议，未知版本拒绝修改。
3. 旧活动状态、control.db、权限注册、密钥与保护基线先保全并验证，再转换所有权/切换路由。禁止通过一段同时接受新旧写协议的兼容期削弱可信端；回退不重新启用旧敏感接口。
4. 迁移日志记录每个保护单元的清单、schema、校验、完成阶段和恢复验证。重启继续同一操作，未覆盖资源保持停写；不能全局宣称迁移成功。
5. 回退保留已生成的保护集和不可回滚的格式版本。旧二进制不得以为“关闭开关”便有权删除它；若不理解新格式，只进入维护只读态，由兼容恢复工具导出后恢复服务。
6. 真实磁盘操作前必须新增迁移运行手册，包含稳定目标识别、停止全部写者/FD、确认、基线校验、回滚和恢复演练；本页不提供可直接对实验盘运行的命令。当前任务不执行迁移。

## 验收矩阵

| 验收 | 必须观察到的结果 | 层次 |
|---|---|---|
| 产品 UID 任意改文件/伪造会话 | 不能改身份/保护目录及父目录；新造令牌被拒；旧 control.db 被改不产生身份 | 单元负对照 + systemd 真实 UID |
| 盗用真实成员/管理员会话 | 可以执行的活动修改仍可恢复；不能直接销毁、重置授权、删保护集或取密钥 | API/IPC + 恶意产品替身 |
| 逐个直调旧/新 Host、容器、文件、相册 IPC | 无令牌、错受众、错角色、旧协议、改目标、重放一律失败关闭 | 契约 + root 容器 |
| 产品伪造提交成功或替换提交收据 | 可信入口查不到未提交操作，改资源/版本/摘要的收据验证失败；真实已确认版本可定位恢复集 | 可信收据 + 独立查询负对照 |
| 完整字节与用户元数据 | 覆盖/删空/清回收站后恢复原件、动态片段、目录、标签、歌单、反馈、应用数据及 ID 对应 | 模块接口 + 独立恢复工具 |
| 暂存/路径/FD 竞态 | 提交后改旧 FD、SMB 改名、inode 复用与路径替换不能改变已保护版本或误删他物 | Linux 文件系统 + 并发故障注入 |
| 崩溃、断电与响应丢失 | 在每个日志阶段 kill/重启，已确认版本可恢复，重试无重复销毁或越权 | 单元阶段注入 + systemd 可丢弃卷 |
| 长期驻留、时间/版本/磁盘洪泛 | 等待或造版本不能淘汰基线；超预算拒写；恢复预算可用且恢复过程不依赖产品 | 注入时钟 + 压力/配额测试 |
| 外部写路径 | SMB 未资格前只读；Shell/容器不能改保护区；每个已开放写入口完成相同恢复/崩溃测试 | Samba/真实容器/PTY |
| 系统盘重建与保护索引恢复 | 从独立恢复集重建身份/引用，产品服务停机仍能恢复，缺密钥/损坏清单明确拒绝 | 独立恢复演练 |
| 迁移、旧版本和回退 | 任意中断保持停写或保护状态；回退不会重开旧销毁权限 | 安装器 + 协议兼容系统测试 |

日常实现按受影响模块测试；Go、构建或实际跨模块契约变化执行 `make check`，每个候选制品还需对应 systemd、Samba 和恢复门禁。CI 中的恶意产品替身以实际 `a-nas` UID 直接攻击接口，不只走遵守 UI 限制的正常 HTTP 客户端。性能门禁同时记录保护开销、批量导入、目录规模、拒写行为和恢复耗时；数值阈值在 P0/P1 可丢弃基准后冻结，不能以取消保护换吞吐。

本次为文档交付，未执行上述新增门禁；此前成功伪造会话的本地探针是问题证据，不是修复证明。现有全部 Go 测试通过也不能替代本矩阵。
