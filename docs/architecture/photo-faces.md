# 相册人物识别（M3 切片 13）实施方案

状态：draft（“待确认”中的问题得出结论后开始实现）
更新时间：2026-10-10

本文把[相册技术设计](photo-library.md)的切片 13 细化为可实现的方案：在每个图库内检测人脸、把同一个人的人脸聚成人物，用户命名后可以按人物浏览和搜索。产品行为以[相册规格](../specs/photo-library.md)为准：人脸识别首版默认启用，每个私有图库与共享图库各有独立的人物库，可以按图库关闭并清除。方案复用 M2 的 Worker、持久任务、空闲门控与内置交付（[相册本地 AI](photo-ai.md)、[ADR 0016](../adr/0016-ship-photo-ai-as-a-built-in-offline-capability.md)）。

## 目标与范围

完成后，成员可以：

- 在“人物”中看到自己图库里反复出现的人，每人一张封面和照片数；
- 给人物命名，按名字搜索，打开人物后按时间看到 TA 的全部照片；
- 合并被拆开的同一个人，把认错的人脸移出，隐藏不想看到的人物；这些操作是用户数据，重新识别不会推翻。

不在范围内：

- 视频中的人脸，以及跨图库共享人物（规格：图库之间不自动合并人物身份）。
- 推断年龄、性别、表情等属性。
- 以人脸找人脸（上传一张脸搜索）。

## 模型选择

候选的许可、指标与来源证据见[本地照片 AI 研究](../research/photo-ai-model-runtime-selection.md#人脸检测对齐向量与聚类)。建议改用 OpenCV Zoo 的组合，原设计的 Open Model Zoo 组合降为回退：

| 组合 | 依赖 | 判断 |
|---|---|---|
| YuNet 检测 + SFace 向量（OpenCV Zoo；MIT、Apache-2.0） | 运行环境里已有的 OpenCV 5.0 直接提供 `FaceDetectorYN` 与 `FaceRecognizerSF`（2026-10-10 在开发镜像中核实），不新增 Python 依赖；模型约 0.2 MB 与 37 MB | **首选**。YuNet 同时给出 5 个关键点，SFace 用它对齐 112×112 的人脸并输出 128 维向量 |
| Open Model Zoo 检测、关键点与 reid 三件套（Apache-2.0） | 需要 OpenVINO 运行时，Debian 13 不在其官方支持列表；仓库已进入维护模式；检测只针对大于约 60 px 的人脸 | 回退 |
| InsightFace（ArcFace 等） | 预训练权重只许非商业研究使用 | 不可用 |
| MediaPipe Face Detector | 已在运行环境 | 只检测、不给身份向量，不单独使用 |

两个模型像 EmbeddingGemma 一样用清单固定来源、大小与 SHA-256，随 release 按内容交付，设备不联网获取。

## 处理流程

### 输入图

512 px 缩略图不够用：多人合影里的人脸常常只有 20–40 px，而 SFace 需要 112×112 的对齐人脸。人脸任务使用长边 1600 px 的临时输入图：相册服务从原图解码、按 EXIF 转正、缩放后编码进 `memfd`，以只读描述符交给 Worker，处理完即释放，不落盘、不占派生存储。代价是每张照片多解码一次原图（12 MP JPEG 在开发机上约 160 ms）。最终尺寸由评估决定。

### Worker

新增操作 `detect_faces`：输入一张图的描述符，返回每张人脸的框、5 个关键点、检测分数和 128 维 L2 归一化向量，以及模型 ID（两份权重的哈希、输入尺寸与检测阈值）。最小人脸边长与检测阈值由评估确定。Fake Provider 按图片哈希返回确定性的人脸，供 Go 测试与系统测试使用。

### 任务与存储（Catalog migration 7）

- 复用持久任务表：向量任务之后为原图对象排入 `faces/v1`，使用同一空闲与资源门控，Worker 仍串行处理。
- `face_occurrences(id, object_id, model, box, landmarks, score, vector, created_at)`：人脸属于原图对象，副本与重复照片共用；20,000 张照片约 3–5 万张人脸，128 维 float32 约 25 MB。
- 人物属于图库，因此人物归属以“图库 + 人脸”为键，见下一节。

### 聚类

在相册服务（Go）中按图库增量进行，参照 Immich 的做法（DBSCAN 思路：一张人脸在距离阈值内至少有 N 个邻居才算核心点）：

- 新人脸：在同一图库的人脸向量中找相似度高于阈值的邻居。邻居多数已归某个人物时归入该人物；否则邻居数达到下限时新建人物；都不满足时留作“未归类的人脸”，不显示为人物。
- 阈值偏保守：同一人被拆成两个人物，用户合并即可；两个人被合成一个，会混淆甚至暴露家人，必须避免。
- 图库内精确扫描：几万个 128 维向量在内存中逐一比较足够快，不引入向量数据库或 ANN。
- 不采用 scikit-learn 的 HDBSCAN：它要一次处理全部向量，并给运行环境增加约 160 MB 的 SciPy 与 scikit-learn。

### 人物与用户数据

- `persons(id, library_id, name, hidden, cover_face, created_at, updated_at)`：聚类自动创建的人物没有名字；命名、隐藏、换封面由用户操作。
- `person_faces(library_id, face_id, person_id, source)`：`source` 为 `auto` 或 `user`。用户确认、合并、移出（`face_rejections(library_id, face_id, person_id)`）都保存为用户数据，重新聚类只改动 `auto` 的归属，不推翻用户的决定。
- 更换模型后人脸要重新检测，人脸 ID 会变。新旧人脸在同一原图对象上按框的重叠度（IoU）对应，把用户的命名、归属与拒绝转移过去；对应不上的用户决定保留在人物上，作为该人物的锚点。
- 规格要求人工人物名称是用户元数据：关闭人脸能力或重建派生数据时，删除人脸与自动归属，保留人物名称及用户的决定。

### 权限

沿用图库 Policy：私有图库的人物只有所有者可见、可改；有效查看授权下的管理员只读；共享图库的人物所有成员可见，谁能命名、合并与拆分见“待确认”。其他成员的人物、人脸框与人脸数量都不得通过列表、搜索、计数或错误信息泄漏，泄漏测试覆盖这些路径。

### 搜索与界面

- 接口：
  - 列出图库的人物：`GET /api/v1/photos/libraries/{id}/people`；
  - 某个人物的照片：`GET /api/v1/photos/people/{id}/assets`；
  - 修改名称、隐藏与封面：`PATCH /api/v1/photos/people/{id}`；
  - 合并：`POST /api/v1/photos/people/{id}/merge`；
  - 移出一张人脸：`DELETE /api/v1/photos/people/{id}/faces/{faceId}`；
  - 照片详情另外返回人脸框与所属人物。
- 接口只返回框与人物，从不返回人脸向量。
- 搜索：人物名与照片名称、用户标签同属第一档；查询里含人物名时（如“小明 海边”），以该人物过滤，其余文字按语义排序。
- 人物页与照片详情里的人脸框、命名交互由相册界面会话实现。

## 隐私与合规

- 本地处理：人脸任务与 EmbeddingGemma 在同一个无网络、无数据卷访问的 Worker 中运行（ADR 0016）。
- 人脸向量只存于数据卷上的 Catalog，不进日志、不出接口，也不进入首版必备备份（派生数据）。
- 每个图库可以关闭人脸能力并清除派生数据。
- 人脸属于生物识别信息，中国《个人信息保护法》将其列为敏感个人信息。面向消费者默认开启前，建议法务确认是否需要首次使用时的告知或单独同意。

## 评估与验收

- 公开数据集只在开发机使用，下载前逐个列出体积征求同意：
  - LFW：成对验证，用于阈值；
  - FG-NET：同一人从幼儿到老年，用于年龄跨度；
  - Families In the Wild：亲属照片，用于“家人长得像”的误合并。
- 指标：
  - 聚类的成对精确率优先（同一人物中真为同一人的比例），目标不低于 99%；
  - 召回其次；
  - 儿童、年龄跨度、亲属和多人合影中的小脸单独报告。
- 开发机记录每张 1600 px 输入的检测与编码耗时、内存增量；实机数字在部署后补充。
- 质量门槛未达到时，人物功能不默认开启（规格：不满足质量则不默认发布）。

## 步骤

一个里程碑 PR，每步一个提交；开发期只在开发机验证，部署另行确认。

| 步骤 | 内容 | 完成标准 |
|---|---|---|
| 1 | 评估：YuNet 与 SFace 在 OpenCV 5.0 下的检测、对齐与向量；输入尺寸、检测阈值与聚类参数 | 形成研究报告，冻结模型、输入尺寸与阈值；未达门槛则按候选表换回退方案 |
| 2 | Worker：`detect_faces`、两份模型清单、Fake 人脸、协议测试 | Go 客户端与 Python Worker 的互通测试通过；真实模型测试在 Debian 13 容器中通过 |
| 3 | 相册服务：`faces/v1` 任务、`memfd` 临时输入、`face_occurrences` 存储 | 上传 → 缩略图 → 向量 → 人脸，用 Fake 跑通；没有 Worker 时基础相册不受影响 |
| 4 | 聚类与人物：增量聚类、人物与用户决定、换模型时按位置对应、接口与 Policy | 单元与泄漏测试覆盖其他成员、查看授权与回收站；用户决定经重新聚类保留 |
| 5 | 搜索与界面：人物名进入第一档、人物与语义组合；人物页与照片详情（与界面会话协作） | 本地 systemd 环境中用真实模型完成命名、合并、移出与搜索 |
| 6 | 关闭与清除：图库的人脸开关、清除派生数据并保留名称 | 规格“关闭私有图库 AI 能力”场景通过 |
| 7 | 打包与系统测试：模型随 ADR 0016 的通道交付；系统测试用 Fake | 系统测试通过；部署到 Experimental NAS 另行确认 |

## 待确认

1. **模型**：是否改用 YuNet + SFace（OpenCV，已在运行环境），原设计的 Open Model Zoo + OpenVINO 降为回退？
2. **数据集**：是否同意下载 LFW、FG-NET 与 Families In the Wild（只在开发机使用）？体积在下载前列出。
3. **共享图库的人物库**：谁可以命名、合并与拆分？建议只有设备管理员可以，成员只能查看，与“共享图库只由管理员控制 AI 开关”一致。
4. **合规与告知**：默认开启前是否需要首次使用时的告知（如“本机识别人脸以整理人物，可在设置中关闭”），是否要法务确认？
5. **输入尺寸**：是否接受每张照片多解码一次原图来生成 1600 px 的临时输入？

## 风险

- SFace 是 2021 年的 MobileFaceNet 模型，在亚洲儿童与年龄跨度上的表现未知，评估中单独报告。
- 两个模型的训练数据来源需在对外发行前核对（与 EmbeddingGemma 的许可核对一并进行）。
- 婴幼儿变化快，同一个孩子可能被拆成多个人物，依赖用户合并；双胞胎与亲属可能被误合并，阈值保守，用户可以移出。
- 人脸任务增加后台处理时间；它与向量任务共用空闲门控和 Worker，不影响前台。
