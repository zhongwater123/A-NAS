# 局域网 HTTP 页面点击“发送分享”无反应

状态：fixed locally；待修复版本部署与宿主机验收
更新时间：2026-10-16

## 症状与最小复现

用户在电脑浏览器通过 NAS 的 IP 地址访问，选中接收成员后点击“发送分享”，弹窗保持原样，没有错误提示。PR #123 已合并，用户报告已部署。

以 Chromium 打开可丢弃开发实例的 `http://<非回环 IP>:<端口>`，登录测试账号，在文件管理中选普通文件或文件夹，选择成员后点击发送。原版本稳定抛出 `TypeError: crypto.randomUUID is not a function`，未发出创建分享请求。使用 localhost 不能复现此问题。

## 根因

生成幂等请求标识时直接调用了仅在安全上下文中提供的 `crypto.randomUUID()`。NAS 的局域网入口支持明文 HTTP；浏览器不会把普通 IP 的 HTTP 页面视为安全上下文，但会特殊信任 localhost。发送、保存、回复的标识生成还位于各自的 `try` 之外，使异常绕过界面的错误提示。

之前浏览器验收使用 localhost，服务端系统测试直接通过 HTTP 客户端调用 API，均没有覆盖非回环 HTTP 页面执行 JavaScript 的边界。因此即使接口、权限与文件流程通过，用户仍无法从实际入口发起操作。

## 修复

- 使用普通 HTTP 页面同样提供的 `crypto.getRandomValues` 生成 UUID v4 格式的请求标识；不使用弱随机替代，会话与权限机制不变。
- 发送、保存、回复的标识生成均在错误捕获范围内；不可用时显示可读提示，恢复按钮并保留草稿。
- 不确定结果的重试继续复用原请求标识，避免重复分享或保存。
- 发送弹窗拆为独立组件，提供文件摘要、带头像的成员选择、搜索、明确的加载/失败/重试反馈及固定操作栏。分享入口按用户要求迁至左侧系统快捷栏。

## 验证

- 现有分享界面测试模拟 `getRandomValues` 可用但 `randomUUID` 缺失：修复前 3 项失败（发送、重试、保存）；修复后通过。
- 补充私聊回复的 HTTP 场景、随机能力不可用时的可见错误、搜索后保留成员选择的回归。
- 用相同的非回环 HTTP 地址执行真实 Chromium 验收；原版出现上述异常，修复版发送后进入“分享中”，两名接收者与 Unicode 留言正确持久化；接收者回复表情成功，并将整个文件夹保存到指定子目录，任务显示 3 项完成、2 个文件。
- 左侧分享入口、桌面不再含分享图标由桌面行为测试与浏览器验证；390 × 844 与 1440 × 1000 的发送弹窗截图检查通过。
- 分享测试 17 项通过；前端全套首次为 349/351，单独重跑桌面得到 73/75；两轮都出现文件排序测试的 15 秒超时，随后分别出现上传加载与启用页面重复元素失败。排序、启用与上传三项独立重跑全部通过（不修改测试或放宽其原有超时）。
- `npm run typecheck`、`npm run build`、`make docs-check` 通过。

## 部署与后续

只有前端与文档变化，无 API 或数据库迁移。修复版本需重新构建嵌入式 Web 资源并按现有部署手册安装。已部署环境尚未由本次任务核验；SSH 公钥认证被拒绝，需要恢复现有开发授权后再核对。
