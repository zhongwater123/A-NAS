# A-NAS 文档系统

这套文档系统保存代码无法自证的项目知识，并为新会话提供最短可靠路径。每项事实只有一个权威位置，其他文档通过链接引用。

## 路由

| 需要回答的问题 | 权威位置 | 何时更新 |
|---|---|---|
| 现在做到哪里、下一步是什么 | [当前状态](status/CURRENT.md) | 阶段、下一步或阻塞变化时 |
| 项目术语是什么意思 | [领域语言](../CONTEXT.md) | 术语得到明确约定时 |
| 系统由什么组成、哪些边界不能破坏 | [架构总览](architecture/OVERVIEW.md) | 组件、数据流或不变量变化时 |
| 为什么采用某项长期技术或边界 | [ADR](adr/README.md) | 作出难以逆转且存在权衡的决定时 |
| 功能应该表现成什么样 | [功能规格](specs/README.md) | 行为或验收条件变化时 |
| 某个复杂缺陷为何发生、如何证明已修复 | [调查记录](investigations/README.md) | 非显然缺陷调查获得新证据时 |
| 某项安装、恢复或高风险操作如何安全执行 | [运行手册](runbooks/README.md) | 步骤、前提、回滚或验证变化时 |
| 某个版本交付了什么、如何验收、有何限制 | [发布记录](releases/README.md) | 创建版本或发布结论变化时 |
| 某项技术候选有哪些一手证据、限制与基准建议 | [技术研究](research/README.md) | 选型证据或候选发生实质变化时 |
| 本机开发环境如何使用 | [本地环境](development/LOCAL_ENVIRONMENT.md) | 工具链或账号配置变化时 |
| 产品起点、竞品研究和完整历史背景 | [项目上下文](../PROJECT_CONTEXT.md) | 产品事实或决策总表变化时 |
| 实现何时、由谁、怎样改变 | Git 提交和 Pull Request | 每次实现变更时 |

## 写入规则

1. 先选择上表中的事实类型，再更新最近的权威文档。
2. 规格描述行为，架构描述边界，ADR 描述原因，调查记录描述证据，运行手册描述操作。
3. 文档中的结论要链接到相关代码、测试、ADR、调查或运行手册。
4. 当前状态使用现在时，只保留仍会影响下一次工作的内容。
5. 从模板创建文档后删除所有占位符；被替代的内容标明状态并链接替代项。

## 完成标准

文档变更在以下条件全部满足时完成：

- `make docs-check` 通过；
- 文档放在正确类别且没有复制其他事实源；
- 新会话仅凭路由、相关文档和代码即可复现结论或继续工作；
- 当前状态与仓库实际状态一致。
